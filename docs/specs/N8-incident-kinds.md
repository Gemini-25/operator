1. 새 유형과 새 시나리오 **둘 다** 늘린다. 2. 분량은 **크게**: 시나리오 +35쯤, 새 유형 +5~6, 묶음 둘(N8·N9). 3. 가벼운 사건(한 팀 3~5분)과 무거운 사건(여러 분야 15~20분)을 **고르게**. 4. 부족한 분야는 **전부**(경찰 일상 치안·소방 구조·구급·합동) + "특수 분야도 모자람". 5. 사건 묶음 **열두 가지 모두**: 높은 곳·깊은 곳 구조 / 동물 / 시설 사고 / 위기에 놓인 사람 / 일상 치안 / 재산 범죄 / 군중·행사 / 테러·중대 위협 / 교통 시설 / 산업 현장 / 의료의 여러 갈래 / 날씨·환경 피해. 6. 일이 늘 특수 부대 **넷 모두**: 특공대·폭발물 처리 / 화생방 / 헬기·해상 / 구조대 전문 장비. 7. 새 부대 **세 갈래 모두**: 유관 기관 차량(전력·가스·수도 복구반, 견인차) / 새 전문 구조대(산악·수중·화생방 제독·동물 포획) / 경찰의 새 부대(형사·교통 경찰·기동대·경찰견). 8. 새 장소를 지도에 **더한다**(터널·지하철역·경기장/공연장·놀이공원·은행 등 + 전용 현장). 9. 민감한 소재는 **절제해서** 넣는다(설득·안전 매트·구조 중심, 실패는 그림 없이 기록 한 줄). 10. 비응급 신고를 **여러 갈래로**(장난 전화·오인 신고·단순 민원 이관·중복 신고, 합쳐 6~8%). 11. **일상 사건 먼저**(N8), 큰 사건·새 장소는 N9. 12. 연쇄는 **조건이 맞을 때만**(대응이 늦거나 실패했을 때), 연쇄 상한 유지. 13. 화면 표시는 **유형 기호만**(새 유형의 기호만 더한다. 핀·카드에 시나리오 이름·시나리오별 기호를 넣지 않는다). 14. 무거운 사건 수는 그대로, **짧은 사건을 교대당 4~6건 더**.

## 1. 원칙

- **새 사건마다 "새로 볼 것"이 하나 이상**: 새 위험의 움직임 · 새 판단 · 새 작업(방법) · 새 결말 가운데 하나. 문구만 다른 사건은 넣지 않는다.
- **유형으로 세우는 기준**: 가는 분야의 구성, 현장의 위험 규칙, 지휘 판단, 끝나는 방식 가운데 둘 이상이 기존 여덟 유형과 다르다. 화면에는 유형 기호만 보이므로(결정 13) 체감은 유형 수에 달렸다 — 그래서 새 유형을 여섯 세운다(N8 다섯 · N9 하나).
- **모든 새 사건은 끝난다**: 항목마다 한계 시간(`sceneManager.LIMIT`), 맡을 부대가 없을 때(`commander.needFor`), 마지막 부대가 떠났을 때(7번 블록), 유관 기관 차량이 오지 못할 때의 길을 적고 강제 실행 20교대로 한계 시간·방치 0 을 잰다.
- 판단부는 진실을 읽지 않는다. 새 사건의 다름은 **믿음(사실 종류·`CasBelief` 칸·`haz.sub`)이나 생김새(`s.kind`·`s.rules`·구역)**로 드러나야 R2·R3 가 반응한다.
- 앞선 문서(`docs/DESIGN.md` §5 "새 사건은 되도록 시나리오로", I1 머리말 "사건 수보다 상황 수")와 방향이 다르다 — **이 결정이 최신**이고, 구현 때 DESIGN §5 를 고친다. 대신 새 사건이 일곱 묶음의 방법·교본·부상·조짐·인과를 타게 만든다.

## 3. 지금 상태 (조사 — `N8-research/`)

보통 교대 하나에 사건 14.2건, 유형 6.4가지, 서로 다른 시나리오 9.6가지. 사건의 67%가 기본 여덟 모습이고 표의 시나리오 23개는 다 합쳐 20%다. 실종·응급·가스·수난에는 평소 시나리오가 없다. 지도 핀은 유형 기호 8(+붕괴 변형 4)뿐이다. 경기장·역·놀이공원 같은 큰 건물에는 화재·강력 범죄만 나고, 학교·주차장·다리·건널목에는 사건이 없다. 구조정 출동 6회·해체 5건·호이스트 10건·물 투하 0건(40교대) — 전문 부대의 전문 일이 드물다. 관문은 전체 값만 본다(성공+지연 65~90%, 지금 84%).

### 4.2 기존 유형에 더하는 시나리오 (N8)

- **응급의 갈래**(지금 "집 한 채에 환자 한 명"뿐): 집단 식중독 `medical/poison`(식당·학교, 환자 5~9 — 분류와 병원 나눠 보내기) · 약물 과다 `medical/overdose`(해독제·난동 가능 → 경찰 동행) · 출산 임박 `medical/birth`(현장 분만이냐 이송이냐의 판단) · 폭염 환자 `medical/heat`(야외·공원, 여럿이 차례로 쓰러진다). 행사장 환자 다발은 N9(`crowd`).
- **비응급 신고**(결정 10 — 유형이 아니라 신고의 갈래): ① 장난 전화(접수 AI 가 질문으로 가려내면 출동 없이 끝, 속으면 출동 → `FALSE_ALARM`) ② 오인 신고(연기 → 수증기, 비명 → TV: 출동해 확인하고 끝) ③ 단순 민원(소음·주차 — 다른 기관에 넘긴다는 기록으로 끝, **출동 없음**) ④ 중복 신고(이미 열린 사건의 둘째 신고 — 새 정보가 있으면 그 사건의 믿음을 고치고, 못 알아보면 부대를 한 번 더 보낸다). 합쳐 6~8%.

## 5. 공통 틀 (N9 도 쓴다)

1. **유형을 자료로**(틀 단계 — 결과 불변): 새 유형 하나가 공용 파일 스무 곳의 분기를 고치는 지금 구조(조사 `extension.md` §1.1 의 54자리)를 먼저 정리한다. `src/sim/incidentTypes.ts`(새 파일)의 `TYPE_DEFS: Record<IncidentType, { name, color, icon, limit, respLimit, indoorRisk, hasStruct, … }>` 로 문자열 열쇠 표 9개와 손으로 쓴 유형 배열 4곳을 옮기고, 가능도 배열 42개(`NATURE_LIK` 20 + 시나리오 `lik` 22)는 **자리(8열) 대신 유형 이름으로 찾는 꼴**(`{ fire: 0.6, … }`, 없는 유형은 0)로 바꾼다. 이 단계는 여덟 유형의 값을 그대로 옮기기만 하므로 기록 해시가 같아야 한다.
2. **짧은 사건의 추첨**(결정 14): 기존 사건의 일정·종류는 건드리지 않고, **새 난수 흐름 `daily`** 로 `tag: 'daily'` 시나리오(시설·동물·치안·보호·비응급 신고)를 교대당 4~6건 따로 얹는다(`difficulty.ts` 의 빈도 손잡이에 비례). 기존 흐름에 호출을 끼워 넣지 않는다. 그래도 부대를 나눠 쓰므로 결과는 바뀐다 — 그 단계에서 기준을 다시 잰다. 새 유형의 무거운 시나리오(`rescue`·`welfare/ledge`)와 응급의 갈래는 기존 유형 추첨에 몫으로 넣는다(`SCENARIOS` **끝에** 새 묶음 `scenarios/kinds.ts`).
3. **통화만 있는 신고**: 장난 전화·단순 민원은 `Incident` 를 만들되 출동 없이 접수 단계에서 닫는 종료 사유(`closeReason 'screened'`)를 더한다 — 판정·보고서·측정 도구(잊힌 사건·기록 일치 관문)가 이 사유를 세게 한다. 중복 신고는 열린 사건에 붙는 둘째 통화다.
4. **조건부 연쇄**(결정 12): `chain.canChain` 과 I1-b 의 `spawnConsequence` 위에서만. 조건(대응 지연·실패)이 참일 때만 예약하고 난수는 늘 뽑는다. N8 의 연쇄: 끊어진 전선 방치 → 화재 / 수도관 파열 방치 → 싱크홀 → 교통사고 / 주취 소란 실패 → 흉기 시비(`armed/dispute`) / 벌집·개 물림 → 응급 / 멧돼지 놓침 → 도로에서 교통사고 / 날치기 놓침 → (재범 예약은 기존 규칙).
5. **화면**(결정 13): 새 유형 여섯의 핀 기호·색(`view/icons.ts`·`renderCity.TYPE_COLOR`·범례·패널의 확률 목록)만 더한다. 카드 제목은 지금 규칙 그대로(유형 이름). 조사자가 권한 "현장 확인 뒤 시나리오 이름표·핀 아이콘 넓히기"는 **사용자 결정으로 하지 않는다.** 현장 그림은 새 소품·스킨(전선·난간·그물·금고·안전 매트)으로 구별된다.
6. **민감한 소재**(결정 9): `welfare/ledge` 는 설득(협상 임무) → 안전 매트 설치(새 소품) → 붙잡기/스스로 내려옴으로 끝난다. 실패는 "구조하지 못했습니다" 기록 한 줄과 판정뿐 — 떨어지는 그림·소리·카메라 연출을 만들지 않는다.

## 6. 균형

- 목표(보통 60시드, N8 0단계 기준 대비): 성공+지연 ±4%p, 실패+미해결 +3%p 이하, 한계 시간+방치 +2건 이하, 평균 대응 +8초 이하, `NO_UNIT`·통화 대기 사건 비율 +5%p 이하. 프리셋 순서 유지. 새 시나리오마다 `--force 유형/변형` 20교대에서 한계 시간 0·방치 0, 성공률은 가벼운 것 85~97%·무거운 것 60~85%(가벼운 사건이 너무 쉬우면 관문 위쪽 90%를 넘는다 — 실패하는 길을 반드시 둔다: 놓침·번짐·복구반 지연).
- 손잡이 차례: ① 짧은 사건 수(6 → 4) ② 새 시나리오의 몫 ③ 새 부대 수(복구반 대기 시간) ④ 한계 시간. `sweep --check` 의 범위는 고치지 않는다.

## 7. 정보 격리 (요지 — 상세 표는 구현 전 설계에서)

숨은 진실: 전선이 살아 있는가 · 수도관이 어디서 터졌는가 · 싱크홀이 더 넓어지는가 · 동물의 위치와 흥분 · 날치기의 도주 방향 · 위기자의 마음(설득 단계) · 문 안의 사람 상태 · 신고가 장난인가. 아는 길: 신고 내용(틀릴 수 있다) → 시야 안 관찰(`perceive`) → 장비(검전기·열화상·경찰견) → 무전. 관제는 접수한 것만 안다.

## 9. 테스트 — `tests/kinds.test.ts`

1. `TYPE_DEFS` 가 모든 유형을 덮고 가능도 표가 유형 이름으로만 읽힌다(열 수 검사 셋을 대체). 2. 틀 단계 전후 기록 해시 동일. 3. `civil` 부대는 지휘관이 되지 않는다·능력과 장비 불변 조건. 4. 새 시나리오마다 직접 일으켜(`createIncident`/`force`) 재현성(같은 시드 두 번). 5. 새 시나리오마다 끝난다(한계 시간 안, 부대 없음·복구반 없음·마지막 부대 이탈의 세 경우). 6. 정보 격리: 판단 파일이 새 진실 칸을 읽지 않는다(소스 검사). 7. `daily` 흐름을 꺼도 기존 사건의 시각·종류가 같다. 8. 비응급 신고: 가려내면 출동 0·`screened`, 속으면 `FALSE_ALARM`, 중복 신고는 사건 수를 늘리지 않는다. 9. 새 임무(`repair`·`towAway`·`capture`·`track`)의 낡은 믿음 반복 방지(강제 보고·`cancel`·`needFor`). 10. 연쇄는 조건이 참일 때만, 상한을 넘지 않는다. 11. 민감한 소재: `ledge` 실패에 그림 기록(`Fx`)이 없다. 12. 화면: 새 유형의 기호·색·범례가 있고 카드 제목 규칙이 그대로다.

## 11. 알려진 위험

- 새 유형 다섯은 비싸다(유형 하나에 src 26파일) — 틀 단계(§5-1)를 건너뛰면 감당할 수 없다. 틀 단계가 결과 불변임을 해시로 증명한다.
- 사건이 교대당 4~6건 늘면 경찰·구급의 가동률이 오른다(지금 최고 가동률 61%, `NO_UNIT` 16%). 새 부대가 일을 나눠 가져야 한다 — 짧은 사건은 새 부대가 주로 맡게 수요를 짠다.
- 가벼운 사건은 쉽다(쓰러진 나무·맨홀은 60교대 전부 성공) → 관문 위쪽. 사건마다 실패하는 길을 둔다.
- 군중 모델이 없다(N9 의 몫). 날씨에 폭염·폭설 값이 없다 — `medical/heat` 는 날씨가 아니라 시간대·장소로 건다(I1 §9: 날씨만으로 사건을 늘리면 인과가 아니라 난이도).
- "그 차가 와야 끝나는 사건"은 복구반이 고장·정체로 못 오면 한계 시간으로 간다 — 인근 도시 지원(`createAidUnit`)에 복구반을 넣거나, 소방이 임시 조치(차단기·밸브)로 닫을 수 있게 한다(권장: 둘 다).
