- Every former `placeGone` call now goes through `placeUsable`. The spec lists four sites; the code had five: pickPlace strict and fallback, the fixed building in createIncident, kidnap hideout candidates in pursuit.ts, law incidents in tickIncidents, and the I1-b C10 reoffend site in hazards.reoffendPlace. `placeGone` stays exported in incidents.ts only as an alias, because tests/catastrophe.test.ts calls it.
- Disaster site picking (disaster.pickPlace) and the next arson target (arsonNext pool) call `placeUsable(…, false, false)`, so they see only carried-over state.
- I1-b `placeState().usable` now calls `placeUsable` in all three branches; `ruinFrac` for a carried entry is `ruin ? 1 : 0` as in §3.6.
- Building overlay set up at shift start: `initCarry` → `applyPlaceCarry` copies carry.places into `cs.places` and adds one 'place' note per closed/ruined building (longest repair first) and per reopened building. Order is buildings, then roads, then crew.
- `announceCarry` writes the building lines: the first `PLACE_LINES` (4) closed/ruined and the first 4 reopened buildings get one line each, the rest go into one '외 n곳' line per group. The traffic-ledger owner for the slowdown in front of a closed building is now that building's line.
- `pickPlace` third stage: only with a carry, and only when strict and fallback both find nothing, closed buildings are allowed; ruined ones never are. Damaged-but-open (marked) buildings get extra weight: collapse × (1 + 3·dmg), gas leak × (1 + dmg).
- `applyPlaceWear(sim, s, I)` runs in createScene right after I1-b `applyExpo`. It merges `s.wear` (larger dmg wins; its cause and incident name go with it; soot comes from the carry) and marks `round(PRE_BURN 0.35 × soot × indoor fuel tiles)` tiles as already burnt (hash order, never on or next to a fire tile): fuel 0, burned 1, `totalFuelTiles − k`, `wear.pre = k`.
- In X6 `catOf`, the burnout denominator (`fuelMask`) now excludes the already-burnt tiles, so they drop out of both numerator and denominator.
- `noteWearIncident(sim, I)` logs one line right after the incident's creation line when the building has dmg ≥ 0.1 or soot ≥ 0.2 (tag carry, truth, cause = the carry summary line) and pushes to `stats.markedInc`.
- `placeOutcome(sim, I)` builds the end state per incident: the five X6 rows, fire loss rows (0.6 / 0.25 / 0.05), collapse rubble with the 0.22 threshold or a '2차 붕괴' detail, elevator excluded, gasblast / exploded props / ignited valve / ignited props for buildings X6 did not mark, open ground kept as a trace only. Several matching rows merge to the heaviest state with the largest values.
- `placesNext`, called from `makeCarryover` (still pure, no randomness): merges with the previous state (since kept from the previous entry); rest step (repair −1; at 0 the building reopens with dmg ×0.4, soot ×0.5, opened set, mark and spot cleared; traces fade by −0.25 soot / −0.15 dmg and are dropped below 0.05); caps CLOSED_CAP 12 and PLACE_CAP 24.
- tests/persistence.test.ts grew from 65 to 81 tests, covering §9-3 (all six sites, third stage, damage weighting, the damaged-building scene, soot direction, source-text check), the end-state table, rest and caps, and the building share of 6·10. ## 설계서와 다르게 한 곳

- New leaf module src/sim/placeUse.ts holds `placeCond`, `placeUsable` and `preBurnt`/`setPreBurnt` (spec: persist.ts). Reason: scenarios/crime.ts (arsonNext) must call the check, and importing persist.ts there pulls in resources → dispatcher → callSystem, which can read SCENARIOS before scenarios.ts has finished loading (the same cycle CLAUDE.md warns about for pursuit). persist.ts re-exports both functions.
- There were five `placeGone` sites, not four: the I1-b C10 reoffend site (hazards.reoffendPlace) also uses `placeUsable(sim, q.id)`. It has to filter when it picks, otherwise the reserved building and the actual incident building can differ.
- X6 counts already-burnt tiles in the burnout denominator (`fuel > 0 || burned`), so instead of subtracting `wear.pre` from the numerator (§10.2) the already-burnt tiles are removed from `fuelMask` via the `preBurnt` mask. This removes them from numerator and denominator together.
- Collapse rubble rows also apply to buildings X6 marked. X6's `ruinFrac` counts only tiles that fell during the incident; without this, a heavily collapsed site with an extra partial collapse would end up lighter (closed 2) than one without it (ruin 4).
- The '천장 일부 붕괴' row is gone: X6 stage 3 removed that code path.
- `inc` uses `util.TYPE_NAME` (e.g. '조직 n번째 교대 · 04 건물 화재') instead of `scenarioName`, for the same import-cycle reason as stage 4.
- When rows or entries merge, cause, inc, mark and spot come from the heavier state (on a tie, the newer one). A trace with dmg and soot both below 0.05 is not created. A reopened building loses mark and spot; `opened` is announced once; a building reopened in this rest step is not also decayed as a trace in the same step.
- Cap order: over CLOSED_CAP, the smallest repair (then the largest id) reopens; over PLACE_CAP, the faintest trace (smallest dmg + soot, then largest id) is dropped.
- Line wording and grouping (spec gives only the gist): '<address> <name> — <inc>로 복구 공사 중이라 출입을 통제합니다 (n교대 남음).', '… 무너져 출입할 수 없습니다 …', '<address> <name> 복구 완료 — 다시 문을 열었습니다.', '외 n곳도 …' (PLACE_LINES 4). Open ground gets the '이 터에는 … 탄 자리' line only when soot ≥ 0.2.
- Already-burnt tile count is `min(candidates, round(PRE_BURN × soot × indoor fuel tiles))`; the base count is taken before the fire-adjacent tiles are removed.
- Shock/carry overlap: createScene runs buildScene → applyExpo → applyPlaceWear. dmg is the larger of the two, and cause and inc follow that side; on a tie the earlier shock stays. Soot comes from the carry. So the metrics tool's S(I) and the I1-b report line about an already-cracked building follow whichever damage is larger.
- `world.expo` is not carried over (header ④): it is not a source in the §3.6 table, `PlaceCarry.cause` has no shock value, and the spec's preface defers cross-shift world state. Measured: 0–3 buildings per normal shift, 5–15 per quake shift.
- In the soot-direction test the ratio check uses a spreading fire (severity 3), and the number of tiles burnt this shift is checked as well. The spec does not fix the severity; small fires go the other way (see issues).
- Added `placeCond` and `preBurnt` to the forbidden names in isolation test 9.

## 알려진 문제 · 다음 작업자가 알아야 할 것

- Small fires in sooty buildings show a higher loss ratio: already-burnt tiles leave both numerator and denominator (as the spec and test require), so a fire that burns the same number of tiles scores about total/(total−pre) ≈ 1.27× higher. A spreading fire goes down because the burnt tiles act as firebreaks. Stage 8 knob: PRE_BURN, or keep the original fuel count as the denominator (that would differ from the spec — a user decision).
- Already-burnt tiles still count in X6's per-second region burn share (structure cap via K_BURN) and in `regionBurning` (thermal-imaging threshold), on top of the initial integrity cut from wear.dmg. At soot 0.6 the cap is about 0.84, still above L1 0.6.
- After a quake, closed + ruined buildings sit near CLOSED_CAP 12 for about 4 shifts (whole-building collapses stay ruined for 4). Site picking moves elsewhere, so timeouts did not rise. Knob §6.4-2: collapse repair 4 and 2.
- In naturally generated lineages, incidents in damaged (marked) buildings are rare (0 of 678): there are 0–7 such buildings and they fade within one or two shifts. The damage weighting and noteWearIncident are covered only by hand-made states in test 3; stage 8's chain.ts markedInc should measure the natural rate.
- Fires often leave an X6 partial collapse, so burnt buildings are usually closed for 2 shifts. That comes from X6's K_BURN or from this stage's partial → repair 2 row.
- Notes for later stages. Stage 6: carryLayer should read `carryState.places` (mark, spot, opened, state, soot, dmg); the scene smudge should read `s.wear?.soot` and `s.burned`. Stage 7: '손상된 건물에서 사건 n건' = `stats.markedInc`, and `CarrySummary.marked/closed/ruin` come from the next state's places. Stage 8: move s5-soot.ts into chain.ts --soot; §6.3-6 diagnostic so far: quake lineages have 9–12 closed/ruined at shift 2 and 3–8 at shifts 5–6.
