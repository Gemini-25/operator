# AUTONOMOUS RESPONSE

자율형 긴급구조 조직 시뮬레이션. 경찰·소방·구급 AI 조직이 가상의 도시에서 스스로 신고를 받고, 판단하고, 출동하고, 현장에서 협력하고, 실패하고, 다시 시도한다. 플레이어는 지휘관이 아니라 **관찰자**다. 화면에는 AI에게 명령을 내리는 조작이 하나도 없다.

- 브라우저에서만 실행된다. 서버, 외부 API, LLM 호출이 없다.
- 같은 시드와 같은 난이도로 실행하면 같은 교대가 그대로 재현된다.
- 사건 유형 4가지: 건물 화재, 교통사고, 실종·조난, 무장 사건(대치·총격).

## 설치와 실행

Node.js 20 이상이 필요하다.

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 `http://localhost:5173` 을 연다. 주소 뒤에 `?seed=원하는글자` 를 붙이면 그 시드로, `&diff=hard` 나 `&diff=4,4,4,2,3` 을 붙이면 그 난이도로 시작한다.

그 밖의 명령:

| 명령 | 하는 일 |
|---|---|
| `npm run build` | 타입 검사 후 정적 파일을 `dist/` 에 만든다 |
| `npm test` | 자동 테스트(재현성, 교대 완주, 상태 변화, 정보 격리, 난이도 등 21개) |
| `npm run check` | 타입 검사 + 테스트 + 시드 40개 헤드리스 검증 (커밋 전 관문) |
| `npm run sweep -- 100` | 화면 없이 시드 100개를 돌려 결과 분포와 교착 여부를 본다 |
| `npm run sweep -- 100 --diff hard` | 난이도를 바꿔서 같은 검증을 한다 |
| `npm run sweep -- 1 --log S7` | 시드 S7 한 교대의 전체 기록과 종료 보고서를 출력한다 |

## 조작 (관찰 전용)

| 조작 | 기능 |
|---|---|
| `Space` | 일시정지 / 재개 |
| `1` `2` `3` `4` | 1배속 / 3배속 / 8배속 / 15배속 |
| `A` | 자동 카메라로 돌아가기 |
| `C` | 도시 전체 보기 |
| `T` | 관찰자 시점 ↔ AI 시점 |
| 지도의 사건 핀 클릭 | 그 현장을 확대해서 본다 |
| 왼쪽 사건 카드·기록·타임라인 클릭 | 그 사건으로 관찰 대상을 고정한다 |
| 현장의 대원 또는 부대 목록의 이름 클릭 | 그 대원이 아는 정보와 행동 후보 점수를 본다 |
| 지도에서 휠·드래그 | 확대/축소, 이동 |

| 상단의 `난이도` 버튼 | 다음 교대의 조건을 정한다 (진행 중인 사건에는 영향 없음) |

**관찰자 시점**에서는 AI가 아직 모르는 사실(발견되지 않은 구조 대상, 숨은 용의자, 미확인 연료 누출, 무전 음영 구역, 신고 내용의 사실 여부)이 흐리게 함께 보인다. **AI 시점**에서는 AI가 아는 것만 보인다.

## 난이도

난이도는 교대가 **시작되기 전에** 정하는 조건이다. 사건이 벌어진 뒤에는 아무것도 바꿀 수 없다. 손잡이 다섯 개(각 1~5, 3이 기준)와 프리셋 네 개가 있다.

| 손잡이 | 바꾸는 것 |
|---|---|
| 사건 빈도 | 사건 사이 간격, 교대당 사건 수(5~11건), 동시에 진행되는 사건 수(2~5건) |
| 사건 심각도 | 규모 분포, 숨은 위험(잔해·잠긴 문·가스·누출), 부상 악화 속도, 화재 확산 속도 |
| 용의자 위협 | 무장 사건 비중, 총격범 비중, 용의자 수·공격성·사격 실력, 숨은 공범, 도주 시점 |
| 대원 장비 상태 | 차량 주행 속도, 펌프 상태와 마모, 용수 탱크, 구조·의료·방호 장비, 출근 시 체력 |
| 신고 신뢰도 | 침착한 신고자와 부정확한 신고자의 비율, 현장 목격자의 정확도 |

프리셋별 결과(시드 100개):

| 프리셋 | 손잡이 | 사건/교대 | 성공 | 부분 성공 | 대응 지연 | 미해결 | 실패 | 구조율 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 쉬움 | 2-2-2-4-4 | 6.0 | 80% | 12% | 3% | 1% | 4% | 95% |
| 보통 | 3-3-3-3-3 | 6.8 | 63% | 17% | 8% | 4% | 9% | 91% |
| 어려움 | 4-4-4-2-2 | 8.2 | 41% | 22% | 11% | 6% | 20% | 78% |
| 극한 | 5-5-5-1-1 | 10.0 | 17% | 20% | 16% | 7% | 40% | 63% |

손잡이 하나만 1과 5로 바꿨을 때의 성공률(나머지는 3): 사건 빈도 67% → 39%, 사건 심각도 76% → 46%, 대원 장비 상태 51% → 69%, 용의자 위협은 무장 사건 안에서 85% → 54%.

한 현장에는 같은 부서의 부대가 여러 팀 들어갈 수 있다(예: 경찰 2 + 소방 2 + 구급 1). 몇 대가 들어갈지는 배정 AI의 판단과 현장 지휘관의 지원 요청으로 정해지며, 부대 수에 상한은 없다. 시드 100개 실행에서는 한 사건에 최대 5대가 들어갔다.

## 화면 구성

- **왼쪽**: 진행·종료 사건(유형, 위험도, 배정 부대, 부족한 자원), 출동 부대 6대와 대원 12명의 상태.
- **가운데**: 도시 관제 지도 또는 현장 확대 화면. 통화 중에는 신고 통화창이 뜨고, 결정적인 순간에는 속보 띠가 뜬다.
- **오른쪽 위**: 판단 요약(신고 정보 → 상황 분석 → 배정 → 현장 지휘관의 작업 목록 → 문제와 복구) 또는 대원 정보.
- **오른쪽 아래**: AI 관제·무전 기록.
- **아래**: 배속 제어, 교대 진행 시간, 사건 타임라인.
- **교대 종료 시**: 사건별 결과와 원인 설명이 담긴 보고서.

## 시스템 구조

시뮬레이션(`src/sim`)과 표현(`src/view`, `src/ui`)이 분리되어 있다. `src/sim` 은 DOM, React, Canvas, `Math.random`, `Date` 를 쓰지 않으며(테스트로 강제), 그래서 Node에서 화면 없이 그대로 돈다.

```

  difficulty.ts               난이도 손잡이 → 수치 표, 프리셋
  rng.ts                      시드 난수. fork(label) 로 시스템별 독립 흐름
  events.ts                   EventLogger: 원인(causes) 연결을 가진 이벤트, 문제/복구 기록

  dispatch/analyst.ts         상황 분석 AI: 유형 확률, 위험도, 필요 자원, 재평가
  dispatch/dispatcher.ts      배정 AI: 적합도·도착 시간·피로·장비·예비 전력으로 부대 선택
  field/builders.ts           현장 생성(화재 건물, 사고 도로, 수색 구역, 무장 사건 매장)

  field/commander.ts          현장 지휘관 AI: 믿음 → 작업 목록, 배정, 지원 요청, 종료 판단
  field/sceneManager.ts       FieldSceneManager: 현장 틱, 부대 도착·철수, 지휘권 이양

  camera.ts                   CameraDirector: 흥미도 점수로 관찰 대상 자동 선택
```

### 한 사건의 흐름

1. **사건 발생**: 생성기가 유형·위치·규모·숨은 위험을 조합해 현장(30×20 격자)을 만든다. 이 시점부터 불은 번지고 부상자는 악화된다.
2. **신고**: 신고자는 침착함·공황·상황 파악 미흡·일부만 목격·부정확한 확신 중 한 성향을 갖고, 사건의 일부만 혹은 틀리게 안다. 접수 AI는 현재 가설에 따라 다음 질문을 고르고, 질문을 더 하는 가치가 시간 비용보다 낮아지면 통화를 끝낸다.
3. **분석**: 진술의 키워드와 신뢰도로 유형 확률과 위험도를 계산한다. 입력이 틀리면 결론도 틀린다. 추가 신고나 현장 보고가 오면 다시 평가한다.
4. **배정**: 필요한 능력별로 `적합도 − 도착 시간 − 피로 − 장비 상태 − 예비 전력 손실` 점수가 가장 높은 부대를 보낸다. 위치와 유형만 확인되면 먼저 출동시키고, 통화가 이어지면서 추가로 보낸다. 가용 부대가 없으면 대기열에 올리고, 긴급도 차이가 크면 다른 사건으로 가던 부대를 돌린다.
5. **이동**: 도로 그래프 위를 달린다. 정체와 통제를 반영하고, 교차로마다 경로를 다시 본다.
6. **현장**: 먼저 도착한 부대의 선임이 지휘를 맡고 현장 평가를 한 뒤 작업 목록을 만든다. 대원은 인지 → 믿음 갱신 → 목표 선택 → 실행 → 보고 → 재계획을 반복한다.
7. **종료**: 지휘관이 자신의 믿음으로 종료를 선언한다. 판정은 엔진의 진실로 내리므로 지휘관이 놓친 구조 대상도 보고서에 드러난다.

### 설계에서 정한 것들

- **정보 격리**: 대원은 시야 안에서 본 것과 무전·대면으로 들은 것만 안다. 이동 경로도 믿음으로 계획하므로, 잠긴 문이나 잔해는 부딪혀 본 뒤에야 알고 우회·제거·포기 중에서 다시 고른다.
- **실패는 상태에서 나온다**: 연기로 줄어든 시야 때문에 방 구석의 구조 대상을 지나치고, 출동 전부터 상태가 나빴던 펌프가 방수 중에 고장 나고, 통제되지 않은 차로에서 2차 사고가 난다. 난수는 사건 생성과 사격 판정 등 일부에만 쓴다.
- **능력치의 쓰임**: 전문 기술은 작업 속도, 상황 판단은 탐지 거리와 점수 추정 오차, 침착성은 위험 속 후퇴 성향과 협상·사격, 체력은 이동 속도와 소모, 경험은 반응 주기·수색 간격·자발적 임무 선택에 쓰인다. 팀워크는 동료 구조 적합도에만 쓰인다.
- **AI 구조**: 명세의 Utility AI + Behavior Tree + HTN 조합 대신, 대원은 Utility 목표 선택과 임무별 단계 실행기, 지휘관은 믿음에서 작업을 분해하는 규칙으로 구현했다. 대원 12명 규모에서는 이 편이 가볍고 추적하기 쉽다.
- **종료 보장**: 재시도 보류 시간, 현장별 한계 시간(400~470초), 교대 종료 후 7분 상한으로 모든 사건이 반드시 끝난다.
- **저장**: LocalStorage에 설정, 진행 중인 시드와 틱, 최근 교대 12개의 요약을 저장한다. 새로고침하면 같은 시드를 저장된 틱까지 다시 돌려 복원한다.

## 구현된 기능

**P0 (전부 구현)**

- 4개 구역(주거·상업·산업·외곽)의 도시, 소방서 2곳·경찰서 2곳·병원, 도로 그래프와 경로 탐색
- 신고 자동 생성, 신고자 성향 5종, 질문 선택형 통화, 추가 신고의 기존 사건 연결
- 상황 분석(유형 확률·위험도·필요 자원)과 재평가, 자원 배정과 대기열
- 차량 이동, 정체, 도로 통제 시 우회, 병원 이송과 재출동
- 현장 4종과 대원의 자율 행동: 현장 평가, 수색, 화재 진압, 급수 연결, 잔해 제거, 문 강제 개방, 구출, 응급 처치, 이송, 구급차 탑승, 교통 통제, 연료 누출 조치, 출입구 봉쇄, 협상, 진입·교전, 검거, 목격자 면담, 도로 정리, 동료 구조, 후퇴, 휴식, 장비 교체
- 문제 발생과 재계획(경로 차단 → 우회 또는 제거, 무전 음영 → 이동 후 재보고, 장비 고장 → 교체, 인원 불일치 → 재수색, 수색 실패 → 범위 재조정)
- 성공·부분 성공·대응 지연·미해결·실패 판정, 원인 연결 이벤트 기록, 자동 카메라, 종료 보고서, 일시정지와 배속

**P1 (구현)**

- 대원별 능력과 성향, 피로와 휴식, 장비 손상(펌프 마모, 용수 소진)
- 도로 교통 변화(정체, 공사 통제, 사고 구간 통제), 동시 사건 간 자원 경쟁과 부대 전환 배정
- 추가 신고와 현장 보고에 의한 평가 갱신, 지휘권 이양과 승계

**명세에 더한 것**

- 난이도 설정: 손잡이 5개와 프리셋 4개, 시드와 함께 저장·복원

- 무장 사건(대치, 협상, 진입, 교전, 도주, 검거): 요청에 따라 네 번째 유형으로 추가
- 관찰자 시점 / AI 시점 전환, 대원별 행동 후보 점수와 믿음 목록 표시
- 신고 통화창, 속보 띠, 날씨·야간 표현, 선택한 대원의 인지 범위 표시
- 헤드리스 실행기와 자동 테스트

## 미구현과 알려진 문제

- **경험치·숙련도 변화 없음**: 대원의 경험 수치는 누적되지만 능력치에 반영되지 않고 교대 사이에 저장되지도 않는다.
- **소규모 후속 사건 없음**, P2 항목(대형 재난, 위험물, 수난·산악, 병원 수용 능력, 예산, 장기 성장) 없음.
- **난이도가 유형별로 고르지 않다**: 보통 기준 화재는 성공 45%로 어렵고, 실종·조난은 성공 85%로 쉽다.
- **신고 신뢰도 손잡이는 결과를 거의 바꾸지 않는다**: 1과 5의 성공률 차이가 1%p 안팎이다. 오판과 재수색 같은 과정은 달라지지만, 현장에서 금방 바로잡히기 때문이다.
- **극한에서는 감당이 안 된다**: 사건의 13%가 한계 시간이나 무대응으로 끝난다. 과부하를 의도한 설정이다.
- **최초 배정이 보수적이다**: 사건의 절반가량에서 현장 지휘관이 추가 지원을 요청한다. 위치만 확인되면 먼저 보내는 방식의 결과다.
- **한계 시간으로 끝나는 사건이 있다**: 675건 중 17건(2.5%)이 지휘관의 종료 선언이 아니라 한계 시간으로 끝났다.
- **정보 격리의 예외 세 가지**: 지휘관은 7초마다 건물 밖에서 화염을 벽 너머로 관찰한다(재발화를 놓치지 않기 위한 근사). 이미 발견한 구조 대상이나 용의자가 움직일 때 대원은 그 현재 위치를 따라간다. 스스로 대피한 사람이 안전 구역에 도착하면 현장 무전망에 자동으로 알려진다.
- **건물은 단층**이고 현장 크기는 30×20 격자로 고정이다.
- **소리 없음**, 타임라인 되감기 없음.
- **데스크톱 전용**: 가로 1280px 이상을 기준으로 만들었고 터치 조작은 지원하지 않는다.
- **글꼴**: 시스템에 설치된 한글 글꼴을 쓴다.
- **재현 범위**: 같은 빌드, 같은 브라우저 엔진에서의 재현을 보장한다. 부동소수점 연산이 다른 엔진 사이의 일치는 확인하지 않았다.

| 항목 | 결과 | 확인 방법 |
|---|---|---|
| A 신고·출동 | 통과 | 자동 테스트: 모든 사건에 진술·평가가 있고, 도착한 사건은 지령 → 도착 순서가 성립 |

브라우저 확인은 헤드리스 Chromium(1600×900)에서 했다. 새로고침 복원(같은 시드·같은 난이도, 이어지는 틱), 난이도 설정 화면, 콘솔 오류 0건도 여기서 확인했다. UI 자체를 검사하는 자동 테스트는 없다.

난이도 도입 전후로 '보통'의 결과가 달라지지 않는 것은 시드 30개의 기록 해시를 비교해 확인했다(30개 모두 일치).
