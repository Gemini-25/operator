# 전체 설계 — 무엇을, 어떤 순서로, 어떻게 만드는가

이 문서는 **남은 작업 전체의 설계도**다. 세션이 바뀌어도(다른 모델이 이어받아도) 방향이 어긋나지 않도록, 결정된 것과 만드는 방법을 구체적으로 적는다.

- 작업 규칙과 함정은 `CLAUDE.md`, 지금 어디까지 했는지는 `docs/ROADMAP.md`, 사용자용 설명은 `README.md`.
- 이 문서의 묶음(M1, M2, N4b …)을 하나 끝내면 `ROADMAP.md` 의 체크를 고치고, 설계와 다르게 만든 점이 있으면 **이 문서를 고친다**(설계와 코드가 어긋난 채로 두지 않는다).
- 한 묶음 = 구현 → `npm run check` → 브라우저 확인(콘솔 오류 0건) → 커밋 → 푸시 → 문서 갱신.

## 1. 확정된 방향 (사용자가 정한 것)

| 항목 | 결정 |
|---|---|
| 게임의 성격 | 관찰 전용. 플레이어는 시간·시점·교대 시작 전 조건만 정한다. AI에게 명령하는 입력은 만들지 않는다 |
| 참고 | 911 Operator·119 Operator 류의 **장르 방식**(지도 중심 관제, 통화창, 사건 핀, 둥근 부대 표식, 다양한 신고 시나리오, 근무 보고서)을 많이 참고한다. 특정 게임의 아트·이름·지도·UI 배치를 그대로 옮기지는 않는다 |
| 지도 | 설계한 도시 하나(격자가 아님). 강 + 바다 + 산. 필요하면 실제 도시의 **구조를 모티브**로 삼아도 된다(이름·지도를 베끼지는 않는다) |
| 지도 위 표식 | **차량 그림을 쓰지 않는다.** 부대는 둥근 바둑돌 모양의 표식으로, 분야와 종류가 한눈에 구분되게. 길 위를 달리는 일반 차량 그림도 없앤다(난잡하다). 교통량은 도로의 색으로만 |
| 현장 화면 | 지금의 그림(건축 도면 방식, 제복 입은 인물, 차량, 화염·연기)을 유지한다. 현장에서는 차량 그림을 그대로 쓴다 |
| 건물 | 큰길가에만 몰려 보이지 않게 **골목·작은 길을 늘린다.** 건물은 도로와도, 서로도 겹치지 않는다(생성기가 보장하고 테스트가 검사한다) |
| 이름표 | 중요한 건물만 멀리서 보이고, 나머지는 확대하거나 마우스를 올릴 때 |
| 건물의 성격 | 용도를 섞고(주택가에도 가게·교회·공업사), 하나뿐인 랜드마크를 곳곳에 |
| 부대 | 경찰·소방·구조·구급·특수 네 분야에 3~5팀씩. 특수: 특공대, 폭발물 처리반, 구조 헬기, 구조정, 화학 구조대 (+ 사다리차) |
| 사건 | 네 묶음 모두: 생활 사건, 강력 범죄(테러·납치·인질극·추격전), 대형 사고(비행기 추락 등), 재난(태풍 등) |
| 재난 | 교대 시작 전에 고를 수 있고(없음·종류·무작위), 무작위로 두면 드물게 일어난다 |
| 맨 마지막 | 총격전 때 창문·가구가 깨지는 표현 |

## 2. 지금의 구조 (2026-11-14 기준)

```
cityPlan.ts  설계도 ─▶ city.ts  도로 그래프 + 길가에 건물 채우기 ─▶ City (고정, 한 번만 만든다)
scenarios.ts 시나리오 표 ─▶ incidents.ts 사건 생성(유형 → 시나리오 → 장소) ─▶ builders.ts 현장(진실)
callSystem(신고) ─▶ analyst(유형·위험도·필요 자원·이름) ─▶ dispatcher(부대 선택) ─▶ resources(이동) ─▶ sceneManager(현장)
pursuit.ts   추격전: 도주 차량이 도로를 달리는 동안 사건의 자리가 움직인다 ─▶ 서면 그 교차로에 현장
field/*      지휘관(commander) → 대원(brain) → 실행(executor), 세계 규칙(hazards), 믿음(beliefs)
view/*       지도(renderCity + city/staticCity + city/places), 현장(renderScene + scene/*)
```

핵심 자료형: `Place`(건물·터: 종류, 이름, 주소, `rot`, `rank`, 진입 교차로와 길가 지점), `RoadEdge`(`cls`: highway·arterial·street·local, `name`, `seq`, `bridge`), `Scenario`(유형 안의 사건 모습), `Unit`(`kind`, `field`, `air`, `sea`, `curb`), `Incident.truth`(`type`, `variant`, `placeId`, `placeKind`), `Incident.pursuit`.

## 3. 지도 표식 — 묶음 M2 (둥근 표식)

지도(`view/renderCity.ts`)에서 `drawEmergency`·`drawCar` 를 부르지 않는다. 현장(`renderScene.ts`)은 그대로 둔다.

**부대 표식 `drawToken(ctx, x, y, r, u, state, timeMs)`** — `view/city/tokens.ts` 를 새로 만든다.

- 모양: 반지름 `r = 9 × zs`(화면 화소, 축소 창에서는 3.5)의 원. 아래에 옅은 그림자, 가장자리에 밝은 테, 위쪽에 작은 하이라이트(바둑돌 느낌).
- 바탕색 = 분야: 경찰 `#3f7fd0`, 소방 `#d8503a`, 구조·구급 `#2fae7a`, 특수 `#8f6fd0`. (구급차는 구조·구급 안에서 테를 흰색으로, 구조 공작차는 주황 테로 구분)
- 안의 글자 = 종류(굵은 흰 글씨 한 자): 순(순찰) · 기(기동) · 특(특공대) · 폭(폭발물) · 진(진압) · 사(사다리) · 조(구조) · 급(구급) · 화(화학) · 헬(헬기) · 정(구조정). 같은 종류가 여럿이면 오른쪽 아래에 작은 번호.
- 상태: 출동 중 = 바깥에 도는 점선 테(분야색), 현장 = 노란 실선 테, 병원 이송 = 초록 테에 `+`, 복귀 = 55% 투명, 대기 = 아래 규칙.
- 대기 중인 부대: 멀리서(zoom < 2)는 시설 배지 옆에 **대기 수 숫자**만 쓴다. 가까이(zoom ≥ 2)에서는 시설 옆에 돌을 한 줄로 놓는다.
- 헬기: 같은 돌에 회전 날개 호 두 개, 그림자를 멀리 떨어뜨려 떠 있음을 보인다. 구조정: 돌 뒤에 짧은 물결.
- 호출부호 이름표: 관찰 중인 사건의 부대이거나 zoom ≥ 1.8 일 때만. 도착 예정 초는 이름표 안에.
- 경로선: 모든 이동 부대에 옅게(투명도 0.22), 관찰 중인 사건의 부대만 진하게.
- 도주 차량: 빨간 돌에 `!`, 퍼지는 고리, 지나온 길 점선(지금 구현의 모양에서 차량 그림만 돌로 바꾼다).
- 사건 핀: 지금 모양 유지(둥근 아이콘 + 진행 고리).

**일반 차량**: `renderCity.ts` 의 ambient 차량 그리기를 지운다. 교통량은 지금 있는 도로 색 덧칠(혼잡 주황·빨강, 통제 빨간 점선)로만 보인다. 덧칠의 투명도를 조금 올려 읽히게 한다.

완료 조건: 지도 화면에 차량 스프라이트가 하나도 없다. 17팀이 모두 움직일 때도 도로가 가려지지 않는다(스크린샷 확인). `hitCity` 의 부대 클릭 판정이 돌의 반지름과 맞는다. 시뮬레이션 결과는 한 건도 달라지지 않는다(표현만 바꿨다).

## 4. 지도 — 묶음 M1 (작은 길과 겹침 보장)

문제: 지금은 설계도의 도로 50개(큰 블록) 길가에만 건물이 줄지어 있고, 블록 안쪽은 막다른 골목과 띄엄띄엄한 건물뿐이다.

### 4.1 이면 도로를 블록 안에 낸다 (`city.ts` `addLocalStreets`)

설계도(`cityPlan.ts`)는 그대로 큰 뼈대만 갖고, 블록 안의 작은 길은 생성기가 낸다(설계도가 지저분해지지 않는다).

1. **블록(면) 찾기**: 도로 그래프에서 반변(half-edge) 순회로 면을 구한다. 각 교차로에서 나가는 간선을 각도로 정렬하고, `(u→v)` 다음 간선은 `v` 에서 `(v→u)` 의 시계 방향 다음 간선. 넓이가 음수(바깥 면)인 것은 버린다.
2. **나눌 블록 고르기**: 넓이 > 55,000, 중심이 뭍(`coastY`)·평지(`mountainAt < 0.25`)·시가지(`districtAt().density ≥ 0.55`)인 면.
3. **길 내기**: 면의 변 가운데 가장 긴 변 `e1`(고속도로·다리 제외)을 고르고, 맞은편에서 `e1` 의 법선 방향과 가장 잘 맞는 변 `e2` 를 고른다. 두 변 위 0.35~0.65 지점(난수)에 새 교차로를 넣어 변을 둘로 쪼개고(이름·등급 유지, `seq` 다시 매김), 두 교차로를 `local` 등급 도로로 잇는다. 이름은 `${e1.name} ${n}길`.
   - 선분이 면 안에 있고, 강·호수·바다·철길·손으로 놓은 건물(`LANDMARKS`)을 지나지 않을 때만 낸다(8등분 표본 + 상자 충돌).
   - 길이가 260 을 넘으면 가운데에 꺾이는 교차로를 하나 두고 ±18 만큼 비튼다(직선만 늘어서지 않게).
4. **한 번 더**: 나뉜 두 면이 아직 70,000 보다 크면 같은 방법으로 한 번 더 나눈다(깊이 2 까지).
5. 그 뒤에 지금의 순서대로: 막다른 골목(차가 못 다니는 좁은 길) → 길가 채우기 → 블록 안쪽 채우기.

기대: 교차로 78 → 130~150, 이면 도로 30~45개, 건물 1,200 → 1,600 안팎. 이면 도로는 실제 도로망이므로 차량이 건물 앞까지 들어간다.

### 4.2 겹침을 수식으로 막는다

지금의 검사는 상자의 아홉 점만 본다(긴 창고 밑으로 좁은 길이 지나갈 수 있다). 다음으로 바꾼다.

- `rectSegDist(box, ax, ay, bx, by)`: 선분을 상자의 좌표계로 돌린 뒤 선분-직사각형 최소 거리를 구한다. 건물은 모든 도로에 대해 `거리 ≥ 도로 반폭 + 2.5`, 골목에 대해 `≥ 5.5`, 철길 `≥ 8`.
- 물: 강은 상자 둘레를 6 간격으로 표본 떠 `riverDist ≥ 7`, 바다는 `y < coastY(x) − 8`, 호수는 타원 밖.
- 건물끼리: 지금의 분리축 검사(`obbHit`)에 여유 2.5(주택 3.5, 아파트 9, 공장 7).
- **손으로 놓은 건물도 같은 검사를 통과해야 한다.** 생성 때 어기는 랜드마크가 있으면 예외를 던진다(이름과 무엇에 걸렸는지). 걸리면 `cityPlan.ts` 의 좌표를 고친다. 터(공원·해변·활주로·부두·컨테이너 부두)는 물가에 걸칠 수 있으므로 도로 검사만 한다.

### 4.3 테스트 (`건물마다 정해진 도시`)

- 모든 건물 × 모든 도로: `rectSegDist ≥ 반폭`. 모든 건물 쌍(공간 해시로 이웃만): 겹치지 않음. 물 위·지도 밖 없음. 랜드마크 포함.
- 도로끼리 교차 없음(끝점 공유 제외), 모든 교차로에 닿음, 이면 도로가 20개 이상, 건물의 85% 이상이 가장 가까운 도로에서 60 이내.
- 지도가 교대마다 같음(지금 테스트 유지).

지도를 바꾸면 사건 위치가 달라져 모든 결과가 바뀐다. `npm run sweep -- 60` 과 네 프리셋을 다시 재고 `README.md`·`ROADMAP.md` 의 수치를 고친다.

### 4.4 실제 도시 모티브 (선택)

지금 도시는 "강 하구의 항구 도시"를 직접 설계한 것이다: 로터리와 방사로(구도심), 두 겹의 순환로, 강 서쪽의 주택가, 비스듬한 신도시, 동쪽의 고속도로와 공항, 남쪽의 항구와 공단, 북서쪽의 산과 호수. 더 사실적으로 가려면 실제 항구 도시의 **뼈대만** 본뜬다(강과 해안선의 굴곡, 구도심과 신시가의 위치 관계). 지명·도로 이름·랜드마크 이름은 지어낸 것을 쓴다.

## 5. 사건 체계

유형(8개)은 관제·현장 AI의 큰 규칙을 정하고, 시나리오(`scenarios.ts`)는 모습을 바꾼다. **새 사건은 되도록 시나리오로 넣는다.** 유형을 늘리면 고칠 표가 열 곳이 넘는다.

### 5.1 지금 있는 것

| 유형 | 시나리오 |
|---|---|
| 화재 | 일반(단층·2층), 오인 신고 |
| 교통사고 | 충돌, 버스 추돌, 쓰러진 나무(도로 통제), 맨홀 추락, 난폭 운전(추격전) |
| 실종·조난 | 실종(배회), 조난(등산객) |
| 무장 | 강도, 난동, 총격, 인질극, 장난 전화, 가정 폭력, 침입 절도, 납치(추격전) |
| 응급 환자 | 심정지, 낙상·외상, 실신 |
| 건물 붕괴 | 붕괴, 승강기 갇힘 |
| 가스 누출 | 누출(밸브 차단·폭발·주변 통제) |
| 수난 사고 | 강·호수·해수욕장·부두의 익수 |

### 5.2 N4b 강력 범죄 (다음 묶음)

**(가) 폭발물** — 유형 `armed`, 시나리오 `bomb`(실제 장치) · `bombthreat`(협박 전화, 장치 없음) · `package`(주인 없는 가방, 35%만 진짜).

- 자료: `PropKind` 에 `'bomb'`(`real`, `fuse`: 터지는 시각, `mitigated`: 해체됨). `WorkKind` 에 `'defuse'`. `Needs`·`UnitCaps` 에 `eod` 를 더한다(`emptyNeeds`, `dispatcher.MINCAP`(0.9), `resources.caps()`·`KIND`·`AID_KIND`(인근 도시 폭발물 처리반), `analyst.needsText`, `panels` 의 필요 자원 표시).
- 신고: `NATURE` 키 `bombthreat`("폭탄을 설치했다는 전화를 받았어요"), `package`("주인 없는 가방이 계속 놓여 있어요"). 관제 이름 "폭발물 의심".
- 분석: 경찰 2, 폭발물 1, 구급 1·진압 1(대기). 위험도 2.3 이상.
- 현장: 건물은 장소 종류로(`planBuilding`). 안에 시민 4~9명(걸을 수 있음). 장치는 방이나 홀의 가구 옆.
- 지휘관(용의자가 없는 무장 현장): ① 시민 대피 — 경찰이 본 시민은 `hostage` 표시가 풀려 스스로 나간다. ② 방 수색(지금의 `search`). 장치를 3칸 안에서 보면 믿음 `haz: bomb`. ③ 장치를 알면 6칸 안의 다른 작업을 취소하고 `defuse` 를 낸다. 폭발물 처리반이 없으면 `request('eod')`. 나머지 경찰은 출입구 봉쇄. ④ 모든 방을 보고도 없으면 "이상 없음"으로 종료(협박 전화는 `FALSE_ALARM`).
- 실행 `defuse`: 폭발물 처리반만(`fitFor`: `u.kind === 'eod'`). 옆 칸에서 `26 / (0.5 + 숙련)` 초. 매초 `0.004 × (1 − 숙련)` 로 실수 → 폭발.
- 세계 규칙 `hazards.tickBomb`: `real && !mitigated && sim.t ≥ fuse` 면 폭발 — `blast(…, 반경 3.4, 피해 55)`, 반경 2 의 칸에 불, 벽 손상. 그 뒤는 화재·붕괴 규칙으로 이어진다(지휘관이 진압·구조·구급 요청). 문제 코드 `ESCALATION`.
- 판정: 해체했거나 확인만으로 끝나고 다친 사람이 없으면 성공. `hazardActive` 에 해체되지 않은 진짜 장치를 넣는다.
- 장소: 기차역, 공항 터미널, 백화점, 버스·여객선 터미널, 마트, 은행, 사무용 건물, 호텔, 경기장, 방송국, 대학교, 시장, 발전소.
- 그림: 장치 소품(가방·상자, 깜박이는 불, 관찰자 시점에서 남은 시간), 폭발 효과는 지금의 `boom`.

**(나) 대형 인질극 `siege`** — 지금의 인질극을 키운다: 인질 4~6명(방 둘에 나뉘어), 총을 든 용의자 2~3명, 시한이 길다. 필요: 경찰 2, 기동·특공 2, 구급 1. 장소: 공항 터미널, 백화점, 은행, 방송국, 대학교, 버스 터미널. 한계 시간 +120초.

**(다) 도주 차량 `getaway`** — 총을 든 용의자가 현장을 빠져나가면(지금은 재범 예약) 절반은 그 교차로에서 추격전이 시작된다. `pursuit.ts` 의 종류에 `getaway` 를 더한다(선 뒤의 현장: 총을 든 용의자, 인질 없음).

**(라) 납치범의 은신처** — 납치범의 목표를 60%는 도시 밖, 40%는 은신처(외곽·공단의 창고·공업사·농가·펜션)로. 시야를 벗어난 채 은신처에 닿으면 추격은 "놓침"으로 끝나고, 40~90초 뒤 제보 전화로 그 건물의 인질 사건(`hostage`)이 이어진다(`gen.chain` 에 장소와 시나리오를 실어 보낸다).

**(마) 폭동 `riot`** — 경기장·시장·광장. 비무장·흉기 용의자 6~10명이 흩어져 있고 다친 시민 2~4명, 작은 불. 지금의 협상·검거 규칙으로 처리하되 경찰 3팀 이상이 필요하다. 한계 시간 +120초.

**(바) 연쇄 방화 `arson`** — 밤이나 상점·창고의 화재 넷 중 하나. 현장에서 목격자 면담(지금의 `interview`)을 마치면 다음 방화 전에 검거될 확률이 오른다. 못 잡으면 60~120초 뒤 가까운 곳에서 다음 불(최대 세 번).

### 5.3 N5 대형 사고

드물게(위험도 3 인 사건 가운데 `tune.majorProb`, 보통에서 두 교대에 한 번쯤) 일어나고, 여러 부대를 오래 묶는다. 모두 지금의 규칙(구출·처치·이송·진압·수난 구조) 위에 규모만 키운다.

| 시나리오 | 유형 | 장소 | 현장 | 필요 |
|---|---|---|---|---|
| 비행기 추락 `plane` | 화재 | 활주로·공항 부지, 드물게 주택가 | 들판에 동체 세 토막(`vehicle` 소품에 `skin: 'fuselage'`, 탑승자 12~20명), 새는 연료에 붙은 불, 잔해 | 진압 3, 구조 2, 구급 4, 경찰 1, 헬기. 한계 +240초 |
| 열차 탈선 `train` | 교통사고 | 철길 건널목(철길에 가까운 교차로), 가온역 | 객차 2~3량(`skin: 'train'`, 10~16명), 건널목에서 부딪힌 차 | 구조 2, 구급 3~4, 경찰 1. 한계 +170초 |
| 다중 추돌 `pileup` | 교통사고 | 도시고속도로의 교차로 | 차량 5~7대, 8~12명, 연료 누출. 안개면 더 잦다. 그 구간 통제 | 구조 2, 구급 3, 진압 1, 경찰 1 |
| 가스 폭발 `gasblast` | 건물 붕괴 | 식당·다세대 주택·상점 | 붕괴 구역 + 처음부터 붙은 불 + 새는 밸브, 밖에 다친 행인 | 진압 2, 구조 1, 구급 2, 화학 1 |
| 크레인 붕괴 `crane` | 건물 붕괴 | 공사장 | 길 위로 넘어진 크레인, 잔해에 깔린 작업자, 흔들리는 구조물(2차 낙하) | 구조 2, 구급 2, 경찰 1 |
| 선박 화재 `ship` | 화재 | 부두·여객선 터미널·컨테이너 부두 | 부두에 댄 배(홀형 평면에 `skin: 'ship'`), 물에 뛰어든 선원(수난 구조) | 진압 2, 구조 1, 구급 2, 구조정 |

공통: 사상자가 많으므로 한계 시간 가산, 응급실 인계 대기, 인근 도시 지원이 자연스럽게 걸린다. 보고서에 "대형 사고" 표시.

### 5.4 N6 재난

**설정**: `Difficulty` 에 `disaster: 'none' | 'typhoon' | 'flood' | 'quake' | 'wildfire' | 'tsunami' | 'random'`. 난이도 화면에 선택 줄, 주소 `&disaster=typhoon`, `difficultyKey` 에 포함, 프리셋 기본값 `none`. `random` 은 심각도 손잡이에 따라 0 · 5 · 10 · 18 · 30% 로 하나가 일어난다(`sim.rng.fork('disaster')`).

**뼈대 `sim/disaster.ts`**: `initDisaster(sim)`, `tickDisaster(sim)`(엔진에서 `tickIncidents` 앞). 상태 `{ kind, phase: 'calm' | 'warning' | 'impact' | 'aftermath', tWarn, tImpact, tEnd, queue: { at, scenario, where }[] }`. 재난은 **지금 있는 시나리오를 한꺼번에 여러 곳에 일으키고 도시의 상태(도로·날씨)를 바꾸는 것**이다. 사건 하나하나는 평소와 같은 규칙으로 처리된다. 재난 중에는 평소 사건 생성 간격을 1.6배로 늘린다.

| 재난 | 예고 | 일어나는 일 |
|---|---|---|
| 태풍 `typhoon` | 교대 15~25% 시점에 특보 | 날씨를 비로 고정, 충격 구간(30~70%) 동안 12~20초마다: 쓰러진 나무(도로 통제), 끊어진 전선, 간판 낙하(외상), 지붕 파손(작은 붕괴), 강변 침수(수난), 표류 선박(부두 수난). 정전 시 지도가 어두워지고 전 구간 혼잡 +0.4 |
| 홍수 `flood` | 수위 경보 | 강에서 60 이내의 도로가 차례로 느려지다 통제(절정에 다리 통제), 둔치·강변 주택의 수난 구조(지붕 위 사람: 구조정·헬기), 지하 누출 |
| 지진 `quake` | 없음 | 한순간에 붕괴 3~5(가스 폭발 포함), 화재 2~3, 가스 누출 2, 승강기 갇힘 3, 교통사고 2, 도로 몇 구간 통제. 120~200초 뒤 여진: 진행 중인 붕괴 현장의 2차 붕괴와 새 사건 1~2건. 인근 도시 지원 +3 |
| 산불 `wildfire` | 연기 신고 | 산(`MOUNTAINS`)에서 불머리가 바람을 타고 6~10분에 걸쳐 가장 가까운 동네로 번진다. 지도에 탄 자리가 커지고, 가장자리에서 현장이 열린다(`fire/wild`: 숲 현장, 나무가 탄다, 펜션 주민 대피). 헬기가 현장에 있으면 번지는 속도 ×0.7. 산길 통제, 가까운 동네는 연기로 시야 감소 |
| 해일 `tsunami` | 경보(대피 시간) | 예고 동안 해수욕장·부두의 사람들을 뭍으로 옮겨야 한다(경찰의 대피 유도 사건). 충격: 바닷가의 수난 구조 여러 건, 해안로 통제, 전복 선박 |

- 산사태 `landslide`(붕괴 유형, 산길의 교차로, 도로 통제, 묻힌 차·집)는 태풍·지진·홍수에 딸려 일어난다.
- 지도 그림: 재난 덧칠(바람 줄기, 강을 따라 번지는 물, 탄 자리, 지진 순간의 물결, 해일 띠), 상단 특보 띠, 보고서에 "재난 대응 요약".
- 균형: 재난 교대는 평소보다 어렵다. `npm run check` 의 기준 범위는 재난 없음에만 적용하고, `sweep --disaster typhoon` 을 따로 둔다.
- 테스트: 재난마다 교대가 끝까지 가고, 재난 표시가 붙은 사건이 정해진 수 이상 나오고, 통제된 도로가 교대 끝에 풀려 있거나 표시되며, 같은 시드는 같은 결과.

### 5.5 N7 현장 파손

- `Scene.glass: Uint8Array`(창이 깨졌는가), 가구의 내구(`decorHp`).
- 사격(`executor.shootAt`, 용의자의 사격): 탄도 선이 창 칸을 지나면 깨진다(효과 `glass`, 소리). 엄폐물로 쓰인 가구는 맞을 때마다 내구가 줄고, 다 닳으면 그 칸이 바닥이 된다(**엄폐가 사라진다** — 전술에 영향).
- 섬광탄은 2칸 안의 창을, 폭발(폭발물·가스)은 반경 안의 창과 가구를 부순다.
- 그림: `staticSig` 에 파손 상태를 넣어 고정 층을 다시 그린다. 깨진 창(유리 조각), 부서진 가구.
- 테스트: 총격이 있었던 현장에 깨진 창이 생기고, 가구가 부서진 뒤 그 뒤의 용의자가 더 잘 맞는다.

### 5.6 뒤로 미룬 것 (하고 싶은 것 목록)

다리 위의 위기자(협상 → 실패 시 수난 구조), 동물 출몰(멧돼지·뱀·벌집), 끊어진 전선, 문 잠김 개방, 주취자, 실종 아동, 산업 재해(끼임), 감전, 집단 식중독, 산악 구조(헬기 인양), 낙뢰·정전, 화재 경보 오작동, 사다리차의 창문 구조, 구조정의 현장 그림, 기차 운행.

## 7. 균형과 측정

- 보통 난이도의 목표: 성공 70~80%, 실패 + 미해결 5~12%, 한계 시간 종료 1% 이하, 교대당 사건 12~15건. 프리셋 순서(쉬움 > 보통 > 어려움 > 극한)가 15%p 안팎으로 벌어질 것.
- 묶음마다: `npm run sweep -- 60`(전후 비교), 새 시나리오는 `scripts` 의 임시 스크립트로 시나리오별 결과(성공·부분·실패·한계 시간)를 60교대에서 센다. 한계 시간 종료가 나오면 `sweep -- 1 --log 시드` 로 기록을 읽고 원인을 고친다(대개 "기다리는 자원이 오지 않는다" 아니면 "닿지 못하는 자리").
- 수치를 문서에 적을 때는 방금 잰 값만 적는다(`README.md` 의 표, `ROADMAP.md` 의 "지금 상태").

## 9. 어기면 안 되는 것 (요약 — 자세한 것은 `CLAUDE.md`)

1. 플레이어가 AI에게 명령하는 입력을 만들지 않는다.
2. 같은 시드 + 같은 조건 = 같은 결과. 새 기능은 새 난수 흐름(`sim.rng.fork`).
3. `src/sim` 은 화면 코드를 import 하지 않는다.
4. AI는 자기 믿음으로만 판단한다. 관제는 신고·목격·부대의 시야로만 안다(추격전의 `reportedNode` 처럼).
5. 기록은 상태를 바꾸는 코드에서만 남긴다.
6. 모든 사건은 반드시 끝난다. 새 시나리오마다 한계 시간 종료 건수를 센다.
7. 특정 게임의 아트·이름·지도·배치를 그대로 옮기지 않는다.
