## 설계와 다르게 한 곳

- hazards.blast has no noSignal parameter (I1-b b0 sends no blast signal), so it is called with the existing 9 arguments: blast(sim,s,I,x,y,1.5,18,ev,'blast').
- blockerRate takes a 5th argument I (bestTool records hidden faults). ExecKit gained unblock(sim,s,a,tile,method?) → event id, because methodRun cannot import executor.
- The charge waits for any agent in the 2.5 radius including downed ones; the spec says only active agents. ESCALATION is detected from casualty and suspect health before and after blast within 2 tiles. Text: '문 뒤에 있던 ○○이/가 폭파에 휘말려 다쳤습니다!'; detail: '폭파 진입으로 ○○ 부상'. A charge on door-blocking debris also writes a recBreach (door -1, how 'charge') so the blast is drawn.
- Barricade 'unheld casualty' uses hazards.isHeld. Hostage scenes have two hostages, so counting only hostageId almost never allowed a barricade. Conditions are checked once at the decided time; a door with someone standing on it is skipped.
- Room-entry locked door: every gathered agent computes the same opener (an existing sub-task on that door wins). The door-check belief is shared with gathered mates; pendingBlock is cleared. The 25s cap marks PATH_BLOCKED recovered. A door opened by a sub-task gets no second recBreach, so the G5 test now also counts the earlier forced record.
- stackSpot: BFS of up to 12 steps over truth-walkable tiles without crossing the door. Axis is vertical when the tiles left and right of the door are walls. Spots claimed by other agents are skipped (0debf70). The claimed marker is t.range=1, same as in 1b.
- toolClear completion text is '장비로 잔해를 잘라 통로를 확보했습니다.' rather than the spec's '절단기…'. Kick is not plain, so it announces with the noGear prefix (e.g. '유압 구조기가 없습니다. 장비 없이 문을 걷어차 열겠습니다.'), per the spec's noGear definition.
- Step 3: basic extrication kits include spreader, and its speed is the R1 formula using bestTool. The spec listed only irons/lightRescue, which dropped spreader-only extricators to manual (0.12) in manhole, fire and cabin extrications and broke the 'keep the usual formula' intent. Shore speed after prep equals basic.
- rapid's 'burning region' is the fire belief of the casualty's own region (> 0.3). Completion text for non-plain methods is '구조 대상 A, <noun> 구출 완료. 이송이 필요합니다.'; plain methods keep the old text, because the H1 test searches for '구출 완료'. Extrication also sets freedHow/freedBy.
- Search MethodUse is recorded once at task completion (eventId -1). The methodReport search sentence is kept only if that agent discovered someone during the task. The detection-kit check happens at the first waypoint (ptI 0).
- casFact veh/pit are set only while the casualty is trapped. Leak facts created by X6 catastrophe.ts (inactive, ignited) carry no sub; that file is read-only.
- Drawing: the charge strip is placed on the agent's face of the door. The countdown digit is drawn one tile above the door. Barricade furniture goes on the side with the smaller region.

## 알려진 문제 — 다음 작업자가 알아야 할 것

- Breaching charge is rare (above): barricaded doors get kicked open before entry by passers-by, and breachers seldom sit in entry teams. When a charge does happen and the breacher has no belief of the hostage's position, hostages behind the door get hurt (S24). R3 S26 is where 'no charge without hostage location' belongs; a commander 'force' order for known locked hostile-room doors would route the breacher.
- Before entry, agents can kick open a barricaded hostage room while doing other work. This scene is new: armed scenes had no locked doors before barricades.
- rapid extrication is frequent (27% in normal 60): fire smoke and collapse dust > 0.3 trigger it at arrival recheck. Normal 60 fire/std failures went 21 → 28, while the 9 forced sets went 110 → 105, so this could not be separated from sampling noise. The spec knob (sense smoke 0.3 → higher) was not turned.
- airRescuer carrying only lightRescue can open doors only by kicking (the irons row requires irons); R1 used lightRescue at 0.6. Rare.
- Kick start announcements add one log line per door for unequipped police and EMS (kick is non-plain by spec).
