- **R1 부대 편성·개인 장비·헬기 — 구현 중** (2026-11-15 시작, 워크플로 `package-run`). 그 뒤 H1 → X6 → R2 → R3 → I1-b → I2 를 같은 방식으로 하나씩 한다.

  - 진행 중인 묶음의 가장 최신 커밋은 **로컬 브랜치 `wf/<묶음>`**(R1 은 `wf/crews`)이 가리킨다 — 작업자가 커밋할 때마다 옮긴다. 주 브랜치(`claude/great-ptolemy-s31sxn`)에는 **덩어리 하나가 관문(`npm run check`)을 통과할 때마다** 그 자리까지 `git merge --no-ff` 로 합쳐 푸시한다(컨테이너가 사라져도 그 단계부터 이어받게). 그래서 주 브랜치는 언제나 `npm run check` 통과 상태지만, 묶음이 진행 중이면 균형·화면·문서가 중간 상태일 수 있다(그 설계서 끝의 "구현 메모 (진행 중)"에 어디까지 했는지와 실제 이름이 있다).

## 병렬 작업 규칙 (여러 에이전트가 동시에 할 때)

트랙마다 주로 만지는 파일이 다르다. 한 트랙에는 한 번에 한 에이전트만 둔다.

| 트랙 | 소유 파일 | 비고 |
|---|---|---|
| S-균형 | `sim/difficulty.ts`, `sim/incidents.ts`, `sim/field/builders.ts`, `sim/field/hazards.ts` | 수치만 바꾼다. 검증은 `sweep` |
| S-현장AI | `sim/field/commander.ts`, `brain.ts`, `executor.ts`, `agents.ts`, `sceneManager.ts` | 새 임무는 `CLAUDE.md` 확장 표대로 |
| S-관제AI | `sim/dispatch/*` | |
| S-기반 | `sim/engine.ts`, `resources.ts`, `city.ts`, `debrief.ts`, `events.ts` | |
| V-그래픽 | `view/renderCity.ts`, `renderScene.ts`, `view/scene/*`, `view/city/*`, `icons.ts`, `camera.ts` | 시뮬레이션 결과가 달라지면 안 된다 |
| U-패널 | `ui/*` | |
| T-도구 | `scripts/*`, `tests/*` | |

- `sim/types.ts` 와 `util.ts` 는 공유 파일이다. 필드·코드 **추가만** 하고, 병합 충돌이 나면 양쪽 추가를 모두 살린다.
- S-트랙 둘이 동시에 수치를 바꾸면 결과 분포의 원인을 가릴 수 없다. S-균형은 다른 S-트랙이 끝난 뒤 마지막에 돌린다.
- 각 에이전트는 자기 묶음의 "완료 조건"을 `npm run sweep` 출력으로 증명하고, 전후 수치를 보고에 적는다.

## 다음 작업 묶음

우선순위 순. ID 앞 글자는 트랙이다.

### A1 소리 다듬기 — V-그래픽
- 현재: `view/audio.ts` 의 합성음은 헤드리스 브라우저에서 오류 없이 도는 것만 확인했다. 사람이 들어 본 적이 없다.
- 할 일: 직접 들으며 음색·음량·빈도를 조정. 배속이 높을 때 소리가 몰리지 않는지 확인.
- 완료 조건: 사용자가 들어 보고 승인.

### M2 지도의 다음 단계 — S-기반 + V-그래픽
- 현재: 건물마다 종류·이름·주소가 있고 사건이 그 건물에서 난다. 블록 안의 이면 도로(M1)로 차량이 건물 가까이 들어가지만, 막다른 골목은 지도와 주소에만 있다. 현장은 건물 종류만 따르고 지도의 건물 외곽과는 무관하게 30×20 격자에 만든다. 소방서·병원 같은 공공 시설에서는 사건이 나지 않는다.
- 할 일: (1) 같은 건물의 재발(탄 지붕·무너진 지붕·통제선의 흔적은 G4 가 그린다 — 교대를 넘는 흔적은 I2). (2) 지도의 건물 외곽·층수와 현장 평면 맞추기. (3) 학교·병원·공항 터미널 같은 큰 시설의 전용 현장. (4) 지도 편집 화면.
- 완료 조건: 항목별로 따로 잡는다. 지도를 바꾸면 사건 위치가 달라지므로 매번 `sweep -- 100` 으로 다시 잰다.

### C4 새 유형의 깊이 — S-현장AI + S-균형
- 건물 붕괴: 탐지는 지금 구조대의 발견 보정뿐이다(`agents.detectRadius`). 청음·탐지견 같은 행동, 구역별 안전 판정, 장시간 매몰자 상태 변화를 넣을 수 있다.
- 가스 누출: 경찰의 출입구 통제는 들어갔다. 환기, 바람 방향, 주변 건물 대피 안내는 없다.
- 수난 사고: 물가에서 줄을 던지는 구조뿐이다. 보트·잠수, 하류에서 기다리는 차단선, 급류 등급을 넣을 수 있다.
- 다수 사상자 사고: 버스 추돌 하나뿐이다. 현장 분류소(중증도 분류 뒤 이송 순서 결정)와 병상 수 한계를 넣을 수 있다. 지금 병원은 인계 대기 시간만 있다(`resources.ts`).
- 2층 건물: 화재·붕괴·가스 누출에 있다. 무장 사건으로 넓히고, 3층 이상과 창문 구조(사다리)를 본다.

### C5 건물 전체 수색 계획 — S-현장AI
- 현재: 지휘관은 건물 출입구를 최대 두 곳 고르고(`commander.planEntry`), 방은 진입조가 용의자를 쫓아가며 문 앞 대기 → 섬광탄 → 진입을 한다(`executor.roomDoorFor`).
- 할 일: 용의자의 위치를 모를 때 방을 순서대로 훑는 계획(구역 나누기, 확인한 방 표시).

### K1 대원 경험치 성장과 교대 간 저장 — S-기반 + U-패널
- 현재: `Responder.xpGained` 만 쌓이고 쓰이지 않는다.
- 할 일: 교대 종료 시 경험·숙련 소폭 상승, 부상자는 다음 교대 결장, LocalStorage 저장. 재현성을 위해 "명부 상태"를 `Sim` 생성자의 입력으로 받는다.
- 완료 조건: 재현성 테스트에 명부 입력 추가, 저장된 명부로 재실행 시 해시 일치.

### K2 AI가 실패에서 배우기 — S-관제AI
- 종료 보고서의 오판 기록(`MISJUDGE_TYPE`, `UNDERESTIMATE`, `FALSE_ALARM`)으로 분석·배정 기준이 교대 사이에 조금씩 바뀐다. K1 과 같은 방식으로 "조직 기억"을 입력으로 받는다.

### T2 정보 격리 예외 3건 제거 — S-현장AI
- 지휘관의 벽 너머 화염 관찰, 움직이는 대상 추적, 안전 구역 자동 통보(`README.md` 참고).

### P2 (이후)
- 병원 수용 능력, 예산·시설, 장기 성장, 다리 위의 위기자·동물 출몰·끊어진 전선 같은 생활 사건, 금고털이.
