# AUTONOMOUS RESPONSE

자율형 긴급구조 조직 시뮬레이션. 경찰·소방·구급 AI 조직이 가상의 도시에서 스스로 신고를 받고, 판단하고, 출동하고, 현장에서 협력하고, 실패하고, 다시 시도한다. 플레이어는 지휘관이 아니라 **관찰자**다. 화면에는 AI에게 명령을 내리는 조작이 하나도 없다.

- 브라우저에서만 실행된다. 서버, 외부 API, LLM 호출이 없다. TypeScript + React + Vite, 그림은 Canvas 2D.
- 같은 시드와 같은 난이도로 실행하면 같은 교대가 그대로 재현된다. 되감기도 이 성질로 구현했다.
- 사건 유형 5가지: 건물 화재, 교통사고, 실종·조난, 무장 사건(대치·총격·인질), 응급 환자. 여기에 허위·오인 신고와 비긴급 전화가 섞인다.

이어서 개발할 사람(또는 AI 세션)은 `CLAUDE.md` 와 `docs/ROADMAP.md` 부터 읽는다.

## 설치와 실행

Node.js 20 이상이 필요하다.

```bash
npm install
```

```bash
npm run dev
```

브라우저에서 `http://localhost:5173` 을 연다. 주소 뒤에 `?seed=원하는글자` 를 붙이면 그 시드로, `&diff=hard` 나 `&diff=4,4,4,2,3,3` 을 붙이면 그 난이도로 시작한다.

| 명령 | 하는 일 |
|---|---|
| `npm run build` | 타입 검사 후 정적 파일을 `dist/` 에 만든다 |
| `npm test` | 자동 테스트 29개 |
| `npm run check` | 타입 검사 + 테스트 + 시드 40개 헤드리스 검증 (커밋 전 관문) |
| `npm run sweep -- 100` | 화면 없이 시드 100개를 돌려 결과 분포와 교착 여부를 본다 (`--diff hard`, `-v`, `--json`) |
| `npm run sweep -- 1 --log S7` | 시드 S7 한 교대의 전체 기록과 종료 보고서를 출력한다 |

## 조작 (관찰 전용)

| 조작 | 기능 |
|---|---|
| `Space` | 일시정지 / 재개 |
| `1` `2` `3` `4` | 1배속 / 3배속 / 8배속 / 15배속 |
| `←` `→` | 10초 되감기 / 앞으로 |
| 타임라인 클릭 | 그 시각으로 이동 (되감기 포함) |
| 기록 더블클릭, 보고서의 "결정적 순간" | 그 장면으로 돌아가 1배속으로 다시 본다 |
| `A` / `C` | 자동 카메라 / 도시 전체 보기 |
| `T` | 관찰자 시점 ↔ AI 시점 |
| `M` | 소리 켜기 / 끄기 |
| 지도의 사건 핀, 작은 현장 창 클릭 | 그 현장을 확대해서 본다 |
| 사건 카드·기록·타임라인의 사건 막대 클릭 | 그 사건으로 관찰 대상을 고정한다 |
| 현장의 대원, 부대 목록의 이름 클릭 | 그 대원이 아는 정보, 행동 후보 점수, 인지 범위를 본다 |
| 지도에서 휠·드래그 | 확대/축소, 이동 |
| 상단의 `난이도` 버튼 | 다음 교대의 조건을 정한다 (진행 중인 사건에는 영향 없음) |

**관찰자 시점**에서는 AI가 아직 모르는 사실(발견되지 않은 구조 대상, 숨은 용의자, 미확인 연료 누출, 무전 음영 구역, 신고 내용의 사실 여부, 잘못 신고된 위치)이 함께 보인다. **AI 시점**에서는 AI가 아는 것만 보이고, 무장 사건 현장은 대원이 지금 보고 있는 곳만 밝다.

## 난이도

난이도는 교대가 **시작되기 전에** 정하는 조건이다. 사건이 벌어진 뒤에는 아무것도 바꿀 수 없다. 손잡이 여섯 개(각 1~5, 3이 기준)와 프리셋 네 개가 있다.

| 손잡이 | 바꾸는 것 | 1일 때 → 5일 때 성공률 (나머지는 3) |
|---|---|---|
| 사건 빈도 | 사건 사이 간격, 교대당 사건 수(5~11건), 동시 진행 수(2~5건) | 66% → 48% |
| 사건 심각도 | 규모 분포, 숨은 위험, 부상 악화 속도, 화재 확산 속도 | 78% → 56% |
| 용의자 위협 | 무장 사건 비중, 총격범 비중, 용의자 수·공격성·사격 실력, 숨은 공범, 도주 시점 | 69% → 60% |
| 대원 장비 상태 | 차량 주행 속도, 펌프·용수·구조·의료·방호 장비, 섬광탄 수, 출근 시 체력 | 57% → 71% |
| 신고 신뢰도 | 침착한 신고자 비율, 위치를 틀리게 말할 확률, 허위 신고·비긴급 전화 빈도 | 67% → 64% (아래 참고) |
| 부대 규모 | 출동 부대 수 4 · 5 · 6 · 8 · 10대 | 39% → 73% |

신고 신뢰도는 성공률보다 과정을 바꾼다. 1에서는 허위 신고가 6배 이상 많고(시드 50개에서 40건 대 6건) 실제 사건의 평균 대응 시간이 8초 길다(64초 대 56초). 허위 신고는 확인만 하면 "성공"으로 끝나기 때문에 전체 성공률은 오히려 조금 높게 나온다.

프리셋별 결과(시드 60개):

| 프리셋 | 손잡이 | 사건/교대 | 성공 | 부분 성공 | 대응 지연 | 미해결 | 실패 | 구조율 |
|---|---|---:|---:|---:|---:|---:|---:|---:|
| 쉬움 | 2-2-2-4-4-3 | 6.1 | 76% | 12% | 6% | 2% | 5% | 95% |
| 보통 | 3-3-3-3-3-3 | 7.0 | 68% | 11% | 9% | 3% | 9% | 90% |
| 어려움 | 4-4-4-2-2-3 | 8.7 | 46% | 14% | 15% | 6% | 20% | 80% |
| 극한 | 5-5-5-1-1-3 | 11.1 | 24% | 14% | 17% | 11% | 34% | 67% |

한 현장에는 같은 부서의 부대가 여러 팀 들어갈 수 있다(예: 경찰 2 + 소방 2 + 구급 1). 몇 대가 들어갈지는 배정 AI의 판단과 현장 지휘관의 지원 요청으로 정해지며 상한은 없다. 기본 편성(6대)의 시드 100개 실행에서는 한 사건에 최대 5대가 들어갔다.

## 화면 구성

- **왼쪽**: 진행·종료 사건(유형, 위험도, 배정 부대, 부족한 자원), 출동 부대와 대원의 상태.
- **가운데**: 도시 관제 지도 또는 현장 확대 화면. 통화 중에는 신고 통화창이, 결정적인 순간에는 속보 띠가 뜬다. 오른쪽 아래에는 도시 지도와 진행 중인 다른 현장이 작은 창으로 보인다.
- **오른쪽 위**: 판단 요약(신고 정보 → 상황 분석 → 배정 → 현장 지휘관의 작업 목록 → 문제와 복구) 또는 대원 정보.
- **오른쪽 아래**: AI 관제·무전 기록.
- **아래**: 되감기·배속 제어, 교대 진행 시간, 사건 타임라인, 소리.
- **교대 종료 시**: 사건별 결과와 원인 설명, 결정적 순간 목록이 담긴 보고서.

## 시스템 구조

시뮬레이션(`src/sim`)과 표현(`src/view`, `src/ui`)이 분리되어 있다. `src/sim` 은 DOM, React, Canvas, `Math.random`, `Date` 를 쓰지 않으며(테스트로 강제), 그래서 Node에서 화면 없이 그대로 돈다. 파일별 역할과 규칙은 `CLAUDE.md` 에 있다.

```
src/sim/                      시뮬레이션 (순수 TypeScript)
  engine.ts                   0.2초 고정 틱, 하위 시스템 호출 순서 고정
  difficulty.ts               난이도 손잡이 → 수치 표, 프리셋
  rng.ts, events.ts           시드 난수(fork), 원인 연결 이벤트 기록
  city.ts, resources.ts       도로 그래프·다익스트라·교통량, 부대 명부·차량 이동·병원 이송
  incidents.ts, debrief.ts    사건 생성·종료, 판정·원인 문장·교대 보고서
  dispatch/                   callSystem(신고자·통화), analyst(분석), dispatcher(배정)
  field/                      builders(현장 생성), hazards(세계 규칙), grid(격자·시야·A*),
                              beliefs(믿음), agents(인지·무전), brain(목표 선택),
                              executor(행동 실행), commander(지휘관), sceneManager(현장 틱)
src/view/                     runner(틱·되감기·저장), camera, renderCity, renderScene, icons, audio
src/ui/                       React 패널 (초당 6회 갱신, 캔버스는 매 프레임)
scripts/sweep.ts              헤드리스 실행기
tests/sim.test.ts             자동 테스트
```

### 한 사건의 흐름

1. **사건 발생**: 생성기가 유형·위치·규모·숨은 위험을 조합해 현장(30×20 격자)을 만든다. 이 시점부터 불은 번지고 부상자는 악화된다.
2. **신고**: 신고자는 침착함·공황·상황 파악 미흡·일부만 목격·부정확한 확신 중 한 성향을 갖고, 사건의 일부만 혹은 틀리게 안다. 위치를 옆 교차로로 잘못 말하기도 한다. 접수 AI는 현재 가설에 따라 다음 질문을 고르고, 지혈·가슴 압박·대피 같은 안내를 한다. 신고자가 따르면 현장 상태가 실제로 바뀐다.
3. **분석**: 진술의 키워드와 신뢰도로 유형 확률과 위험도를 계산한다. 입력이 틀리면 결론도 틀린다. 추가 신고나 현장 보고가 오면 다시 평가한다.
4. **배정**: 필요한 능력별로 `적합도 − 도착 시간 − 피로 − 장비 상태 − 예비 전력 손실` 점수가 가장 높은 부대를 보낸다. 가용 부대가 없으면 대기열에 올리고, 긴급도 차이가 크면 다른 사건으로 가던 부대를 돌린다.
5. **이동**: 도로 그래프 위를 달린다. 정체와 통제를 반영하고 교차로마다 경로를 다시 본다. 신고 위치가 틀렸으면 엉뚱한 곳에 먼저 도착한다.
6. **현장**: 먼저 도착한 부대의 선임이 지휘를 맡고 현장 평가를 한 뒤 작업 목록을 만든다. 대원은 인지 → 믿음 갱신 → 목표 선택 → 실행 → 보고 → 재계획을 반복한다.
7. **종료**: 지휘관이 자신의 믿음으로 종료를 선언한다. 판정은 엔진의 진실로 내리므로 지휘관이 놓친 구조 대상도 보고서에 드러난다.

### 설계에서 정한 것들

- **정보 격리**: 대원은 시야 안에서 본 것과 무전·대면으로 들은 것만 안다. 이동 경로도 믿음으로 계획하므로, 잠긴 문이나 잔해는 부딪혀 본 뒤에야 알고 우회·제거·포기 중에서 다시 고른다.
- **실패는 상태에서 나온다**: 연기로 줄어든 시야 때문에 방 구석의 구조 대상을 지나치고, 출동 전부터 상태가 나빴던 펌프가 방수 중에 고장 나고, 통제되지 않은 차로에서 2차 사고가 난다. 난수는 사건 생성과 사격 판정 등 일부에만 쓴다.
- **실내 전술**: 용의자는 바라보는 방향만 본다. 진입조는 가까운 출입구 앞에 모였다가 동시에 들어가고, 기동 부대는 섬광탄으로 용의자를 잠시 무력화한다. 인질이 곁에 있으면 사격을 삼가고, 시한이 지나면 인질이 다친다.
- **AI 구조**: 명세의 Utility AI + Behavior Tree + HTN 조합 대신, 대원은 Utility 목표 선택과 임무별 단계 실행기, 지휘관은 믿음에서 작업을 분해하는 규칙으로 구현했다.
- **종료 보장**: 재시도 보류 시간, 현장별 한계 시간(300~470초), 교대 종료 후 7분 상한으로 모든 사건이 반드시 끝난다.
- **저장**: LocalStorage에 설정, 진행 중인 시드·난이도·틱, 최근 교대 12개의 요약을 저장한다. 새로고침하면 같은 조건을 저장된 틱까지 다시 돌려 복원한다.

## 구현된 기능

- **도시와 자원**: 4개 구역, 소방서 2곳·경찰서 2곳·병원, 도로 그래프와 경로 탐색, 정체·공사·사고 구간 통제, 부대 4~10대.
- **신고 접수**: 신고자 성향 6종, 질문 선택형 통화, 추가 신고 연결, 통화 중 안내, 장난 전화 낌새 감지, 비긴급 전화, 위치 오인과 정정.
- **분석과 배정**: 유형 확률·위험도·필요 자원, 재평가, 대기열, 전환 배정, 현장 지원 요청, 병원 이송 후 재출동.
- **현장 행동**: 현장 평가, 수색, 화재 진압, 급수 연결, 잔해 제거, 문 강제 개방, 구출, 기본·전문 응급 처치, 이송, 구급차 탑승, 교통 통제, 연료 누출 조치, 출입구 봉쇄, 협상, 문 앞 대기와 동시 진입, 섬광탄, 교전, 검거, 목격자 면담, 도로 정리, 동료 구조, 후퇴, 휴식, 장비 교체.
- **문제와 재계획**: 경로 차단 → 우회 또는 제거, 무전 음영 → 이동 후 재보고, 장비 고장 → 교체, 인원 불일치 → 재수색, 수색 실패 → 범위 재조정, 위치 오류 → 재확인 후 재이동.
- **연쇄**: 총을 든 채 달아난 용의자의 재범, 사고 구간 통제가 다른 출동의 경로에 미치는 영향.
- **관찰**: 자동 카메라, 관찰자/AI 시점, 다중 현장 창, 되감기와 결정적 순간, 대원별 행동 후보 점수·믿음 목록·인지 범위, 신고 통화창, 속보, 소리(합성음), 날씨·야간 표현.
- **결과**: 성공·부분 성공·대응 지연·미해결·실패 판정, 원인 연결 이벤트 기록, 사건별 원인 설명이 담긴 종료 보고서.
- **조건**: 시드, 난이도 손잡이 6개와 프리셋 4개.
- **도구**: 헤드리스 실행기, 자동 테스트, 커밋 전 관문.

## 미구현과 알려진 문제

- **경험치·숙련도 변화 없음**: 대원의 경험 수치는 누적되지만 능력치에 반영되지 않고 교대 사이에 저장되지도 않는다.
- **없는 것**: 건물 붕괴·위험물·수난 구조 유형, 다층 건물, 인근 도시 지원, 병원 수용 능력, 예산, 장기 성장.
- **난이도가 유형별로 고르지 않다**: 보통 기준 성공률이 화재 55%, 교통사고 65%, 응급 환자 68%, 무장 73%, 실종·조난 82%다.
- **최초 배정이 보수적이다**: 사건의 43%에서 현장 지휘관이 추가 지원을 요청한다.
- **한계 시간으로 끝나는 사건이 있다**: 보통에서 699건 중 11건(1.6%), 극한에서는 8.6%.
- **정보 격리의 예외 세 가지**: 지휘관은 7초마다 건물 밖에서 화염을 벽 너머로 관찰한다. 이미 발견한 구조 대상이나 용의자가 움직일 때 대원은 그 현재 위치를 따라간다. 스스로 대피한 사람이 안전 구역에 도착하면 현장 무전망에 자동으로 알려진다.
- **지휘관은 측면 진입을 계획하지 않는다**: 등 뒤 기습은 뒷문 쪽에 있던 대원이 우연히 그 길로 들어갈 때만 일어난다.
- **소리는 귀로 확인하지 못했다**: 헤드리스 브라우저에서 오류 없이 동작하는 것만 확인했다. 음색과 음량 균형은 직접 들어 보고 조정해야 한다.
- **데스크톱 전용**: 가로 1280px 이상을 기준으로 만들었고 터치 조작은 지원하지 않는다. 글꼴은 시스템의 한글 글꼴을 쓴다.
- **재현 범위**: 같은 빌드, 같은 브라우저 엔진에서의 재현을 보장한다.
