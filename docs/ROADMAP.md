## 병렬 작업 규칙 (여러 에이전트가 동시에 할 때)

트랙마다 주로 만지는 파일이 다르다. 한 트랙에는 한 번에 한 에이전트만 둔다.

| 트랙 | 소유 파일 | 비고 |
|---|---|---|
| S-균형 | `sim/difficulty.ts`, `sim/incidents.ts`, `sim/field/builders.ts`, `sim/field/hazards.ts` | 수치만 바꾼다. 검증은 `sweep` |
| S-현장AI | `sim/field/commander.ts`, `brain.ts`, `executor.ts`, `agents.ts`, `sceneManager.ts` | 새 임무는 `CLAUDE.md` 확장 표대로 |
| S-관제AI | `sim/dispatch/*` | |
| S-기반 | `sim/engine.ts`, `resources.ts`, `city.ts`, `debrief.ts`, `events.ts` | |
| V-그래픽 | `view/renderCity.ts`, `renderScene.ts`, `icons.ts`, `camera.ts` | 시뮬레이션 결과가 달라지면 안 된다 |
| U-패널 | `ui/*` | |
| T-도구 | `scripts/*`, `tests/*` | |

- `sim/types.ts` 와 `util.ts` 는 공유 파일이다. 필드·코드 **추가만** 하고, 병합 충돌이 나면 양쪽 추가를 모두 살린다.
- S-트랙 둘이 동시에 수치를 바꾸면 결과 분포의 원인을 가릴 수 없다. S-균형은 다른 S-트랙이 끝난 뒤 마지막에 돌린다.
- 각 에이전트는 자기 묶음의 "완료 조건"을 `npm run sweep` 출력으로 증명하고, 전후 수치를 보고에 적는다.

## 다음 작업 묶음

우선순위 순. ID 앞 글자는 트랙이다.

### B1 유형별 난이도 편차 줄이기 — S-균형
- 현재(보통): 화재 성공 45% · 실종 85% · 교통사고 55% · 무장 74%.
- 할 일: 화재는 연기 피해(`hazards.ts` 의 `smoke * 0.42`)와 도착 전 사망을 줄이고, 실종은 대상 악화와 탐지 난도를 올린다. 수치는 가능하면 `difficulty.ts` 의 유형별 기준값으로 옮긴다.
- 완료 조건: 보통에서 네 유형 모두 "성공+대응 지연" 55~75%, 전체 분포는 지금과 ±5%p 이내.

### I1 신고 신뢰도 손잡이에 실효성 주기 — S-관제AI + S-기반
- 현재: 신고 신뢰도 1과 5의 성공률 차이가 1%p 안팎. 잘못된 정보가 현장에서 금방 바로잡히기 때문이다.
- 할 일(안): 신고자가 위치를 틀리게 말하는 경우를 넣는다. 관제가 아는 위치(`reportedNode`)와 실제 위치를 분리하고, 부대가 틀린 곳에 도착하면 "현장 없음" 보고 → 재확인 → 실제 위치로 재이동. 지도 핀도 AI 시점에서는 관제가 아는 위치에 그린다.
- 완료 조건: 신고 신뢰도 1과 5의 평균 대응 시간 차이 10초 이상, 보통(3)의 결과 해시는 변하지 않을 것.

### B2 최초 배정 과소 — S-관제AI
- 현재: 사건의 53%에서 현장이 추가 지원을 요청(`UNDER_DISPATCH`). 위치·유형만 확인되면 1대를 먼저 보내는 구조 때문이다.
- 할 일: 분석 AI의 "예측 위험"을 필요 자원에 더 반영하고, 통화 중 재평가에서 수요가 늘면 즉시 추가 배정하는지 확인.
- 완료 조건: `UNDER_DISPATCH` 35% 이하, 평균 대응 시간 57초에서 +5초 이내, 자원 활용률이 크게 늘지 않을 것.

### B3 한계 시간 종료 없애기 — S-현장AI
- 현재: 675건 중 17건. `npm run sweep -- 100 -v | grep timeout` 으로 대상 시드를 찾고 `--log 시드` 로 본다.
- 알려진 원인 후보: 구급차를 기다리는 중상자, 낡은 믿음으로 남은 작업, 무장 사건의 장기 대치.
- 완료 조건: `timeout` 1% 미만, 새로 생긴 교착 없음.

### F1 대원 경험치 성장과 교대 간 저장 — S-기반 + U-패널
- 현재: `Responder.xpGained` 만 쌓이고 쓰이지 않는다.
- 할 일: 교대 종료 시 경험·숙련 소폭 상승, LocalStorage 저장, 대원 정보 패널과 보고서에 표시. 재현성을 위해 "명부 상태"를 `Sim` 생성자의 입력으로 받는다(시드 + 난이도 + 명부가 같으면 같은 결과).
- 완료 조건: 재현성 테스트에 명부 입력 추가, 저장된 명부로 재실행 시 해시 일치.

### F2 접수 AI의 도착 전 안내 — S-관제AI + S-현장AI
- 통화 중 접수 AI가 신고자에게 지혈·대피·접근 금지 등을 안내하고, 신고자 성향에 따라 실제 현장 상태가 바뀐다(구조 대상 악화 속도 감소, 거동 가능한 사람의 자력 대피 등).
- 완료 조건: 안내가 이벤트로 남고, 안내 유무에 따라 해당 구조 대상의 상태 변화가 달라지는 테스트.

### F3 자원 규모와 편성 — S-기반 + U-패널
- 현재 6대 12명 고정. 사건 하나에 같은 부서 여러 팀이 들어가는 것은 이미 된다(최대 6대까지, 테스트 있음).
- 할 일: `difficulty.ts` 에 "부대 규모" 손잡이(예: 4~10대)를 추가하고 `resources.ts` 의 `UNIT_DEFS` 를 그에 맞춰 생성, 시설별 배치 표시.

### F4 소규모 후속 사건 — S-기반
- 종료된 사건에서 낮은 확률로 파생 사건(재발화, 도주 용의자 재출현, 2차 신고).

### V1 타임라인 되감기 — U-패널 + V-그래픽
- 같은 시드를 원하는 틱까지 다시 돌리는 방식(이미 새로고침 복원에 쓰는 방법). 타임라인 클릭 → 그 시각으로 이동.

### V2 소리 — V-그래픽
- WebAudio 로 무전 잡음, 신고 벨, 사이렌. 외부 음원 파일 없이 합성.

### V3 현장 그래픽 고도화 — V-그래픽
- 대원 걷기·작업 동작, 건물 유형별 타일, 차량·잔해 파괴 표현, 동시 진행 현장 미리보기.

### T1 화면 자동 테스트 — T-도구
- Playwright 로 배속·일시정지·새로고침 복원·보고서 표시를 검사. 지금은 수동 확인만 했다.
