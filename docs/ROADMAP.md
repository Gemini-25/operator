작업 묶음을 끝낼 때마다 이 파일을 고친다. 작업 규칙은 `CLAUDE.md` 에 있다.

## 지금 상태

- 교대 하나가 입력 없이 신고 → 종료 보고서까지 진행된다. 관문 `npm run check` 통과 상태로 푸시되어 있다(테스트 29개).
- 사건 5종(화재·교통사고·실종·무장·응급 환자), 무장 사건의 변형(강도·난동·총격범·인질·장난 전화), 허위·오인 신고, 비긴급 전화, 위치 오인 신고, 통화 중 안내, 연쇄 사건.
- 난이도 손잡이 6개(빈도·심각도·용의자·장비·신고 신뢰도·부대 규모)와 프리셋 4개.
- 관찰 기능: 자동 카메라, 관찰자/AI 시점, 다중 현장 창, 되감기, 결정적 순간, 소리(합성음).
- 기준 수치(난이도 보통, 시드 S0~S99, 사건 699건): 성공 68% · 부분 성공 12% · 대응 지연 9% · 실패 9% · 미해결 2%, 한계 시간 종료 11건(1.6%), 구조율 90%, 평균 대응 60초.
- 유형별 성공률(보통): 화재 55% · 교통사고 65% · 응급 환자 68% · 무장 73% · 실종 82%.
- 프리셋별 성공률(시드 60개): 쉬움 76% · 보통 68% · 어려움 46% · 극한 24%. 손잡이별 수치는 `README.md` "난이도".
- `npm run check` 의 기준 범위(`scripts/sweep.ts` 끝부분)는 보통 난이도에 맞춰져 있다. 균형을 의도적으로 바꾸면 그 범위와 위 수치, `README.md` 를 함께 고친다.

## 병렬 작업 규칙 (여러 에이전트가 동시에 할 때)

트랙마다 주로 만지는 파일이 다르다. 한 트랙에는 한 번에 한 에이전트만 둔다.

| 트랙 | 소유 파일 | 비고 |
|---|---|---|
| S-균형 | `sim/difficulty.ts`, `sim/incidents.ts`, `sim/field/builders.ts`, `sim/field/hazards.ts` | 수치만 바꾼다. 검증은 `sweep` |
| S-현장AI | `sim/field/commander.ts`, `brain.ts`, `executor.ts`, `agents.ts`, `sceneManager.ts` | 새 임무는 `CLAUDE.md` 확장 표대로 |
| S-관제AI | `sim/dispatch/*` | |
| S-기반 | `sim/engine.ts`, `resources.ts`, `city.ts`, `debrief.ts`, `events.ts` | |
| V-그래픽 | `view/renderCity.ts`, `renderScene.ts`, `icons.ts`, `camera.ts` | 시뮬레이션 결과가 달라지면 안 된다 |
| U-패널 | `ui/*` | |
| T-도구 | `scripts/*`, `tests/*` | |

- `sim/types.ts` 와 `util.ts` 는 공유 파일이다. 필드·코드 **추가만** 하고, 병합 충돌이 나면 양쪽 추가를 모두 살린다.
- S-트랙 둘이 동시에 수치를 바꾸면 결과 분포의 원인을 가릴 수 없다. S-균형은 다른 S-트랙이 끝난 뒤 마지막에 돌린다.
- 각 에이전트는 자기 묶음의 "완료 조건"을 `npm run sweep` 출력으로 증명하고, 전후 수치를 보고에 적는다.

## 다음 작업 묶음

우선순위 순. ID 앞 글자는 트랙이다.

### A1 소리 다듬기 — V-그래픽
- 현재: `view/audio.ts` 의 합성음은 헤드리스 브라우저에서 오류 없이 도는 것만 확인했다. 사람이 들어 본 적이 없다.
- 할 일: 직접 들으며 음색·음량·빈도를 조정. 배속이 높을 때 소리가 몰리지 않는지 확인.
- 완료 조건: 사용자가 들어 보고 승인.

### B1 유형별 난이도 편차 줄이기 — S-균형
- 현재(보통): 화재 55% · 교통사고 65% · 응급 환자 68% · 무장 73% · 실종 82%.
- 할 일: 화재는 도착 전 사망과 연소 확대를 줄이고, 실종은 탐지 난도를 올린다. 실종은 지금 "성공 아니면 실패"로만 갈리므로 중간 결과(늦은 발견으로 위중)를 만들 방법도 본다.
- 완료 조건: 보통에서 다섯 유형의 성공률이 60~75% 안에 들고, 전체 분포는 지금과 ±5%p 이내.

### B2 최초 배정 과소 — S-관제AI
- 현재: 사건의 43%에서 현장이 추가 지원을 요청(`UNDER_DISPATCH`).
- 할 일: 분석 AI의 "예측 위험"을 필요 자원에 더 반영.
- 완료 조건: 35% 이하, 평균 대응 시간 +5초 이내.

### B3 한계 시간 종료 줄이기 — S-현장AI
- 현재: 보통 1.6%, 극한 8.6%. `npm run sweep -- 100 -v | grep timeout` 으로 시드를 찾고 `--log 시드` 로 본다.
- 완료 조건: 보통 1% 미만.

### C1 지휘관의 진입 계획 — S-현장AI
- 현재: 진입조는 각자 가장 가까운 출입구에 모인다. 용의자의 시야 밖으로 돌아 들어가는 계획은 없고, 기습은 우연히만 일어난다.
- 할 일: 지휘관이 알고 있는 용의자 위치·방향(믿음)에서 보이지 않는 출입구를 골라 조를 나눠 배치. 방 단위 진입(문 앞 대기 → 섬광탄 → 진입)도 건물 출입구와 같은 방식으로.
- 완료 조건: 기습 발생 빈도가 유의하게 늘고, 인질 사건의 인질 피해가 줄 것.

### C2 새 사건 유형 — S-균형 + S-현장AI
- 건물 붕괴(매몰자 다수, 2차 붕괴), 가스 누출(연기 모델을 유독 가스로, 밸브 차단), 수난 구조. 추가 절차는 `CLAUDE.md` "자주 하는 확장".

### C3 다층 건물과 큰 현장 — S-기반 + V-그래픽
- 현장 격자는 30×20 단층 고정이다. 층 전환(계단)과 층별 화면이 필요하다.

### F1 대원 경험치 성장과 교대 간 저장 — S-기반 + U-패널
- 현재: `Responder.xpGained` 만 쌓이고 쓰이지 않는다.
- 할 일: 교대 종료 시 경험·숙련 소폭 상승, 부상자는 다음 교대 결장, LocalStorage 저장. 재현성을 위해 "명부 상태"를 `Sim` 생성자의 입력으로 받는다.
- 완료 조건: 재현성 테스트에 명부 입력 추가, 저장된 명부로 재실행 시 해시 일치.

### F2 AI가 실패에서 배우기 — S-관제AI
- 종료 보고서의 오판 기록(`MISJUDGE_TYPE`, `UNDERESTIMATE`, `FALSE_ALARM`)으로 분석·배정 기준이 교대 사이에 조금씩 바뀐다. F1 과 같은 방식으로 "조직 기억"을 입력으로 받는다.

### F3 인근 도시 지원 — S-기반
- 과부하(대기열이 60초 이상)일 때 지도 가장자리에서 지원 부대가 들어온다.

### T1 화면 자동 테스트 — T-도구
- Playwright 로 배속·일시정지·되감기·새로고침 복원·보고서를 검사. 지금은 수동 확인만 했다.

### T2 정보 격리 예외 3건 제거 — S-현장AI
- 지휘관의 벽 너머 화염 관찰, 움직이는 대상 추적, 안전 구역 자동 통보(`README.md` 참고).

### P2 (이후)
- 대형 재난, 병원 수용 능력, 예산·시설, 장기 성장.
