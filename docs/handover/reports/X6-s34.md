## 못 한 것

- 단계 5~10(AI 의 대응, 사건의 끝, 판정·보고서·지도, 균형, 선택 규칙, 문서)은 맡은 범위가 아니다. 그래서 c.limitBonus 는 적기만 하고 7번 블록은 아직 읽지 않는다(단계 6). s.ops.utilityAsked 를 넣는 쪽도 없다(단계 5). 시험만 이 칸을 손으로 세운다
- fitFor 의 깔린 동료 조건(rescue ≥ 0.3)은 넣지 않았다. 설계서 §11.2 가 fitFor 를 단계 5·6 으로 묶었다
- §8.1 의 균형 목표는 아직 맞추지 않았다(단계 8). 보통에서 불로 인한 구획 붕괴가 기준선 천장 붕괴의 +36%(49 대 36)라 ±30% 를 넘는다. 전소 0.6%(목표 2~6% — 외부 방어 전), 가스 용기 폭발은 31개 가운데 5개다
- README·CLAUDE·ROADMAP·docs/specs/README.md 는 지시대로 고치지 않았다
- 벽시계 교대당 시간은 기계 부하(평균 7~10) 때문에 믿을 만하게 잴 수 없었다. 대신 프로파일 비율을 적었다

## 설계와 다르게 한 곳

- catOnBlast 의 서명은 (sim, s, I, x, y, radius, dmg, ev, cause) 다. 설계서보다 I(닫힌 사건 거르기)와 ev(causeEv)를 더 받는다. collapseRegion·collapseBuilding·explodeGas·ruptureVessel 은 c(CatState)를 받고 기록 id 를 돌려준다. collapseBuilding 의 인자는 why 가 아니라 폭발 이름 blastWhy 다
- 경계 1칸 안의 사람은 칸 순서가 아니라 목록 순서(구조 대상 → 대원)로 뽑는다. 난수 순서는 구현 메모에 적었다
- 구획 붕괴에서 무너뜨리는 안쪽 벽은 T.WALL 만이다. 칸이 다른 구획에 속해 있었으면 그 구획 목록에서 빼서 옮긴다
- 전체 붕괴 때 대원의 40% '밀려남'은 55~95 대신 25~45 피해로 읽었다. 위치는 선 칸이 걸을 수 없을 때만 옮긴다. 업혀 있던 구조 대상은 8~20
- 창이 바닥이 되면 s.glass 를 지운다. 이것이 없으면 N7 불변 조건 시험이 깨졌다
- 전체 붕괴의 소리에는 건전도가 0.7 아래였던 구획의 구조 조짐 0(down)도 싣는다. 무너진 구획과 전체 붕괴 뒤의 조짐 문구를 따로 정했다(perceiveSigns 의 두 줄)
- 불의 원인 기록 causeEv 가 없으면 I.rootEvent 로 대신한다. 여진의 원인은 sim.disaster.lastEv. 전소 사슬의 근거 기록과 세 기록의 truth 값(s.arrivedAt < 0)은 이 덩어리에서 정했다
- 도로 통제는 node.edges 순서에서 첫 번째로 맞는 구간을 고른다. 통제 기록에는 inc 를 붙인다
- 점화 2(충격)의 문구는 충격 종류와 상관없이 '무너지며 튄 불꽃'이다. 지휘관이 알았는가: 위치를 모르는 신고 조짐(1999)은 치지 않고, 용기는 vessel 조짐 ≥ 2 일 때 안 것으로 본다
- 차량 용기가 터져도 propAt 을 비우지 않는다(잔해가 길을 막는다). CNG·항공유의 불 놓기 범위는 이 덩어리에서 정했다
- collapse/gasblast 의 처음 가스는 1.0 이다(설계서 시작값 0.6). 방치 시험에서 0.6 으로는 구름이 끝내 생기지 않았다
- G4 천장 붕괴 위험 점선은 설계서(단계 4)보다 하나 앞인 단계 3 에서 지웠다. 그것이 읽던 collapseDone 을 단계 3 이 더 채우지 않기 때문이다
- §10-1 가스 시험의 불은 밸브 곁 방(이웃 방)에 둔다. 밸브 방 자체에 두면 센 불이 창을 깨 가스가 빠지고 구름이 생기지 않는다
- mateFact.trapped 는 false 대신 undefined 로 비운다. H1 시험이 toEqual 로 값의 모양을 비교하기 때문이다
- 새 CAT 상수 TOTAL_GRACE·TOTAL_BASE·TOTAL_SLOPE·TOTAL_NOW·GASBLAST_INIT 를 더했다. 설계서 본문의 숫자에 이름만 붙인 것이다

## 알려진 문제 — 다음 작업자가 알아야 할 것

- AI 의 대응(철수·진입 금지·외부 방어 — 단계 5)이 없어서 어려움·극한에서 순직과 한계 시간이 크게 늘었다. 극한 순직 1 → 60/60교대, 한계 12 → 57. 어려움 순직 0 → 22, 한계 3 → 11. 보통도 순직 0 → 2 로, H1 상한(교대당 0.02) 바깥이다. deaths.ts 로 본 순직은 주로 전체 붕괴에 깔린 대원이 구출되지 못한 채 연기·불로 숨진 것이다. 설계서가 말한 길이고 버그는 아닌 것으로 판단했다. 보통의 관문은 통과한다
- 한계 시간으로 닫힌 사건에 남은 일은 무너진 건물의 진압·잔불 정리(전체 붕괴 잔해 속 불씨)와 깔린 동료 구출이다. 단계 6 의 한계 시간 보탬(c.limitBonus + ops.limitBonus — 이미 적고 있다), 잔해 수색 국면, 외부 확인 종료가 받아야 한다
- 보통에서 불로 인한 구획 붕괴가 기준선보다 36% 많다. 단계 8 의 K_BURN·K_HEAT 로 맞춘다
- 강제 fire/plane(한계 3 → 5)·traffic/train(1 → 3)·traffic/pileup(3 → 4)은 NO_STRUCT 인데도 한계 시간이 늘었다. 지운 예전 규칙의 s.rng 순서, 항공유 폭발, 같은 교대의 평소 사건에서 온 차이로 보인다. 단계 8 에서 다시 잰다
- 다음 작업자(단계 5)가 고칠 시험: tests/catastrophe.test.ts 의 교대 묶음 '아직 아무도 판단하지 않는다'(조짐·철수 기록 0, s.ops 없음)를 뒤집는다. checkHonest·x6Count·X6_BOOM 도움 함수는 그대로 쓸 수 있다. 사건 소리의 event 사실은 SIGN_BASE.event + n, value.what·region 으로 지휘 규칙이 믿음에서 읽으면 된다
- 단계 3 커밋의 check 에서 persistence.test.ts beforeAll 이 부하로 시간 초과했다(혼자 돌리면 통과). 공유 기계에서는 시간 초과만으로 실패할 수 있다
- I2 단계 5 가 placeUsable 로 바꿀 자리(pickPlace·createIncident·은신처 후보의 건물 제외)는 X6 단계 7 의 몫이라 아직 넣지 않았다
