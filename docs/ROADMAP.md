# 로드맵과 인계 상태

작업 묶음을 끝낼 때마다 이 파일을 고친다. 작업 규칙은 `CLAUDE.md` 에 있다.

## 지금 상태

- 교대 하나가 입력 없이 신고 → 종료 보고서까지 진행된다. 관문 `npm run check` 통과 상태로 푸시되어 있다(테스트 34개).
- 사건 7종(화재[단층·2층]·교통사고·실종·무장·응급 환자·건물 붕괴·가스 누출), 무장 사건의 변형(강도·난동·총격범·인질·장난 전화), 허위·오인 신고, 비긴급 전화, 위치 오인 신고, 통화 중 안내, 연쇄 사건, 인근 도시 지원.
- 난이도 손잡이 6개(빈도·심각도·용의자·장비·신고 신뢰도·부대 규모)와 프리셋 4개.
- 관찰 기능: 자동 카메라, 현장 확대·이동, 관찰자/AI 시점, 다중 현장 창, 되감기, 결정적 순간, 소리(합성음).
- 그래픽: 현장(`view/scene/*`), 도시 지도(`view/city/staticCity.ts`), UI(`ui/styles.css`)를 모두 다시 만들었다.
- 기준 수치(난이도 보통, 시드 S0~S99, 사건 700건): 성공 74% · 부분 성공 12% · 대응 지연 6% · 실패 7% · 미해결 1%, 한계 시간 종료 6건(0.9%), 구조율 92%, 평균 대응 56초.
- 유형별 성공률(보통): 화재 63% · 교통사고 67% · 건물 붕괴 68% · 가스 누출 72% · 실종 77% · 응급 환자 80% · 무장 87%.
- 프리셋별 성공률(시드 60개): 쉬움 82% · 보통 74% · 어려움 55% · 극한 31%. 손잡이별 수치는 `README.md` "난이도".
- `npm run check` 의 기준 범위(`scripts/sweep.ts` 끝부분: 성공+대응 지연 65~90%, 실패+미해결 3~25%, 한계 시간 종료 4% 이하)는 보통 난이도에 맞춰져 있다. 균형을 의도적으로 바꾸면 그 범위와 위 수치, `README.md` 를 함께 고친다.

## 진행 중

사용자 요청: "현장 배치 다양화 · 교전과 진입 · 보는 연출 · 빈 곳 채우기". 아래 순서로 진행한다. 묶음 하나가 끝날 때마다 `npm run check` → 커밋 → 푸시.

- [x] L1 현장 배치 다양화 — `field/plans.ts`: 건물 틀 네 종(복도형·방 연결형·홀형·2층)과 크기 변화를 화재·붕괴·가스 누출이 함께 쓴다. 무장 사건 장소 네 종(편의점·은행·사무실·창고, `builders.armedVenue`), 주택 배치 두 종. 현장 생성 도구는 `field/kit.ts` 로 분리
- [x] E1 교전과 진입 — 용의자: 사격을 받으면 대원에게 보이지 않는 엄폐 위치로 옮기고, 인질범은 진입이 시작되면 인질을 끌고 먼 방으로 물러나며, 총격범은 대원이 안 보이는 동안 다른 사람을 찾아다니며 쏜다(`hazards.tickHostiles`). 진입조: 경찰이 4명 이상이면 두 문으로 나뉘고(`Scene.entryExit2`), 닫힌 문 뒤의 방은 문 앞에 모였다가 섬광탄을 던져 넣고 들어간다(`executor.roomDoorFor`). 섬광탄은 벽을 넘지 못하고, 섬광탄 없이 방에 들어가면 놀란 인질범이 인질을 쏠 수 있다(`hazards.panicShot`). 가구를 낀 용의자는 맞히기 어렵다
- [x] W1 보는 연출 — 현장 카메라가 벌어지는 일을 따라 자동으로 확대(`camera.frameAction`, 휠로 직접 조작하면 멈추고 두 번 누르면 다시 따라간다), 관찰 중인 현장의 총격·폭발·진입 때 1배속으로 자동 감속(`runner.drama`), 교대 종료 뒤 주요 장면 이어 보기(`App.reelMoments`). 모두 시점·배속만 바꾸며, 브라우저에서 감속·되감기 뒤의 기록 해시가 헤드리스 실행과 같음을 확인
- [ ] F1 빈 곳 채우기 — 가스 누출의 경찰 역할(주변 통제), 다수 사상자 사고와 병원 인계 지연, 붕괴 현장의 탐지 장비, 최초 배정 과소 줄이기, 수난 구조 유형

## 병렬 작업 규칙 (여러 에이전트가 동시에 할 때)

트랙마다 주로 만지는 파일이 다르다. 한 트랙에는 한 번에 한 에이전트만 둔다.

| 트랙 | 소유 파일 | 비고 |
|---|---|---|
| S-균형 | `sim/difficulty.ts`, `sim/incidents.ts`, `sim/field/builders.ts`, `sim/field/hazards.ts` | 수치만 바꾼다. 검증은 `sweep` |
| S-현장AI | `sim/field/commander.ts`, `brain.ts`, `executor.ts`, `agents.ts`, `sceneManager.ts` | 새 임무는 `CLAUDE.md` 확장 표대로 |
| S-관제AI | `sim/dispatch/*` | |
| S-기반 | `sim/engine.ts`, `resources.ts`, `city.ts`, `debrief.ts`, `events.ts` | |
| V-그래픽 | `view/renderCity.ts`, `renderScene.ts`, `view/scene/*`, `view/city/*`, `icons.ts`, `camera.ts` | 시뮬레이션 결과가 달라지면 안 된다 |
| U-패널 | `ui/*` | |
| T-도구 | `scripts/*`, `tests/*` | |

- `sim/types.ts` 와 `util.ts` 는 공유 파일이다. 필드·코드 **추가만** 하고, 병합 충돌이 나면 양쪽 추가를 모두 살린다.
- S-트랙 둘이 동시에 수치를 바꾸면 결과 분포의 원인을 가릴 수 없다. S-균형은 다른 S-트랙이 끝난 뒤 마지막에 돌린다.
- 각 에이전트는 자기 묶음의 "완료 조건"을 `npm run sweep` 출력으로 증명하고, 전후 수치를 보고에 적는다.

## 다음 작업 묶음

우선순위 순. ID 앞 글자는 트랙이다.

### A1 소리 다듬기 — V-그래픽
- 현재: `view/audio.ts` 의 합성음은 헤드리스 브라우저에서 오류 없이 도는 것만 확인했다. 사람이 들어 본 적이 없다.
- 할 일: 직접 들으며 음색·음량·빈도를 조정. 배속이 높을 때 소리가 몰리지 않는지 확인.
- 완료 조건: 사용자가 들어 보고 승인.

### B1 유형별 난이도 편차 줄이기 — S-균형
- 현재(보통): 화재 63% · 교통사고 67% · 건물 붕괴 68% · 가스 누출 72% · 실종 77% · 응급 환자 80% · 무장 87%.
- 할 일: 무장 사건이 쉬워졌다(인근 도시 지원과 진입 계획의 영향). 용의자의 반응이나 진입 뒤 교전을 손본다. 실종은 "성공 아니면 실패"로만 갈리므로 중간 결과(늦은 발견으로 위중)를 만들 방법을 본다.
- 완료 조건: 보통에서 일곱 유형의 성공률이 62~80% 안에 들고, 전체 분포는 지금과 ±5%p 이내.

### B2 최초 배정 과소 — S-관제AI
- 현재: 사건의 40%에서 현장이 추가 지원을 요청(`UNDER_DISPATCH`).
- 할 일: 분석 AI의 "예측 위험"을 필요 자원에 더 반영.
- 완료 조건: 33% 이하, 평균 대응 시간 +5초 이내.

### B3 높은 난이도의 한계 시간 종료 — S-현장AI
- 현재: 보통 0.9%, 어려움 2.5%, 극한 4.5%. `npm run sweep -- 100 --diff extreme -v | grep timeout` 으로 시드를 찾고 `--log 시드` 로 본다.
- 완료 조건: 극한 3% 미만.

### C4 새 유형의 깊이 — S-현장AI + S-균형
- 건물 붕괴: 지금은 균열부 보강과 잔해 제거뿐이다. 탐색 장비(청음·탐지견), 구역별 안전 판정, 장시간 매몰자 상태 변화를 넣을 수 있다.
- 가스 누출: 경찰의 주변 통제·대피 안내(지금은 경찰이 할 일이 없다), 환기, 바람 방향.
- 2층 건물: 화재에만 있다. 붕괴·가스 누출·무장 사건으로 넓히고, 3층 이상과 창문 구조(사다리)를 본다.
- 수난 구조 유형은 아직 없다.

### C5 방 단위 진입 계획 — S-현장AI
- 현재: 지휘관은 건물 출입구만 고른다(`commander.planEntry`). 건물 안에서는 진입조가 용의자에게 곧장 간다.
- 할 일: 방마다 문 앞 대기 → 섬광탄 → 진입을 되풀이하고, 조를 나눠 두 문으로 동시에 들어가는 계획.

### F1 대원 경험치 성장과 교대 간 저장 — S-기반 + U-패널
- 현재: `Responder.xpGained` 만 쌓이고 쓰이지 않는다.
- 할 일: 교대 종료 시 경험·숙련 소폭 상승, 부상자는 다음 교대 결장, LocalStorage 저장. 재현성을 위해 "명부 상태"를 `Sim` 생성자의 입력으로 받는다.
- 완료 조건: 재현성 테스트에 명부 입력 추가, 저장된 명부로 재실행 시 해시 일치.

### F2 AI가 실패에서 배우기 — S-관제AI
- 종료 보고서의 오판 기록(`MISJUDGE_TYPE`, `UNDERESTIMATE`, `FALSE_ALARM`)으로 분석·배정 기준이 교대 사이에 조금씩 바뀐다. F1 과 같은 방식으로 "조직 기억"을 입력으로 받는다.

### T1 화면 자동 테스트 — T-도구
- Playwright 로 배속·일시정지·되감기·새로고침 복원·보고서를 검사. 지금은 수동 확인만 했다.

### T2 정보 격리 예외 3건 제거 — S-현장AI
- 지휘관의 벽 너머 화염 관찰, 움직이는 대상 추적, 안전 구역 자동 통보(`README.md` 참고).

### P2 (이후)
- 대형 재난, 병원 수용 능력, 예산·시설, 장기 성장.
