# U1 — 지도 표식을 그림 기호로, 화면 다듬기

공통 규칙은 `docs/specs/README.md`. 브랜치 `wf/ui`, 개발 서버 포트 **5206**.

사용자의 말: "동그란 표식하고 부대 표시는 마크 같은 걸로 해. 글자로 하지 말고. UI 좀 이쁘게."

**자기 파일**: `src/view/marks.ts`(새로), `src/ui/Mark.tsx`(새로), `src/ui/MapLegend.tsx`(새로), `src/view/city/tokens.ts`, `src/ui/panels.tsx`, `src/ui/App.tsx`, `src/ui/styles.css`, `src/view/icons.ts`.
**공용 파일 수정**: `src/view/renderCity.ts` — 부대 표식·시설 배지·사건 핀·이름표를 그리는 곳만. "도로 상태" 반복문(혼잡·통제)과 `describeAt` 은 T1(교통)이 고치므로 **건드리지 않는다.**
**건드리지 않는다**: `src/sim/*` 전부(화면만 고친다 — `npx tsx scripts/sweep.ts 12` 의 결과가 한 글자도 달라지면 안 된다), `view/renderScene.ts`, `view/scene/*`(현장 그림은 지금 그대로 둔다는 것이 사용자의 결정이다), `view/city/staticCity.ts`·`places.ts`.

다른 묶음이 `panels.tsx` 에 작은 조각을 더하고(`TopBar` 의 교통 요약 한 줄, 사건 카드의 '대형' 딱지, 보고서의 타일), `styles.css` 끝에 자기 블록을 붙인다. 합칠 때 부딪히지 않게: **컴포넌트의 이름·props·파일 안의 순서를 바꾸지 않는다. `styles.css` 는 있는 규칙을 고치되 통째로 다시 쓰거나 순서를 뒤섞지 않는다.** 다른 코드와 임시 스크립트가 붙잡는 클래스 이름(`.units-wrap`, `.unit`, `.diff-chip`, `.disaster-row .chip`, `.modal`, `.ticker`, `.panel-section`)은 유지한다.

## 1. 그림 기호 (`src/view/marks.ts`)

`view/icons.ts` 의 `ICON_PATH` 와 같은 방식: **24×24 좌표의 SVG 경로 문자열 하나**를 캔버스(`Path2D`)와 React(`<svg><path>`) 양쪽에서 쓴다.

```ts
export const UNIT_MARK: Record<UnitKind, string>;           // 종류별 기호
export const FACILITY_MARK: Record<string, string>;         // fireStation · police · hospital · public · heliport · harbor
export const STATE_MARK: Record<string, string>;            // transport(십자) 등 상태에 붙는 작은 기호가 필요하면
export function drawMark(ctx: CanvasRenderingContext2D, d: string, x: number, y: number, size: number, color: string): void;   // 가운데 정렬, evenodd 채움, Path2D 캐시
```

`src/ui/Mark.tsx`: `<Mark d={UNIT_MARK[u.kind]} size={14} color="#fff" />`, 그리고 지도와 같은 모양의 둥근 표식 `<Token field kind size state />`(SVG: 분야색 원 + 흰 기호 + 상태 테).

기호 열두 개 — **한 색으로 채운 실루엣**, 가는 선에 기대지 않는다(지도에서 지름 10~12 화소로 그려진다). 같은 분야 안에서는 **윤곽부터 달라야** 한다:

| 종류 | 기호 | 분야(바탕색) |
|---|---|---|
| `patrol` 순찰차 | 방패 안에 별 | 경찰 |
| `tactical` 기동 순찰 | 방패에 갈매기표 둘(계급장 모양) | 경찰 |
| `swat` 특공대 | 조준선(원 + 십자) | 특수 |
| `eod` 폭발물 처리반 | 둥근 폭탄과 불꽃 튀는 심지 | 특수 |
| `engine` 진압 펌프차 | 불꽃 | 소방 |
| `ladder` 사다리차 | 비스듬한 사다리 | 소방 |
| `rescue` 구조 공작차 | 교차한 도끼와 갈고리(또는 스패너) | 구조·구급 |
| `als` 전문 구급 | 굵은 십자 + 심전도 꺾은선 | 구조·구급 |
| `bls` 일반 구급 | 굵은 십자 | 구조·구급 |
| `hazmat` 화학 구조대 | 마름모 안의 물방울(위험물 표지) | 특수 |
| `heli` 구조 헬기 | 위에서 본 동체 + 회전 날개 | 특수 |
| `boat` 구조정 | 닻 | 특수 |

시설: 소방서 = 불꽃이 든 집 모양, 경찰서 = 방패, 병원 = 십자, 시청 등 공공 = 기둥 건물, 항공대 = 원 안의 H 대신 **헬기 착륙장 표시(원 + 헬기 실루엣)**, 해양구조대 = 닻. 달아나는 차량 = 차 앞모습 + 속도선(지금의 `!` 글자를 대신한다).

**만드는 방법**: 경로를 쓴 뒤 반드시 **견본표를 찍어 눈으로 본다** — 열두 기호를 분야색 원 위에 지름 10·12·16·24 화소로, 어두운 지도 바탕색(`#1a222b`) 위에 늘어놓은 한 장(독립된 HTML + Playwright 스크린샷, `deviceScaleFactor: 2`). 10~12 화소에서 서로 헷갈리는 쌍이 없을 때까지 고친다(특히 `als`↔`bls`, `patrol`↔`tactical`, `engine`↔`hazmat`). 견본표 스크립트와 그림은 저장소 밖에 두고, 마지막 그림의 경로를 보고에 적는다.

## 2. 지도의 표식 (`view/city/tokens.ts`, `renderCity.ts`)

- **글자를 없앤다**: `KIND_GLYPH`(한 글자)와 `ctx.fillText` 로 종류를 쓰는 부분을 지우고 `drawMark(UNIT_MARK[kind])` 로. 기호는 돌 지름의 62% 안팎, 흰색, 아래에 옅은 그림자.
- **같은 종류를 가리는 번호**도 숫자 대신 **점**: 돌의 아래쪽 테두리를 따라 작은 흰 점 n개(1~5). 호출부호 이름표(확대하거나 관찰 중일 때 뜨는 것)는 글자 그대로 둔다 — 그것은 이름이다.
- 바둑돌의 느낌(밝은 하이라이트, 어두운 가장자리, 아래 그림자)과 상태 테(출동 = 도는 점선, 현장 = 노란 실선, 이송 = 초록 + 십자, 복귀 = 반투명)는 유지하되 다듬는다: 테의 굵기를 돌 크기에 비례하게, 이송의 `+` 는 `drawMark` 로.
- 헬기의 회전 날개 호, 구조정의 물결은 유지.
- 축소 창(`mini`)은 지금처럼 색 점만.
- **시설 배지**: 지금의 `119`·`112`·`+` 글자 배지를 기호로 — 둥근 모서리의 **네모**(시설) 안에 `FACILITY_MARK`. 모양으로 구분한다: 네모 = 시설, 원 = 부대, 물방울 핀 = 사건. 대기 중인 부대 수(지금 시설 이름 옆의 동그란 숫자)는 숫자 그대로 둔다(수량이다).
- **이름표 겹침**: 도시 전체 보기에서 시설 이름표끼리, 시설 이름표와 건물 이름이 겹치는 곳을 줄인다(스크린샷에서 '서부119안전센터 ②'·'중부경찰서 … 시청' 근처). 이름표를 배지의 오른쪽·왼쪽·위·아래 가운데 빈 쪽에 두는 간단한 충돌 회피(이미 놓인 상자들과 겹치지 않는 첫 자리)면 충분하다. 매 프레임 계산이 무겁지 않게(시설은 14곳).
- 달아나는 차량: 붉은 돌 + 차량 기호 + 퍼지는 고리(글자 `!` 제거).
- 사건 핀은 지금 모양을 유지하되 테·그림자의 굵기와 색을 표식과 한 가족으로 맞춘다.
- 클릭 판정(`hitCity`)이 돌의 크기와 맞는지 확인한다.

## 3. 부대 목록·사건 목록 (`ui/panels.tsx`)

- 부대 줄(`UnitRow`) 맨 앞에 지도와 **같은** 둥근 표식 `<Token>`(지름 22). 분야 묶음의 제목 옆에도 작은 기호. 상태는 글자 + 작은 색 점(대기 회색, 출동 분야색 점멸, 현장 노랑, 이송 초록, 복귀 옅게). 대원 이름 칩은 유지.
- 사건 카드: 유형 아이콘(지금의 `ICON_PATH`)을 둥근 바탕 위에, 위험도에 따라 왼쪽 띠의 색, 상태 알약, 경과 시간은 고정폭 숫자(`font-variant-numeric: tabular-nums`).
- 지도 범례 `MapLegend`(지도 왼쪽 아래의 접히는 상자, 기본은 접힘 — `범례` 버튼): 분야색 넷, 기호 열두 개와 이름, 상태 테 넷, 모양(네모 = 시설, 원 = 부대, 핀 = 사건), 도로 색(노랑 `#f2c94c` 서행 · 주황 `#ff9f43` 정체 · 빨강 `#ff5d5d` 극심 · 붉은 점선 통제). 표시 방식의 하나일 뿐이다(관찰 전용 원칙에 맞다). 접힘 상태는 `localStorage`.

## 4. 화면 전체 다듬기 ("이쁘게")

먼저 지금 화면을 1440×900 과 1920×1080 으로 찍어(교대 시작 직후, 사건 3~4건이 돌 때, 현장 확대, 난이도 창, 보고서 창) **눈에 걸리는 곳을 목록으로 적고** 그것을 고친다. 구조(왼쪽 사건·부대 / 가운데 지도 / 오른쪽 판단·기록 / 아래 시간)와 담긴 정보는 그대로 둔다. 방향:

- **위계**: 한 화면에서 가장 먼저 읽혀야 하는 것은 지도와 진행 중인 사건이다. 패널의 제목·보조 글자는 한 단계 낮춘다(크기·명도). 글자 크기는 다섯 단계(11·12·13·15·18)로 정리하고, 숫자(시계·경과 시간·확률)는 고정폭 숫자.
- **면과 선**: 패널마다 테두리를 두르기보다 배경 명도의 차이와 넉넉한 간격으로 나눈다. 테두리는 1px 의 옅은 선 하나로 통일, 모서리 반지름은 두 가지(작은 것 6, 큰 것 10)만.
- **색**: 바탕은 지금의 짙은 남청 계열 유지. 강조색 하나(지금의 청록)는 "지금 조작할 수 있는 것·현재 시각"에만. 분야색 넷은 부대에만, 결과색(성공 초록·부분 노랑·실패 빨강)은 결과에만 쓴다 — 장식으로 섞어 쓰지 않는다.
- **밀도**: 부대 목록이 가장 빽빽하다. 줄 높이·여백을 맞추고 대원 이름이 잘리지 않게. 오른쪽 "판단 요약"은 줄 간격과 구획(①②③)의 머리를 정돈한다. 기록(로그)은 역할별 색 점 + 본문, 시각은 옅게.
- **지도 위 덧글**: 지도 아래의 도움말 줄, 왼쪽 위의 시점 표시, 오른쪽 위의 버튼 줄을 같은 모양의 반투명 알약으로 통일.
- **움직임**: 새 사건 카드가 들어올 때, 상태가 바뀔 때의 짧은 전환(150~200ms)만. 계속 깜박이는 것은 "지금 급한 것"(신고 접수 중, 위중 환자)에만.
- 성능: 넓은 면에 `backdrop-filter`·큰 `box-shadow` 를 쓰지 않는다(캔버스가 매 프레임 그려지는 화면이다). 15배속에서 프레임이 떨어지지 않는지 상단의 FPS 로 확인한다.
- 접근성: 본문 글자의 명암비 4.5:1 이상, 색만으로 구분하는 곳에는 모양이나 글자도 함께.

하지 않는 것: AI 에게 명령하는 입력을 만들지 않는다(버튼은 시간·시점·표시 방식·교대 시작 전 조건뿐). 배치를 통째로 바꾸지 않는다. 글꼴 파일을 내려받지 않는다(시스템 글꼴 묶음 유지). 현장 화면의 그림을 바꾸지 않는다.

## 5. 완료 조건

- 지도·부대 목록·범례 어디에도 **종류를 나타내는 한글 한 글자**가 남아 있지 않다(`grep -n "KIND_GLYPH"` 0건).
- 견본표에서 열두 기호가 12화소에서 서로 구분된다(직접 본 그림으로 판단하고 보고에 경로를 적는다).
- 스크린샷으로 확인: ① 도시 전체(부대 여럿이 움직일 때) ② 확대(zoom 4 이상, 대기 중인 돌이 시설 옆에 늘어선 모습) ③ 부대 목록 ④ 범례 펼침 ⑤ 현장 확대 화면에서 좌우 패널 ⑥ 난이도 창 ⑦ 보고서 창 — 1440×900 과 1920×1080. 글자 잘림·겹침·넘침 없음. 콘솔 오류 0건(교대 하나를 끝까지: `scratchpad/full.cjs` 를 복사해 포트만 바꿔 쓴다).
- `npx tsc --noEmit`, `npx vitest run tests/ext.test.ts` 통과. `npx tsx scripts/sweep.ts 12` 의 `outcomes` 줄이 작업 전과 같다(화면만 고쳤다).
- 보고에 "고치기 전 → 고친 뒤" 스크린샷 경로를 짝지어 적는다.
