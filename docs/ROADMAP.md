# 로드맵과 인계 상태

작업 묶음을 끝낼 때마다 이 파일을 고친다. 작업 규칙은 `CLAUDE.md` 에 있다.

## 지금 상태

- 교대 하나가 입력 없이 신고 → 종료 보고서까지 진행된다. 관문 `npm run check` 통과 상태로 푸시되어 있다(테스트 42개).
- 도시: 설계도(`sim/cityPlan.ts`)로 만든 격자가 아닌 도시 하나. 교차로 78곳·도로 50개(고속화·간선·일반·이면), 강·바다·산·철길, 동네 18곳, 건물과 터 약 1,240곳(종류 69가지). 사건은 유형에 맞는 건물에서 일어난다.
- 출동 조직: 경찰·소방·구조·구급·특수 네 분야 12~20팀(보통 17팀). 특공대·구조 헬기·화학 구조대·구조정·폭발물 처리반·사다리차. 소방서 4·경찰서 3·병원 2·소방항공대·해양구조대.
- 사건 8종(화재·교통사고·실종·무장·응급 환자·건물 붕괴·가스 누출·수난 사고)과 그 안의 시나리오(버스 추돌·쓰러진 나무·맨홀 추락·승강기 갇힘·강도·난동·총격·인질극·가정 폭력·침입 절도·장난 전화), 허위·오인 신고, 비긴급 전화, 위치 오인 신고, 통화 중 안내, 연쇄 사건, 인근 도시 지원, 응급실 인계 대기.
- 난이도 손잡이 6개(빈도·심각도·용의자·장비·신고 신뢰도·부대 규모)와 프리셋 4개.
- 관찰 기능: 자동 카메라, 단계별 이름표와 마우스 정보창, 현장 자동 확대, 결정적 순간의 자동 감속, 주요 장면 이어 보기, 관찰자/AI 시점, 다중 현장 창, 되감기, 소리(합성음).
- 기준 수치(난이도 보통, 시드 S0~S59, 사건 828건, 교대당 13.8건): 성공 77% · 부분 성공 12% · 대응 지연 4% · 실패 6% · 미해결 1%, 한계 시간 종료 1건(0.1%), 구조율 92%, 평균 대응 48초, 현장의 추가 지원 요청 30%.
- 유형별 성공률(보통): 화재 63% · 교통사고 72% · 응급 환자 75% · 수난 사고 76% · 실종 85% · 가스 누출 85% · 건물 붕괴 85% · 무장 89%.
- 프리셋별 성공률(시드 60개): 쉬움 84% · 보통 77% · 어려움 66% · 극한 36%. 손잡이별 수치는 `README.md` "난이도".
- `npm run check` 의 기준 범위(`scripts/sweep.ts` 끝부분: 성공+대응 지연 65~90%, 실패+미해결 3~25%, 한계 시간 종료 4% 이하)는 보통 난이도에 맞춰져 있다. 균형을 의도적으로 바꾸면 그 범위와 위 수치, `README.md` 를 함께 고친다.

## 병렬 작업 규칙 (여러 에이전트가 동시에 할 때)

트랙마다 주로 만지는 파일이 다르다. 한 트랙에는 한 번에 한 에이전트만 둔다.

| 트랙 | 소유 파일 | 비고 |
|---|---|---|
| S-균형 | `sim/difficulty.ts`, `sim/incidents.ts`, `sim/field/builders.ts`, `sim/field/hazards.ts` | 수치만 바꾼다. 검증은 `sweep` |
| S-현장AI | `sim/field/commander.ts`, `brain.ts`, `executor.ts`, `agents.ts`, `sceneManager.ts` | 새 임무는 `CLAUDE.md` 확장 표대로 |
| S-관제AI | `sim/dispatch/*` | |
| S-기반 | `sim/engine.ts`, `resources.ts`, `city.ts`, `debrief.ts`, `events.ts` | |
| V-그래픽 | `view/renderCity.ts`, `renderScene.ts`, `view/scene/*`, `view/city/*`, `icons.ts`, `camera.ts` | 시뮬레이션 결과가 달라지면 안 된다 |
| U-패널 | `ui/*` | |
| T-도구 | `scripts/*`, `tests/*` | |

- `sim/types.ts` 와 `util.ts` 는 공유 파일이다. 필드·코드 **추가만** 하고, 병합 충돌이 나면 양쪽 추가를 모두 살린다.
- S-트랙 둘이 동시에 수치를 바꾸면 결과 분포의 원인을 가릴 수 없다. S-균형은 다른 S-트랙이 끝난 뒤 마지막에 돌린다.
- 각 에이전트는 자기 묶음의 "완료 조건"을 `npm run sweep` 출력으로 증명하고, 전후 수치를 보고에 적는다.

## 다음 작업 묶음

우선순위 순. ID 앞 글자는 트랙이다.

### A1 소리 다듬기 — V-그래픽
- 현재: `view/audio.ts` 의 합성음은 헤드리스 브라우저에서 오류 없이 도는 것만 확인했다. 사람이 들어 본 적이 없다.
- 할 일: 직접 들으며 음색·음량·빈도를 조정. 배속이 높을 때 소리가 몰리지 않는지 확인.
- 완료 조건: 사용자가 들어 보고 승인.

### M1 지도의 다음 단계 — S-기반 + V-그래픽
- 현재: 건물마다 종류·이름·주소가 있고 사건이 그 건물에서 난다. 골목은 지도와 주소에만 있고 차량은 큰길가에 선다. 현장은 건물 종류만 따르고 지도의 건물 외곽과는 무관하게 30×20 격자에 만든다. 소방서·병원 같은 공공 시설에서는 사건이 나지 않는다.
- 할 일: (1) 사건이 끝난 건물에 흔적 남기기(탄 지붕, 통제선)와 같은 건물의 재발. (2) 골목을 도로망에 넣어 차량이 건물 앞까지 들어가기(폭이 좁아 느리다). (3) 지도의 건물 외곽·층수와 현장 평면 맞추기. (4) 학교·병원·공항 터미널 같은 큰 시설의 전용 현장. (5) 지도 편집 화면.
- 완료 조건: 항목별로 따로 잡는다. 지도를 바꾸면 사건 위치가 달라지므로 매번 `sweep -- 100` 으로 다시 잰다.

### B1 유형별 난이도 편차 줄이기 — S-균형
- 현재(보통): 화재 57% · 가스 누출 67% · 수난 사고 70% · 교통사고 71% · 건물 붕괴 77% · 응급 환자 80% · 무장 86% · 실종 87%.
- 할 일: 화재가 가장 어렵다. 방 연결형 평면의 화재가 특히 어렵다(단독주택에서 실패가 많았다). 무장 사건은 편의점·식당처럼 단순한 장소가 늘면서 쉬워졌다. 실종은 "성공 아니면 실패"로만 갈린다.
- 완료 조건: 보통에서 여덟 유형의 성공률이 62~84% 안에 들고, 전체 분포는 지금과 ±5%p 이내.

### B3 높은 난이도의 한계 시간 종료 — S-현장AI
- 현재: 보통 0.3%, 어려움 1.3%, 극한 2.1%(여기에 "출동 없음" 종료 1.0%). `npm run sweep -- 100 --diff extreme -v | grep timeout` 으로 시드를 찾고 `--log 시드` 로 본다.
- 완료 조건: 극한 2% 미만.

### C4 새 유형의 깊이 — S-현장AI + S-균형
- 건물 붕괴: 탐지는 지금 구조대의 발견 보정뿐이다(`agents.detectRadius`). 청음·탐지견 같은 행동, 구역별 안전 판정, 장시간 매몰자 상태 변화를 넣을 수 있다.
- 가스 누출: 경찰의 출입구 통제는 들어갔다. 환기, 바람 방향, 주변 건물 대피 안내는 없다.
- 수난 사고: 물가에서 줄을 던지는 구조뿐이다. 보트·잠수, 하류에서 기다리는 차단선, 급류 등급을 넣을 수 있다.
- 다수 사상자 사고: 버스 추돌 하나뿐이다. 현장 분류소(중증도 분류 뒤 이송 순서 결정)와 병상 수 한계를 넣을 수 있다. 지금 병원은 인계 대기 시간만 있다(`resources.ts`).
- 2층 건물: 화재·붕괴·가스 누출에 있다. 무장 사건으로 넓히고, 3층 이상과 창문 구조(사다리)를 본다.

### C5 건물 전체 수색 계획 — S-현장AI
- 현재: 지휘관은 건물 출입구를 최대 두 곳 고르고(`commander.planEntry`), 방은 진입조가 용의자를 쫓아가며 문 앞 대기 → 섬광탄 → 진입을 한다(`executor.roomDoorFor`).
- 할 일: 용의자의 위치를 모를 때 방을 순서대로 훑는 계획(구역 나누기, 확인한 방 표시).

### K1 대원 경험치 성장과 교대 간 저장 — S-기반 + U-패널
- 현재: `Responder.xpGained` 만 쌓이고 쓰이지 않는다.
- 할 일: 교대 종료 시 경험·숙련 소폭 상승, 부상자는 다음 교대 결장, LocalStorage 저장. 재현성을 위해 "명부 상태"를 `Sim` 생성자의 입력으로 받는다.
- 완료 조건: 재현성 테스트에 명부 입력 추가, 저장된 명부로 재실행 시 해시 일치.

### K2 AI가 실패에서 배우기 — S-관제AI
- 종료 보고서의 오판 기록(`MISJUDGE_TYPE`, `UNDERESTIMATE`, `FALSE_ALARM`)으로 분석·배정 기준이 교대 사이에 조금씩 바뀐다. K1 과 같은 방식으로 "조직 기억"을 입력으로 받는다.

### T1 화면 자동 테스트 — T-도구

### T2 정보 격리 예외 3건 제거 — S-현장AI
