# G4 — 한눈에 보이는 현장 상태 (붕괴를 중심으로)

공통 규칙은 `docs/specs/README.md`. 브랜치 `wf/legibility`, 개발 서버 포트 **5212**(다른 묶음과 겹치면 바꾼다).

사용자의 말: "건물 붕괴 이런 것도 진짜 붕괴했는지 안 보이니까 한눈에 보이게."

**하는 일**: 화면 계층의 일이다. 건물이 정말 무너졌다는 것을 지도·현장·사건 카드에서 한눈에 알아보게 하고, 같은 꼴로 "상태는 바뀌었는데 화면에서 잘 안 보이는 것"(가스가 찬 범위, 되살아난 불, 균열과 보강, 폭발 자리, 붙잡힌 인질)을 함께 고친다. **시뮬레이션 결과는 한 건도 달라지지 않는다**(기록 해시가 같다).

**자기 파일(새로 만든다)**: `src/sim/field/ruins.ts`, `src/view/hazardState.ts`, `src/view/scene/ruins.ts`, `src/view/scene/hazardFx.ts`, `src/view/city/ruinLayer.ts`, `src/ui/HazardStrip.tsx`, `tests/legibility.test.ts`.
**자기 파일(이 묶음이 맡는 기존 화면 파일)**: `src/view/scene/staticLayer.ts`, `src/view/icons.ts`, `src/view/marks.ts`.
**공용 파일 수정(§8 에 적힌 자리만, 가장 작게)**: `src/sim/types.ts`, `src/sim/field/kit.ts`(`baseScene` 의 객체 모양 한 줄), `src/sim/field/builders.ts`(`buildCollapse` 세 줄), `src/sim/field/hazards.ts`(`tickFire` 의 천장 붕괴, `tickCollapse`), `src/view/renderScene.ts`, `src/view/renderCity.ts`, `src/view/camera.ts`(`ACTION_W` 에 한 줄), `src/view/scene/fxBook.ts`(G5 — `DECISIVE` 에 한 단어, 그을음 조건 한 조각), `src/ui/panels.tsx`(`IncidentCard` 두 곳), `src/ui/styles.css` 끝 블록. **G5 가 구조를 바꿔 둔 화면 파일 셋도 공용으로 다룬다**(적힌 자리만, G5 가 더한 export·분기를 유지): `src/view/scene/fx.ts`(`sprites()` 에 칸을 더하되 `fxSprites()` 의 반환은 그대로), `src/view/audio.ts`(`legacy()` 에 분기 하나 — `COMBAT_KINDS`·`planCues` 는 건드리지 않는다), `src/ui/MapLegend.tsx`("건물 상태" 묶음 — G5 의 '교전 중'은 그대로). 선택 항목을 하면 `src/view/city/trafficLayer.ts` 한 덩어리. `src/ui/Viewport.tsx` 는 고치지 않는다(G5 뒤에는 효과 종류 조건이 `fxBook.ts` 의 `DECISIVE` 에 있다).
**건드리지 않는다**: 그 밖의 `src/sim/*` 전부(판단·규칙·난수·현장 생성), `src/view/city/staticCity.ts`·`places.ts`, `src/sim/city.ts`·`cityPlan.ts`, `tests/sim.test.ts`, `README.md`·`CLAUDE.md`·`docs/ROADMAP.md`·`docs/specs/README.md`(합친 뒤에 한꺼번에 고친다).

## 2. 원칙

1. **결과 불변.** `src/sim` 에서 바꾸는 것은 §3 의 기록용 쓰기뿐이다. 난수를 부르지 않고, `emit`·`raiseProblem`·`markRecovered` 를 더하지 않고, 기존 호출의 순서를 바꾸지 않고, 시뮬레이션의 어떤 판단도 그 기록을 읽지 않는다. 증명은 §3.4.
2. **상태를 그린다.** 그림은 상태(관찰자 시점은 진실, AI 시점은 관제·지휘관의 믿음)에서만 나온다. 상태에 없는 것은 그리지 않는다. 멀리서 보이게 과장하는 것은 허용하되, 무엇을 얼마나 과장했는지 이 문서에 적는다. 과장 목록: 지도의 지붕 구멍 넓이(§5.3-1), `'major'` 의 외곽 틈(§5.3-6), 현장의 바깥 벽 금(§4.1 `paintRuinWalls` 3).
3. **시점 규칙.** AI 시점: 부대가 도착한 뒤의 건물 겉모습은 모두가 본다고 친다. 수치(균열의 진행, 가스 폭발 판정 칸 수, 지휘관이 모르는 것)는 관찰자 시점에서만 보인다. 표: §4.7, §5.1, §6.
4. **모양으로 구별한다.** 지도와 목록에는 글자 표식 대신 그림 기호(24×24 경로, `marks.ts`·`icons.ts` 방식). 새 기호는 범례에 넣는다. 현장 화면의 글자 표지(`pill`)는 지금처럼 쓴다.
5. **무너짐은 폭발과 달라 보여야 한다.** 무너짐 = 흙빛 먼지·내려앉는 그림자·흔들림·둔탁한 소리, **빛 없음**(가산 혼합·주황·흰 빛을 쓰지 않는다. 밤에는 무너진 자리의 어둠만 몇 초 옅게 걷는다 — §4.3). 폭발 = 지금의 주황·흰 빛.
6. **고정 층 규칙**(`CLAUDE.md` 함정 "현장 그림의 고정 층"). 고정 층에 그리는 상태는 `staticSig` 에 넣는다. 매 프레임 바뀌는 것(먼지, 깜박임, 흔들림, 진행 고리)은 고정 층에 넣지 않는다.
7. **프레임 예산**은 §9.

### 3.2 `src/sim/field/ruins.ts` (새 파일, 그대로 옮겨 써도 된다)

```ts
// 그림용 기록 (docs/specs/G4-scene-legibility.md). 시뮬레이션의 어떤 판단도 이 기록을 읽지 않는다.
// 난수를 부르지 않고 emit 하지 않는다. 기록을 켜든 끄든 같은 시드의 결과는 같다 — tests/legibility.test.ts 가 RUIN_LOG.on 을 바꿔 가며 확인한다.
import type { Sim } from '../engine';
import type { FallRecord, Scene } from '../types';

export const RUIN_WALL = 1, RUIN_SECONDARY = 8, RUIN_CEILING = 9, RUIN_FURN = 16;
/** 테스트 전용 스위치: 끄면 아무것도 기록하지 않는다 */
export const RUIN_LOG = { on: true };

/** 칸 i 가 무엇이었다가 무너졌는지 적는다. 처음 모습(벽·가구)은 나중의 2차 붕괴·천장 붕괴가 덮어쓰지 않는다 */
export function markRuin(s: Scene, i: number, code: number): void {
  if (!RUIN_LOG.on) return;
  if (!s.ruin) s.ruin = new Uint8Array(s.w * s.h);
  if (s.ruin[i] === 0 || code === RUIN_WALL || code >= RUIN_FURN) s.ruin[i] = code;
}

/** 무너진 순간을 적는다. fx 면 'collapse' 효과도 남긴다(카메라·자동 감속·소리가 이것을 본다. 그림은 falls 로 그린다) */
export function recordFall(sim: Sim, s: Scene, x: number, y: number, r: number, cause: FallRecord['cause'], fx = true): void {
  if (!RUIN_LOG.on) return;
  const list = s.falls ?? (s.falls = []);
  if (list.length < 32) list.push({ t: sim.t, x, y, r, cause, region: s.region[Math.round(y) * s.w + Math.round(x)] ?? -1 });
  if (fx) { s.fx.push({ kind: 'collapse', t: sim.t, x, y, x2: undefined, y2: undefined, text: undefined, color: undefined, ttl: 2.6, c: undefined }); if (s.fx.length > 60) s.fx.splice(0, s.fx.length - 60); }   // G5 가 맞춘 효과 기록의 모양(kind,t,x,y,x2,y2,text,color,ttl,c — hazards.pushFx 와 같다)
}
```

`hazards.ts` 의 `pushFx` 를 가져다 쓰지 않는다(`hazards.ts` 가 이 파일을 import 하므로 서로 부르게 된다). 효과 목록의 60개 상한은 `pushFx` 와 같다.

### 4.1 무너진 뒤의 모습 — 고정 층 (`scene/ruins.ts`, `staticLayer` 가 부른다)

`staticLayer.ts` 의 "무너진 자리" 블록(`s.damage` 칸마다 회색 타원을 그리는 블록 — 함수 안의 그 주석으로 찾는다)을 `paintRuinFloor(g, s, R, tAt, { rubble, rubbleColors })` 한 줄로 바꾸고, 7단계에서 창·문턱을 그린 반복문 뒤에 `paintRuinWalls(g, s, R, geo.hw)` 한 줄을 더한다. `rubble`·`rubbleColors` 는 인자로 넘긴다(`scene/ruins.ts` 가 `staticLayer.ts` 를 import 하면 서로 부르게 된다). 재질: `s.variant === 'landslide'` 면 흙, `'crane'` 이면 긁힌 땅(밝은 먼지 + 긁힌 자국), 그 밖은 콘크리트.

**구역**: `damage` 칸을 4이웃으로 이은 덩어리 하나가 구역 하나다. `ruinZones(s)`(`scene/ruins.ts`)가 덩어리마다 칸 목록·경계 상자·경계까지의 칸 거리·경계 선분을 만들어 둔다. 캐시는 `WeakMap<Scene, …>` 이고 `s.staticVersion` 이 바뀔 때만 다시 센다. 처음 무너진 구역, 2차 붕괴 칸, 크레인 팔 밑은 서로 떨어져 있을 수 있다(`tickCollapse` 는 균열 ±2칸 안에 잔해를 쏟는다 — `hazards.ts` 의 `tickCollapse`). 그래서 아래의 "구역 경계 상자"·"구역 경계까지의 거리"·기울기는 모두 **구역마다 따로** 정한다. 칸이 4개 미만인 구역에는 기울기와 그림자 띠(1)를 그리지 않고 잔해(3·6)만 그린다.

**그리는 조건**: `ruin` 값으로 그리는 넘어간 벽(4)과 깔린 가구(5)는 **지금 칸이 `T.FLOOR` 일 때만** 그린다. `sealPockets` 가 다시 벽으로 메운 칸(§3.3)은 `paintRuinWalls` 2 의 "금 간 벽"으로만 그린다. 서 있는 벽 아래에 쓰러진 벽 판이 겹쳐 그려지지 않게 하려는 것이다.

`paintRuinFloor` — 아래에서 위 순서:

1. **내려앉은 구획의 음영**: `damage` 칸 전체에 `rgba(18,14,10,0.18)`. 그 위에 기울기 — 구역 가장자리에서 서 있는 벽(`T.WALL`)에 더 많이 닿은 쪽을 "받쳐진 높은 쪽", 반대쪽을 "낮은 쪽"으로 보고, 구역 경계 상자에 높은 쪽 0.06 → 낮은 쪽 0.36 의 선형 그러데이션을 `damage` 칸에만 칠한다(칸마다 `fillRect`). 북·서쪽 경계(빛은 왼쪽 위 — 벽 그림자가 +x·+y 로 진다)에는 구역 안쪽으로 0.35칸 폭의 그림자 띠 `rgba(0,0,0,0.35→0)`, 높은 쪽 경계에는 깨진 바닥 끝의 밝은 선 `rgba(220,210,190,0.35)` 한 줄. 위에서 내려다보는 그림에서 "한 단 내려앉아 기울었다"로 읽히게 하는 장치다.
2. **먼지 테두리**: 경계 칸에서 바깥으로 0.6칸까지 `rgba(196,178,146,0.16)` 의 흐린 원 몇 개(자리는 칸 번호 해시 `hash2` — 다시 그려도 같은 그림).
3. **잔해 더미의 높낮이**: 칸마다 높이 `h = min(3, 구역 경계까지의 칸 거리) + (ruin === 1 ? 1 : 0) + (ruin ≥ 16 ? 0.5 : 0) + 해시 0~0.6`. 낮은 칸부터, 위쪽 줄부터 그린다. 칸마다 조각 `3 + 2h` 개(크기 `0.08 + 0.05h` 칸, 색은 높이에 따라 §4.0 잔해 색의 왼쪽→오른쪽), 조각마다 왼쪽 위 밝은 면 `rgba(255,255,255,0.14)` 과 오른쪽 아래 그림자 `rgba(0,0,0,0.28)`(+0.03, +0.04칸). `h ≥ 2.5` 인 칸에는 넓은 판 조각 1~2개(`#9b9488`, 금 한 줄). **높아도 무릎 높이로 보이게** 그림자를 짧게 둔다 — 길을 막는 것은 소품(`drawDebris`, 매 프레임, 짙은 그림자와 나무 막대)이고 바닥 잔해는 지나갈 수 있다.
4. **넘어간 벽**(`ruin === 1`): 원래 벽이 서 있던 줄에 짙은 자국(폭 0.12칸, `rgba(20,16,12,0.5)`, 가장자리 들쭉날쭉). 그 옆, 잔해가 더 많은 쪽으로 0.25~0.45칸 밀린 자리에 쓰러진 벽 판(길이 0.9·두께 0.3칸, 먼지 섞은 벽색의 몸 + 윗면, 해시로 ±10~25° 기울기, 2~3토막으로 끊어 틈을 둔다). 방향은 이웃의 `ruin === 1` 이나 남은 벽이 좌우에 있으면 가로, 위아래에 있으면 세로, 둘 다 없으면 기둥(작은 네모 더미).
5. **깔린 가구**(`ruin ≥ 16`): `rubble(g, 해시, rubbleColors(ruin − 16, x, y))` 를 그리고, 그 위에 회색 조각 4~6개를 흩뿌린다(잔해에 묻힌 가구). 단 `decorHp === 255` 이고 `decor` 가 남은 칸(N7 규약 — X6 의 붕괴가 가구를 이렇게 남긴다)은 N7 의 부서진 가구 그림이 이미 그리므로 `rubble` 을 다시 그리지 않고 회색 조각만 얹는다.
6. **2차 붕괴로 쏟아진 칸**(`ruin === 8`): 3 과 같되 색을 한 단 밝게(`#a59d90` 쪽), 밝은 가루 점 6개 — 새로 쏟아진 잔해.
7. **천장이 내려앉은 칸**(`ruin === 9`, 불난 방): 숯빛 잔해(`#2b2118`·`#3a2c20`)와 탄 서까래 둘(가늘고 긴 막대, 끝에 불씨 점 `#ff9a4a` 하나). 그을음(`drawScorch`)은 그 위에 매 프레임 얹힌다.
8. **치운 자리**: `kind === 'debris' && removed` 인 소품의 칸 — 조각을 칸의 두 변으로 밀어 두고 가운데에 밝은 띠 `rgba(220,210,190,0.12)`(치워서 길을 냈다). 흙이면 흙 얼룩, 크레인 팔이면 긁힌 자국이 남는다.
9. **붕괴 구역 경계**: `damage` 칸과 아닌 칸 사이의 변(`ruinZones` 의 경계 선분)을 모아 한 경로로, `#d6a878`·투명도 0.55·굵기 `max(1.5, R·0.05)`·점선 `[R·0.28, R·0.18]`. 벽 밑으로 지나는 곳은 그 위에 벽이 그려져 자연히 끊긴다.

`paintRuinWalls` — 벽과 창을 그린 뒤:

1. **부러진 벽 끝**: 남은 벽 칸(`T.WALL`) 가운데 상하좌우 이웃이 `ruin === 1` 인 쪽마다, 벽 가운데에서 그 칸 경계까지 벽 두께(`hw`)의 들쭉날쭉한 끝(지그재그 4~5점)을 벽색으로 잇고, 끝에서 철근 2~3가닥(`#9a5a3a`, 굵기 0.025칸, 길이 0.15~0.25칸, 조금씩 휜다)을 뻗는다. 지금은 남은 벽이 칸 가운데에서 깔끔하게 끝나 "원래 그렇게 생긴 벽"으로 보인다.
2. **금 간 벽**: `damage === 1` 인데 남아 있는 벽 칸(`sealPockets` 가 메운 칸 포함) — 윗면에 길이 방향 금(짙은 지그재그 `rgba(20,18,16,0.7)`), 가장자리의 떨어져 나간 홈 두어 개, 윗면에 먼지 `rgba(165,157,144,0.35)`.
3. **바깥 벽의 금**(과장 — §2.2): `damage` 칸과 4이웃으로 맞닿은 벽 칸 가운데 건물 밖(`isBuilding` 이 아닌 칸, `T.VOID` 포함)과도 맞닿은 칸, 곧 바깥 벽. 짧은 금 한두 줄(`rgba(20,18,16,0.6)`, 벽 두께 안에서)과 벽 밑 안쪽에 회반죽 가루 점 몇 개(`rgba(165,157,144,0.35)`)만 그린다. 벽을 끊거나 뚫지 않는다. 시뮬레이션은 바깥 벽을 무너뜨리지 않으므로(`builders.ts:650-652`) 그 이상은 상태에 없는 그림이다. 건물 전체 붕괴처럼 바깥 벽을 실제로 무너뜨리는 규칙은 다른 묶음(X6)의 몫이다(§16).

`R < 12`(작은 창·축소 보기)이면 조각 수를 1/3 로 줄이고 철근과 금(2·3 포함)은 그리지 않는다.

### 4.2 무너지기 전 — 2차 붕괴 위험 (매 프레임, `scene/hazardFx.ts` `drawDangerZones`)

그리는 자리는 어둠·날씨 뒤의 정보 표지 단계다(§2.8, §4.6). 밤에도 보인다. 보강하지 않은 균열(`unstable`, `!mitigated`)마다:

- **위험 범위**: 반지름 2.6칸 원(= `tickCollapse` 의 `blast` 반경, 무너지면 다치는 범위). 바깥 `rgba(8,13,18,0.55)` 굵기 0.16칸 위에 `#ffd166` 굵기 0.09칸 점선 `[0.32, 0.22]`칸, 점선이 천천히 돈다(`lineDashOffset = −timeMs / 80`) — 통제선 테이프. 투명도는 관찰자 시점 `0.5 + 0.4·leak`, AI 시점 0.7.
- **진행 고리**(관찰자 시점만): 반지름 0.66칸, 위(−90°)에서 시계 방향으로 `leak × 360°`, §4.0 진행 고리 색, 굵기 0.08칸, 밑에 어두운 고리. 지금의 맥박 고리(반지름 0.52)는 AI 시점에서만 남긴다.
- **곧 무너짐**(관찰자 시점, `leak > 0.75`): 균열 둘레 1칸 안에 먼지 알갱이 4개가 떨어진다(0.5칸, 1.2초 주기).
- 보강한 균열: 범위를 그리지 않는다(지지대 그림 `drawUnstable(shored)` 만 — 지금 그대로).
- 보이는 균열은 지금 규칙 그대로: AI 시점은 지휘관이 아는 것(`cmd.beliefs.get('haz', p.id)`)만, 관찰자 시점에서 지휘관이 모르는 것은 투명도 0.55.
- (선택, 관찰자 시점) 불난 방의 천장 붕괴 위험: 탄 칸이 45% 이상이고 아직 판정하지 않은(`!s.collapseDone.has(r.id)`) 방의 경계 상자에 `rgba(214,168,120,0.5)` 점선. 규칙은 55%에서 판정한다(`tickFire` 의 천장 붕괴 덩어리). X6 가 합쳐지면 그 규칙이 없어지므로 이 표지는 X6 의 구획 건전도 그림으로 대체한다(지운다 — X6 §7.3).

### 4.3 무너지는 순간 (매 프레임, `s.falls` 를 읽는다 — `drawFallMoments`·`drawFallRing`)

`s.falls` 가운데 `age = (sim.t + alpha·sim.dt) − f.t` 가 0~25초인 것마다. 효과 목록(`s.fx`)은 물줄기가 많은 현장에서 60개 상한에 밀려 사라질 수 있으므로 쓰지 않는다. `sim.t` 기준이라 일시정지하면 그 순간에서 멈추고, 스크린샷이 재현된다. **결정**: 무너지는 순간은 일시정지·재현을 위해 시뮬레이션 시각을 쓴다(G5 의 폭발처럼 연출 시계를 쓰지 않는다). 관찰 현장은 `'collapse'` 가 `DECISIVE` 에 들어가 자동 감속(1배속)으로 보이고, 자동 감속을 끈 15배속이나 관찰하지 않는 작은 창에서는 0~0.5초가 실제 시간 30ms 남짓에 지나가 거의 보이지 않는다 — 받아들인다(가라앉는 먼지 25초와 고정 층의 잔해가 남는다).

| 시간 | 무엇 | 어떻게 |
|---|---|---|
| 0~0.35초 | 내려앉는 그림자 | 중심 원, 반지름 `r·0.9·(0.5 + 0.5·age/0.35)`, `rgba(10,8,6, 0.45·(1 − age/0.35))` — 떨어지는 천장의 그림자가 커진다 |
| 0~0.5초 | 떨어지는 덩어리 | 7개. 착지점은 반경 `0.8r` 안(해시). 1.2칸 위·1.6배 크기에서 가속하며 내려와 0.45초에 착지(1배), 착지하면 사라진다(고정 층의 새 잔해가 받는다) |
| 0~0.8초 | 먼지 충격 고리 | `rgba(214,200,170, 0.7·(1−k))`, 반지름 0.4칸 → `r`(빠르게 퍼졌다 느려진다), 굵기 `0.12칸·(1−k)`. **멈추는 반지름 = 다치는 범위** |
| 0.1~3초 | 먼지 기둥 | 먼지 덩어리 10개(`fx.ts` 에 `puffSprite(196,178,146)` 을 더한다), 방향은 해시, 거리 `r·(0.2 + 0.9·e)`, 크기 `ts·(1.2 + 2.2·e)`, 투명도 `0.65·(1−k)^1.3`, 위로 0.3칸 떠오른다 |
| 3~25초 | 가라앉는 먼지 | 반지름 `1.1r` 의 흐린 원, `rgba(196,178,146, 0.22·(1 − (age−3)/22))` |
| 0~1.2초 (천장 붕괴만) | 불티 | 8개(`#ff9a4a`·`#ffd27a`)가 튀어 올랐다 떨어진다 |

(`k` = 그 줄의 경과 비율, `e = 1 − (1−k)²`.) 처음 무너진 구역('zone')도 사건이 생긴 순간에 관찰자가 보고 있으면 같은 연출을 받는다.

**두 단계로 나눠 그린다.** 먼지 충격 고리는 "다치는 범위"를 알려 주는 표지다. 그래서 `drawFallRing` 이 어둠·날씨 뒤의 정보 표지 단계에서 그린다(§2.8). 나머지(그림자·덩어리·먼지 기둥·가라앉는 먼지·불티)는 `drawFallMoments` 가 불 뒤, 나무 수관 앞에서 그린다(§4.6). 0~0.5초에 몰린 연출(그림자·덩어리·고리 앞부분)은 한 틱(0.2초) 차이로 놓친다. 스크린샷은 §11 의 틱을 정확히 지킨다.

- 가산 혼합(`'lighter'`)을 쓰지 않는다. 주황·흰 빛도 없다.
- **밤**: 2차 붕괴가 더는 `'boom'` 을 남기지 않으므로(§3.3), 지금 어둠에 구멍을 내던 장치(어둠 블록의 효과 반복문 — `flash`·`boom` 만 구멍을 낸다)가 무너짐에는 걸리지 않는다. 대신 어둠 블록의 효과 반복문 바로 뒤에 한 줄을 둔다: `for (const f of s.falls ?? []) { const age = (sim.t + o.alpha * sim.dt) - f.t; if (age >= 0 && age < 4) hole(dg, cx(f.x) * k, cy(f.y) * k, ts * f.r * 1.3 * k, 0.3 * (1 - age / 4)); }`. 빛이 아니라 어둠을 옅게 걷는 것이다(투명도 0.3 이하). 먼지 기둥이 밤에도 보이게 하려는 것이다. 무장 사건의 AI 시점 어둠(`fog`)에도 같은 줄이 걸린다(붕괴가 나는 무장 현장은 지금 없다).
- **흔들림**(`fallShake`): 가장 최근의 무너짐이 0.6초 안이면 현장 그림 전체를 `A·(1 − age/0.6)²·(sin(age·97), cos(age·83))` 칸만큼 민다. `A` = 2차 붕괴 0.16칸, 천장 0.1칸, 처음 구역 0.12칸. 지진이 흔들린 직후(`sim.disaster.shakes` 의 마지막에서 0.9초 안)에도 붕괴 현장 0.14칸, 다른 현장 0.08칸. `drawScene` 의 `ctx.translate(L.ox, L.oy)` 바로 뒤에서 한 번 `translate`. 작은 창(`MINI`)은 흔들지 않는다. 동작 줄이기 설정이면 흔들지 않는다 — 판정은 G5 와 한 갈래로: `renderScene` 의 `cv ? cv.reduced : reducedMotion()` 을 인자로 받는다(`hazardFx.ts` 는 `renderScene` 을 import 할 수 없으므로 `matchMedia` 를 따로 부르지 않는다). 지도는 흔들지 않는다(지금의 지진 규칙 그대로).
  `fallShake(sim, s, mini, reduced)` 는 **칸 단위** `{ x, y }` 를 돌려준다(무너짐 몫과 지진 몫을 더한 것, 자기 상한 0.16칸). 흔들림은 `hazardFx.ts` 의 `sceneShake(sim, s, mini, extra, reduced)` 한 함수에 모은다: `fallShake` 에 `extra`(칸 단위)를 더해 돌려준다. `renderScene.ts` 는 그 값에 `ts` 를 곱해 `translate` 를 **한 번만** 한다. G5 는 합쳐졌다 — 지금의 흔들림 줄(`if (cv && !MINI && !cv.reduced) { const sh = cv.book.shake(s.id, ts, view); if (sh.x || sh.y) ctx.translate(sh.x * ts, sh.y * ts); }`)을 `const sh = sceneShake(sim, s, MINI, cv && !cv.reduced ? cv.book.shake(s.id, ts, view) : undefined, cv ? cv.reduced : reducedMotion()); if (sh.x || sh.y) ctx.translate(sh.x * ts, sh.y * ts);` 로 바꾼다(G5 의 가까움 감쇠 `view` 와 `!cv.reduced` 게이트를 살린다). 두 묶음은 각자 자기 상한만 지키고 합은 자르지 않는다(G5 §3.4 와 같은 규칙 — §16).
- 'collapse' 효과는 그림에 쓰지 않고, 다음 셋이 본다(G5 가 합쳐진 뒤의 자리 — G5 구현 메모). **카메라** `camera.ts` 의 `ACTION_W` 레코드에 `collapse: 2.5`(무게는 `boom` 과 같다). **자동 감속** `fxBook.ts` 의 `DECISIVE` 집합에 `'collapse'` 한 단어(감속 길이는 `Viewport` 의 `dramaMs` 기본값 3200 그대로 — `Viewport.tsx` 는 고치지 않는다). **소리** `audio.ts` 의 `legacy(f, fast)`(교전 종류 `COMBAT_KINDS` 밖의 효과가 넘어오는 자리)에 분기 하나: `else if (f.kind === 'collapse') { if (this.ok('collapse', 0.5)) { this.burst(0.9, 0.3, 220, 0.8, 'lowpass'); this.tone(48, 0.9, 0.25, 'sine', 0, 30); this.burst(0.07, 0.18, 2400, 1.2, 'bandpass', 0.02); } }` — 낮게 우르르 + 짧게 쩍.

### 4.4 무너진 뒤

- 2차 붕괴 칸(`ruin === 8`)은 고정 층이 다시 그려지며 밝은 새 잔해가 된다(`tickCollapse` 가 이미 `staticVersion++` 를 한다). 길을 막는 잔해 소품은 지금처럼 매 프레임.
- 가라앉는 먼지 25초(§4.3).
- 무너진 균열은 `leak` 가 0 으로 돌아가 다시 차오른다(`leakRate × 0.6`). 위험 범위는 계속 그려지고 진행 고리는 처음부터 — "또 무너질 수 있다"가 그대로 보인다.
- 사건 카드·지도 핀에 2차 붕괴가 남는다(§5.4, §6).

### 4.5 천장 붕괴(불)·크레인·산사태

- 천장 붕괴: §4.1-7 + §4.3(반경 2.2, 불티). 불난 방 위에 숯빛 잔해와 먼지가 함께 보인다.
- 크레인(`collapse/crane`): 팔 토막은 소품(`craneBoom`)으로 지금처럼. 팔 밑의 `damage` 칸은 긁힌 땅 — 팔 방향(첫 토막과 끝 토막 `color === 99` 을 잇는 방향)의 긁힌 자국 두 줄과 밝은 먼지. 토막을 치우면 자국이 남는다.
- 산사태(`collapse/landslide`): 흙 재질의 더미. 흙(`mud`)을 치운 자리는 흙 얼룩.

### 4.6 그리는 순서 (`renderScene.ts`, 새 것은 굵게)

**흔들림 `translate`(`sceneShake` × `ts`)** → 고정 층 → 그을음 → **폭발 자리(§7.3: 터진 폭발물·불붙은 밸브의 자국)** → 젖은 바닥 → 무전 음영 → 통제 지점 → 용의자 시야 → 소품 → 출동 차량 → 통과 차량 → 연기 아래층(**가스는 연두**, §7.1) → 사람(**인질 상태**, §7.4) → 구조 줄 → 불 → **무너지는 순간의 몸통(`drawFallMoments`: 그림자·덩어리·먼지 기둥·가라앉는 먼지·불티)** → 나무 수관 → 연기 위층 → 어둠과 빛(**밤: 무너진 자리의 어둠을 옅게 걷는 한 줄**, §4.3) → 날씨 → 재난 → 구역 이름·수색% → **정보 표지(§2.8): 붕괴 구역 경계 다시 긋기(밤에만), 2차 붕괴 위험 범위·진행 고리·곧 무너짐(`drawDangerZones`), 먼지 충격 고리(`drawFallRing`), 짙은 가스 경계(`drawGasEdge`), 되살아난 불의 테두리(`drawRekindle`)** → 진입 지점 → 구조 대상 딱지 → 용의자 표지 → 효과 → **새 글자 표지(가스 고임·되살아난 불)** → 대원 이름표 → 가장자리.

- **붕괴 구역 경계 다시 긋기**: 밤(`sim.weather === 'night'`)에는 고정 층의 경계 점선(§4.1-9)이 어둠에 묻힌다. 같은 선분(`ruinZones` 의 경계 선분 — 고정 층과 같은 캐시)을 여기서 한 번 더 긋는다. 색·굵기·점선은 같고 투명도는 0.45. 낮에는 긋지 않는다(두 번 그으면 진해진다).
- 정보 표지 단계는 연기 위층·나무 수관·안개 위에 그려지므로 사람 위를 지나간다. 선은 가늘고 반투명이라 사람을 가리지 않는다. 스크린샷을 보고 어지러우면 투명도를 내린다(§15-4).

`scene/hazardFx.ts` 의 함수는 글자 표지가 필요하면 `{ x, y, text, color }[]` 를 돌려주고 `renderScene.ts` 가 자기 `pill()` 로 그린다(`renderScene.ts` 를 import 하면 서로 부르게 된다).

## 5. 지도

### 5.1 언제 보이나 — `ruinSeen(sim, I, truth)` (`view/hazardState.ts`)

대상: 유형이 붕괴이고 `I.truth.placeId ≥ 0` 이며 현장(`sim.scenes[I.id]`, 사건이 생길 때 만들어지고 지워지지 않는다)의 `damage` 칸이 하나 이상인 사건. 승강기 갇힘은 `damage` 가 없어 저절로 빠지고, 산사태는 건물이 없어(`placeId = −1`) 빠진다(핀 아이콘만 바뀐다).

| 값 | 관찰자 시점 | AI 시점 |
|---|---|---|
| `'confirmed'` | 사건이 생긴 순간부터(미신고면 흐리게, 투명도 0.55) | 첫 부대가 도착한 뒤(`I.firstArrivalAt ≥ 0`) |
| `'reported'` | — | 분석 유형이 붕괴이고, 신고 위치가 맞고(`I.locationKnown && I.reportedNode === I.truth.nodeId` — 건물 테두리 규칙과 같다), 알아본 변형이 승강기 갇힘이 아닐 때 |
| `'none'` | 그 밖 | 그 밖 |

끝난 사건: 관찰자 시점은 교대 끝까지 `'confirmed'`. AI 시점은 도착했던 사건만 남는다.

### 5.2 건물 크기에 따라 두 가지

`min(q.w, q.h) · xf.scale ≥ 12` 화소면 **건물 덧그림**(§5.3), 아니면 **기호**(§5.4). 배율 1 에서는 거의 모든 건물이 기호다.

### 5.3 건물 덧그림 — `drawRuinsWorld` (`view/city/ruinLayer.ts`)

`renderCity.ts` 월드 층의 `drawDisasterWorld(…)` 바로 뒤(같은 변환 안)에서 `drawRuinsWorld(ctx, sim, { truth: o.truth, timeMs: o.timeMs, scale: xf.scale, mini })` 한 번. 축소 창(`mini`)에서는 그리지 않는다. 건물 회전은 테두리 깜박임 코드(`renderCity.ts:223-231`)처럼 `translate(가운데) → rotate(q.rot)` 뒤 `(−w/2, −h/2)` 좌표로 그린다. `staticCity.ts` 의 `local()` 은 export 되어 있지 않으므로 같은 세 줄을 이 파일에 둔다(`staticCity.ts` 는 고치지 않는다). 색표가 필요하면 이 파일 안에 복사한다(`renderCity.ts` 를 import 하면 서로 부르게 된다).

`ruinInfo(sim, I)` (`hazardState.ts`, 진실. `s.staticVersion` 이 바뀔 때만 다시 계산 — `WeakMap<Scene, …>`). **건물 칸이 0 이거나 `damage` 칸이 0 이면 `null`** 을 돌려준다. 산사태 현장(`scenes/disaster.ts:106-150`)에는 건물 칸이 없고(길·땅·나무·바위) `damage` 칸만 73~106개라, 나누면 무한대가 된다. 이 함수를 부르는 곳(덧그림·배지·기호·마우스 정보·카드 칩)은 모두 `null` 이면 아무것도 그리지 않는다. (X6 가 합쳐지면 `Sim.placeMarks` 가 있는 건물은 `damage` 칸이 0 이어도 값을 돌려준다 — 전소·폭발 흔적·그을음은 `s.damage` 를 쓰지 않기 때문이다. 건물 칸 0 → `null` 은 그대로. X6 §7.2.)

- `frac` = `damage` 칸 수 / 건물 칸 수(`FLOOR·FURN·DOOR·STAIR·WALL·WINDOW` 칸).
- `u, v` = 무너진 구역 무게중심의 건물 안 상대 위치 0~1. 기준 상자는 무게중심에서 가장 가까운 건물 칸에서 시작해 건물 칸을 따라 넓혀 간 덩어리의 경계 상자(2층 건물은 두 층이 격자에 나란히 놓이므로 한 층만 잡힌다).
- `level` = `frac ≥ 0.22` 이거나 2차 붕괴가 한 번이라도 있으면 `'major'`, 아니면 `'partial'`. 0.22 는 §1.1 분포의 위 1/3 쯤이다. 스크린샷을 보고 조정해도 된다(조정하면 구현 메모에).
- `secondary` = `falls` 의 'secondary' 수, `lastFall` = 마지막 무너짐 시각, `material` = 콘크리트·흙·크레인.

그림(`'confirmed'` 일 때만):

1. **내려앉은 지붕**: 구멍의 넓이 = 지붕의 `clamp(frac × 2.2, 0.3, 0.85)` — **과장**: 실제 몫의 약 두 배(멀리서도 보이게). 가운데는 `((u − 0.5)·w, (v − 0.5)·h)` 를 지붕 밖으로 나가지 않게 당긴 자리. 모양은 14각형(가장자리를 `hash2(q.id, k)` 로 들쭉날쭉하게), 채움 `#100c09` 투명도 0.62.
2. **구멍 속 잔해**: 조각 10~18개(§4.0 잔해 색), 구멍 가장자리에 기울어진 지붕 판 3~4개(`#78746c` 투명도 0.9, 밝은 윗변).
3. **쏟아진 잔해**: 건물 가운데에서 구멍 쪽 방향으로, 외벽 밖 `0.25·max(w, h)` 안에 조각 5~8개 — 무너진 것이 건물 윤곽 밖까지 넘친다.
4. **지붕의 금**: 구멍에서 지붕을 가로지르는 꺾은선 둘, `#0a0806` 투명도 0.55, 굵기 `max(0.8, 1.2 / scale)`.
5. **먼지**: 마지막 무너짐 뒤 90초 동안 반지름 `0.9·max(w, h)` 의 흐린 원 `#c4b292`, 투명도 0.3 → 0.08, 그 뒤 0.08 로 남는다.
6. `'major'` 는 구멍이 커지고(위 식) 구멍에 가장 가까운 외곽선 한 변을 따라 어두운 틈(외곽이 무너졌다).
7. 밤(`sim.weather === 'night'`)에는 색을 `shade(…, −0.35)`. 정전(`d.dark`) 중에도 그대로 보인다. **덧그림의 색은 모두 `#rrggbb`(또는 `rgb()`)와 투명도로 나눠 적는다** — `shade()`·`mix()` 에는 `rgba` 를 넣을 수 없다(`CLAUDE.md` 함정 "색 계산"). 투명도는 `globalAlpha` 로 건다. 이 절의 색: 구멍 `#100c09` 0.62, 지붕 판 `#78746c` 0.9, 금 `#0a0806` 0.55, 먼지 `#c4b292` 0.08~0.45, 외곽 틈 `#100c09` 0.7, 크레인 팔 `#e0b83a` 1.
8. 크레인: 구멍 대신 공사장을 가로지르는 쓰러진 팔(노랑 `#e0b83a` 굵은 선에 격자 눈금, 끝에 갈고리 점)과 먼지.

**무너지는 순간(지도)**: 무너짐(`falls`)마다 6초 동안 건물 위에 먼지가 피어오른다(반지름 `max(w, h)·(0.6 + 0.4k)`, 투명도 `0.45·(1 − k)`). 관찰자 시점은 모든 무너짐(지진이 일으킨 처음 구역 포함 — 진앙 고리와 함께 도시 곳곳에서 먼지가 핀다), AI 시점은 첫 도착 뒤의 무너짐만. 이 먼지는 건물 크기와 무관하게(배율 1 에서도) 그린다.

진행 중인 사건은 핀이 건물 가운데를 가린다. 구멍은 `u, v` 로 한쪽에 치우치므로 핀 옆으로 보이고, 끝난 사건(핀 없음)에서는 온전히 보인다.

### 5.4 기호와 핀 — `drawRuinBadge`, `ruinGlyphAt` (`ruinLayer.ts`)

- **새 기호**(`marks.ts` `RUIN_MARK`): `partial` = 한쪽이 부서진 건물 + 옆의 잔해, `major` = 납작한 잔해 더미 + 기울어진 판. 바탕 없는 실루엣에 어두운 테(경로를 `#0b1219` 굵기 3 으로 먼저 긋고 채운다) — 네모(시설)·원(부대)·핀(사건)과 다른 네 번째 모양. 초안 경로(evenodd, 견본표로 다듬는다 — §11):

- **진행 중인 사건의 핀 배지**: 핀 몸통을 그린 뒤(`renderCity.ts:297` 의 `drawIcon` 바로 뒤) `drawRuinBadge(ctx, sim, I, x, y, r, o.truth, o.timeMs)` 한 줄. 핀의 왼쪽 아래 `(x − 0.78r, y + 0.78r)` 에 반지름 `0.46r` 의 어두운 원(`#0b1219`), 테 `#d6a878`(굵기 `max(1.5, 0.1r)`), 안에 `RUIN_MARK[level]`(크기 `0.72r`, `#d6a878`). `'reported'` 는 테를 점선으로 하고 기호는 `partial` 을 투명도 0.6 으로(규모를 아직 모른다). 왼쪽 아래는 지금 비어 있다(코드 이름표는 오른쪽 위, 상태 글자는 아래).
- **2차 붕괴 알림**: 마지막 2차 붕괴 뒤 2초 동안 핀에서 흙빛 고리가 퍼지고(`r → r + 28·zs`, `#d6a878`, 투명도 `1 − age/2`, 굵기 3), 배지가 0.6초 동안 1.25배에서 1배로 줄어든다. AI 시점은 첫 도착 뒤의 것만.

### 5.5 지진 때

배율 1 에서: 진행 중인 붕괴는 핀 + 배지(관찰자 시점에서는 미신고 핀도 회색 + 배지), 끝난 붕괴는 기호, 무너진 순간마다 건물 위 먼지. 지진은 25초에 걸쳐 사건을 쏟아내므로(`disaster.ts:276-282`) 그동안 진앙 고리와 함께 도시 곳곳에서 먼지가 피고 배지가 늘어난다. AI 시점에서는 신고가 들어온 곳부터 점선 배지가 뜨고 부대가 닿을 때마다 채운 배지로 바뀐다 — "알려진 피해"와 "확인한 피해"가 한눈에 갈린다. 관찰자 시점에서 지진의 충격 단계(`d.phase === 'impact'`)에 처음 나타나는 배지·기호는 0.4초 동안 1.4배에서 1배로 내려앉으며 나타난다. 여진(`tickQuake`)이 금 간 구조물을 흔들면 곧 2차 붕괴 고리가 여러 핀에서 퍼진다.

## 7. 같은 꼴의 다른 상태

### 7.1 가스가 찬 범위 (필수)

`gasView(s, tick)` (`hazardState.ts`, `sim.tick` 이 바뀔 때만 다시 계산 — 가스 확산은 1초에 한 번이라 대개 그대로다):

- 가스 누출 현장(`s.kind === 'hazmat'`)에서 불붙은 밸브가 없으면 연기 칸 전부가 가스 — 지금과 같다.
- 그 밖에 새는 밸브(`valve`, `!mitigated && !ignited`)가 있고 가스 규칙이 도는 현장(`kind === 'hazmat'` 또는 `rules` 에 'gas'): 밸브 칸에서 벽이 아닌 칸으로 넓혀 가며 "밸브가 설명하는 농도" `g = leakRate × 0.86^걸음`(연기 확산의 실내 감쇠 0.86 과 같다)을 매기고, `smoke ≥ 0.12` 이고 `g ≥ 0.6 × smoke` 인 칸을 가스로 본다. **근사다**(불 연기·붕괴 먼지와 섞인 칸은 회색으로 남는다).
- `dense` = 실내 칸 가운데 `smoke > 0.6` 인 칸 수, `denseMask` — 시뮬레이션의 폭발 판정과 **같은 식**(`tickGas` 의 `let dense = 0` 덩어리). 판정이 불 연기까지 함께 센다는 것을 그대로 보여 준다(규칙은 고치지 않는다). **X6 가 합쳐지면** 그 판정이 없어지고 X6 의 가스 격자(`s.cat.gas`)가 대신한다 — X6 가 `gasView` 를 고친다: `s.cat?.gas` 가 있으면 가스 칸 = `c.gas ≥ 0.25`, `dense`·`denseMask` = LEL 구름(`c.gas ≥ 1`, 덩어리 N ≥ 3), 표지 '가스 LEL 초과 — 폭발 위험'(X6 §7.3).

그림:

- `fx.ts` 의 `smokeLayer`·`drawSmoke` 가 `tint` 대신 `gas: Uint8Array | null` 을 받아 칸마다 가스면 연두 덩어리, 아니면 지금의 회색 덩어리를 쓴다. 연두 덩어리는 지금의 물들이기(`rgba(198,226,92,0.62)` 를 `source-atop`)를 미리 섞은 색 — 옅은 것 `puffSprite(190, 208, 128)`, 짙은 것 `puffSprite(145, 162, 80)`. `source-atop` 물들이기는 지운다. **가스 누출 현장은 지금과 거의 같게 보여야 한다**(전후 스크린샷 F1).
- 짙은 가스 경계(관찰자 시점, 새는 밸브가 있을 때만, 정보 표지 단계 — §4.6. 밤과 안개에도 보인다. 작은 창에서는 없다): `denseMask` 칸과 아닌 칸 사이의 변(틱마다 한 번 선분 목록으로 만들어 둔다)을 `#d6f06a` 점선(굵기 `max(1.5, ts·0.05)`, `lineDashOffset` 이 천천히 흐른다)으로. `dense ≥ 10` 이면 그 무게중심 위에 `'가스 고임 — 폭발 위험'` 표지(빨강 `#ff5d5d`).

### 7.2 되살아난 불 (필수, 작다)

`rekindledRegions(sim, s, truth)` (`hazardState.ts`, `sim.tick` 이 바뀔 때만 다시 계산):

- 관찰자 시점: 실내 방마다 지휘관의 믿음 `cmd.beliefs.val('fire', r.id)` 가 있고 0.05 이하인데 그 방 진실의 `fire` 최대가 0.1 이상이면, 그 방 경계 상자에 `#ff6b3d` 점선 둥근 사각형 + 방 이름 아래 `'다시 붙은 불 — 지휘관은 모름'` 표지(`#ff9a6a`). (035a83f 의 S2 `fire/std` 에서 방 4 가 틱 670~901 동안 이 조건에 든다.)
- AI 시점: 지휘관의 `fire` 믿음 가운데 글에 '되살아남' 이 든 것(`executor.ts` 의 잔불 정리 갈래)은 1초도 안 되어 다음 보고에 덮인다(S2 `fire/std`: 틱 945 에 생기고, 949 에 '화재 (강도 60%)', 959 에 '진압 확인'). 그래서 믿음을 보지 않고 **무전 기록**을 본다. 그 사건의 `sim.events` 가운데 `kind === 'radio'` 이고 글에 `'꺼진 줄 알았던 불이 다시'` 가 든 것이 대상이다(`executor.ts` 의 같은 갈래가 보내는 무전 — 찾을 글귀 `'꺼진 줄 알았던 불이 다시'`, AI 조직이 들은 말). 글은 `${방 이름}에서 꺼진 줄 …` 로 시작한다. 그래서 `s.regions` 가운데 `text.startsWith(r.name + '에서')` 인 방을 고른다(여럿이면 이름이 가장 긴 것). 그 무전의 시각에서 15초 동안 그 방에 같은 점선과 `'잔불 되살아남'` 표지를 그린다.
  - 캐시: `WeakMap<Sim, { next: number; last: Map<number /* incidentId */, Map<number /* regionId */, number /* t */>> }>`. `next` 는 다음에 훑을 기록 번호다. 기록(`sim.events`)은 뒤에 붙기만 하므로 새 기록만 훑는다. 프레임 속도·배속과 무관하게 놓치지 않는다. 되감기는 새 `Sim` 을 만들므로 캐시가 저절로 비워진다.
- 그리는 자리는 정보 표지 단계(§4.6)다. 작은 창에서는 그리지 않는다(§4.8).

### 7.3 폭발 자리 (필수, 작다)

**바닥 흔적으로 그린다.** `renderScene.ts` 의 그을음(`drawScorch(ctx, s, ts)` 줄) 바로 뒤에 `drawBlastScars(ctx, s, ts, MINI)`(`hazardFx.ts`) 한 줄을 둔다. 이 함수는 소품을 한 번 돈다. `kind === 'bomb' && exploded` 는 크기 1, `kind === 'valve' && ignited` 는 0.6 으로 `drawBlastScar(g, p.id, scale)` 를 그린다. 자국의 모양: 반지름 0.9칸의 들쭉날쭉한 검은 자국(`rgba(6,5,5,0.75)`), 1.6칸까지 뻗는 방사형 금 6~8줄(`rgba(20,18,16,0.7)`), 찢어진 가방·상자 조각 3~4개(폭발물만). 모양은 `p.id` 해시로 정해 다시 그려도 같다.

- 소품(밸브·가스 용기)은 그 위에 소품 단계에서 지금처럼 그려진다. 터진 가방·상자는 `skins/crime.ts` 가 지금처럼 `return` 한다 — **`skins/crime.ts` 는 고치지 않는다**.
- 소품 수만큼 도는 반복이라 매 프레임이어도 가볍다. 고정 층에 넣지 않는다(`exploded`·`ignited` 는 `staticSig` 에 없다).
- 겉모습이므로 두 시점 모두 그린다(§2.3). 작은 창에서는 검은 자국만(§4.8).
- 가스 용기는 이미 별 모양 자국이 있다(그대로). 2차 붕괴 자리는 고정 층의 새 잔해로 남는다(§4.4).
- **G5 의 그을음과 겹치지 않게 G4 가 조건을 단다**: 구현된 G5 는 모든 `boom` 에 그을음 남는 그림을 조건 없이 넣는다(`fxBook.ts` 의 `else if (f.kind === 'boom') this.decal(s.id, { kind: 'scorch', … })` 줄). 이 줄에 `c?.src !== 'bomb'` 조건을 단다(터진 폭발물 자리는 G4 의 자국). 터진 밸브 자리의 `'gas'` 그을음(반경 0.7×3.8)도 G4 의 밸브 자국(0.6)과 겹친다 — 뺄지는 스크린샷을 보고 정해 구현 메모에 적는다.

### 7.4 붙잡힌 인질 (필수, 작다)

`hostageState(sim, s, c)` (`hazardState.ts`). 시뮬레이션의 규칙 `hazards.isHeld`(`hazards.ts:289-293`)는 `hostageId` 를 보지 않는다. 3.2칸 안에 대치·교전 중인(무력화되지 않은) 총기 용의자가 있으면 어떤 `c.hostage` 든 붙잡힌 것으로 본다. 인질 사건은 인질 여럿을 총기 용의자 1.6칸 안에 두면서 `hostageId` 는 한 명에게만 준다(`builders.ts:524-526`). 숨은 시민도 `c.hostage` 다(`builders.ts:529·539·547·570`). 그래서 상태는 `isHeld` 와 같은 판정으로, **어느 용의자든** 본다. `c.hostage` 인 사람마다 위에서부터 처음 맞는 줄:

| 상태 | 조건 | 그림 |
|---|---|---|
| `'freed'` | `c.dead` 이거나 `c.where !== 'scene'` | 지금 규칙대로(누운 사람·안전 구역·실려 감) |
| `'held'` | `isHeld(sim, s, c.id)` — 데리고 나올 수 없다(`executor.ts:532` 와 같은 규칙). `c.walking` 이어도 이것이 먼저다(끌려가는 인질은 `walking` 이 참일 수 있다 — 035a83f 의 S3 `armed/hostage` 틱 700 에서 확인) | 손을 뒤로(지금) + 인질 발밑에 붉은 고리 하나 |
| `'window'` | 3.2칸 안에 `hold`·`fight` 인 총기 용의자가 있는데 모두 무력화 중(`sim.t < h.stunUntil`) — 구출 기회 | 손을 뒤로 + 발밑 고리를 노랑 `#ffd166` 으로, 깜박임 |
| `'freed'` | `c.walking` — 스스로 걸어 나가는 중 | 보통 자세(`'side'`, 크기 0.96), 선·고리 없음 |
| `'guarded'` | 5칸 안에 `hold`·`fight` 이고 무력화되지 않은 용의자가 있다(흉기·맨손이거나, 총기인데 3.2칸 밖 — 데리고 나올 수 있다) | 손을 뒤로, 고리 없음 |
| `'confined'` | 그 밖 — 곁에 잡은 이는 없지만 아직 그 자리에 갇혀 있다(숨은 시민, 투항 직후 아직 걷지 않은 인질) | 손을 뒤로(지금과 같다), 선·고리 없음 |

- **점선**은 지금처럼 `hostageId` 가 가리키는 짝(용의자 → 그 인질)에만 긋는다(`renderScene.ts` 의 용의자 → 인질 빨간 점선 블록). 색은 그 인질의 상태로 정한다: `held` 빨강(지금), `window` 노랑 `#ffd166` 점점선 + 깜박임, `guarded` 주황 `#ff9f43`. `freed`·`confined` 면 긋지 않는다. G5 는 인질 선을 건드리지 않는다(G5 §11).
- `renderScene.ts` 의 구조 대상 그리기에 있는 `c.hostage && c.where === 'scene'` 두 곳(자세와 크기)을 `hs !== 'freed'`(`hs` = 그 사람의 상태)로 바꾼다. 결과적으로 지금 그림과 달라지는 것은 걸어 나가는 사람의 자세, 발밑 고리, 점선의 색이다.
- AI 시점은 그 상태를 만든 용의자가 숨어 있지 않을 때(`!h.hidden`)만 점선과 고리를 그린다(지금 용의자 그림의 `hst.hidden && !o.truth` 규칙과 같다). `hostageState` 가 상태와 함께 그 용의자 번호를 돌려준다. 자세는 겉모습이라 늘 따른다.
- `hazardState.ts` 가 `hazards.isHeld` 를 가져다 쓴다(상태를 바꾸지 않는 읽기 함수다 — 화면 계층이 불러도 된다). `'window'`·`'guarded'` 의 거리 판정은 `isHeld` 와 같은 `dist`(`../sim/util`)로 한다.

### 7.5 통제된 도로의 원인 (선택)

`trafficLayer.ts` `drawTrafficScreen` 의 진입 금지 원에 원인을 테두리 색으로: 사건이 막은 구간(`I.blockedEdge === e.id`)은 그 사건의 유형색, 재난이 막은 구간(`closedReason === 'disaster'`)은 `#ffb454`. 색표는 파일 안에 복사한다. 범례에 한 줄. T1 의 파일이라 이 한 덩어리만 고친다.

### 7.6 끝난 화재 건물의 그을린 지붕 (선택)

§5.3 과 같은 틀로, 끝난 화재 사건(`placeId ≥ 0`)의 지붕에 그을음 덩어리(넓이 = 지붕의 `clamp(burnedTiles / totalFuelTiles × 1.6, 0.25, 0.9)`, `rgba(14,10,8,0.55)`). AI 시점은 도착했던 사건만. `docs/ROADMAP.md` M2 (1) "사건이 끝난 건물에 흔적"의 화재 몫이다 — 하면 합칠 때 M2 (1)에서 이 부분을 지운다.

## 9. 성능 예산과 고정 층 다시 그리기

**기준**(`README.md` "프레임 속도"): 그래픽 가속 없는 헤드리스 브라우저에서 도시 지도 60FPS, 보통 현장 44~58FPS, 불과 안개가 겹친 큰 현장 33FPS.

**예산**: 같은 주소·같은 틱에서 일시정지한 화면을 5초 둔 뒤의 FPS(상단 `N FPS · 틱 N`)가 고치기 전보다 2 이상 떨어지지 않는다. 큰 현장(가스 폭발: 불 + 연기 + 붕괴 — 스크린샷 B3)은 31FPS 이상. (일시정지 화면의 FPS 로 비교하는 방법이 이 환경에서 쓸 만한지는 확인하지 않았다 — 값이 흔들리면 같은 장면을 세 번 재어 가운데 값을 쓴다.)

**매 프레임 더하는 일**(붕괴 현장 한 프레임에 합쳐 1ms 이하를 목표):

- 현장: 균열마다 원 두세 개, 0~25초 안의 무너짐(보통 0~2개)마다 먼지 10~12개, 가스 경계는 틱마다 만들어 둔 선분을 긋기만, 되살아난 불은 틱마다 한 번 계산, 폭발 자리는 소품 수만큼. **칸 600개를 도는 반복을 매 프레임 새로 더하지 않는다**(가스 판정·되살아난 불은 틱 캐시).
- 지도: 붕괴 사건마다(지진이라도 16건 이하) 덧그림 경로 40번 안팎 또는 기호 하나. `ruinInfo` 는 `staticVersion` 이 바뀔 때만 다시 센다.
- 카드: `hazardChips` 는 캐시된 값만 읽는다.

**고정 층 서명** — `staticSig` 를 이렇게 바꾼다:

```ts
const ruin = s.ruin;
for (let i = 0; i < s.tiles.length; i++) h = Math.imul(h ^ (s.tiles[i] + s.decor[i] * 16 + s.damage[i] * 512 + (ruin ? ruin[i] * 1024 : 0)), 16777619);
for (const p of s.props) if (p.kind === 'debris' && p.removed) h = Math.imul(h ^ (p.id + 77), 16777619);      // 치운 자리(§4.1-8)
// 보강된 균열 항은 뺀다: 지지대는 매 프레임 그려 고정 층과 무관하다. 지금은 보강할 때마다(executor.ts 의 mitigate 보강 갈래의 staticVersion++) 쓸데없이 통째로 다시 그린다
```

**다시 그리는 때**: 처음 볼 때, 2차 붕괴·천장 붕괴(이미 `staticVersion++`), 잔해를 치울 때, 창·가구 파손(N7). 문이 열리거나 균열을 보강할 때는 서명이 같아 다시 그리지 않는다.

**잔해를 치울 때는 새로 다시 그리게 된다.** 잔해를 치우는 곳(`executor.ts` 의 `unblock`, 잔해 치우기 임무의 `p.removed = true` 줄)은 이미 `staticVersion++` 를 하지만, 지금은 서명이 같아 다시 그리지 않는다. 서명에 치운 자리가 들어가면 치울 때마다 고정 층을 통째로 다시 그린다. 붕괴 현장 한 건에 10~20번이다. 아래 재는 법의 둘째 줄로 확인한다.

**다시 그리는 비용**: 가장 크게 확대했을 때(칸당 96화소, 2880×1920) `buildStatic` 이 60ms 이하(N7 이 잰 지금 값 16~40ms). 재는 법: 작업 중에만 `renderScene.ts` `getStatic` 의 `buildStatic` 호출을 `performance.now()` 로 감싸 콘솔에 찍고(경고·정보 수준 — 오류로 찍지 않는다), 확인한 뒤 지운다. 넘으면 `R ≥ 64` 에서 조각 수를 줄인다.

재는 법 2 — **잔해를 치우는 동안의 끊김**: §11 의 A 장면 현장을 가장 크게 확대(칸당 96화소)하고 1배속으로 30초 동안 대원이 잔해를 치우는 것을 본다. 콘솔에 찍힌 `buildStatic` 시간과 상단 FPS 를 적는다. 한 번이 60ms 를 넘거나 치울 때마다 눈에 띄게 끊기면 대체안을 쓴다. 치운 자리(§4.1-8)를 고정 층에서 빼고, 그을음 뒤에서 매 프레임 그린다(치운 잔해 소품 수만큼, 10~20개 — `drawBlastScars` 와 같은 자리). 그때는 서명에서도 치운 자리 항을 뺀다. 어느 쪽을 골랐는지 구현 메모에 적는다.

Q1 의 `scripts/ui-check.cjs` 도 고치지 않는다. 다만 짜임새(개발 서버 띄우기, `window.__ar.snap()` 읽기)는 본떠도 된다.

**먼저 같은 교대인지 맞춘다.** 화면과 헤드리스가 같은 조건이어야 아래 틱이 맞는다.

- 화면의 난이도 기본값은 `{ ...NORMAL, disaster: 'random' }` 이다(`runner.ts:50`). 주소에 `disaster` 가 없으면 재난을 무작위로 뽑는다(S1 은 지진을 뽑는다 — 확인함). 그래서 **재난 없는 장면의 주소에는 모두 `&disaster=none` 을 붙인다**(`parseDisaster` 가 받는다). 그러면 난이도가 `{ ...NORMAL, disaster: 'none' }` 이 되어 헤드리스의 `find.ts` 와 같은 교대가 된다.
- 설정(배속·관찰자 시점 `truthView`·현장 자동 확대 `sceneAuto`·난이도)은 키를 누를 때마다 `localStorage` 에 저장된다(`runner.ts:91`, `App.tsx:142·145`). 같은 브라우저 컨텍스트에서 다음 주소로 넘어가면 설정이 그대로 따라간다. 예를 들어 C 장면의 지진을 뒤의 재난 없는 주소가 물려받고, A2 에서 누른 `t` 때문에 다음 장면이 AI 시점으로 찍힌다. 그래서 **장면마다 `browser.newContext({ viewport: { width: 1600, height: 900 }, deviceScaleFactor })` 를 새로 열고, 찍은 뒤 닫는다.** 한 컨텍스트 안에서 `t`·`z` 를 누른 장면이 있으면 그 뒤로 그 컨텍스트를 다시 쓰지 않는다. 덧붙여 `context.addInitScript(() => { try { localStorage.clear(); } catch {} })` 로 열 때마다 비운다.
- 장면마다 `window.__ar.snap()` 의 `tick`·`hash`·`difficulty` 를 읽는다. `npx tsx scripts/ui-check-ref.ts '{"seed":"S20","difficulty":<snap 의 difficulty>,"force":"collapse/std","ticks":[<tick>]}'` 가 내는 해시와 같은지 본다. 다르면 같은 교대가 아니다(주소와 설정을 다시 본다).

스크립트가 할 일:

- 창 1600×900(`deviceScaleFactor` 1, 확대 장면은 2 로 한 번 더). 콘솔 `error` 와 `pageerror` 를 모두 모은다 — **장면마다 0건**.
- 틱 읽기: `page.evaluate(() => window.__ar.snap().tick)`. Q1 이 둔 개발 서버 전용 읽기 고리다. 상단 `.meta .dim` 의 글자는 160ms 마다만 바뀌므로(`App.tsx:50`) 쓰지 않는다.
- `runTo(T)`: `4`(15배속)를 누르고 40ms 마다 틱을 읽는다. `T − 40` 이상이 되면 `1`(1배속)로 바꾸고 10ms 마다 읽는다. `T` 가 되면 `Space`(일시정지)를 누르고 다시 읽는다. 1배속은 틱당 200ms 라 대개 맞는다. **목표를 지나쳤으면** `ArrowLeft`(10초 = 50틱 되감기, 일시정지는 그대로)를 누르고, `Space` 로 1배속을 다시 시작해 같은 방법으로 다시 노린다. 세 번까지 해 본다. 장면마다 새 컨텍스트이므로 G5 의 자동 감속(`S` 로 끄고 켬, `snap().slowed`)은 켜진 기본값이다. 결정적 순간(`shot`·`boom`·`collapse` …)에 1배속으로 떨어져도 틱을 읽는 방식은 그대로 맞는다 — 15배속을 지나치는 일이 줄 뿐이다.
- **경과 시간 맞추기**: 멈춘 순간의 보간값(`runner.alpha`)이 남아 그림의 경과 시간이 0~0.2초 흔들린다(`age = sim.t + alpha·dt − f.t`). 목표 틱에서 멈춘 뒤 `ArrowLeft` → `ArrowRight` 를 누르면 같은 틱으로 돌아오면서 보간값이 0 이 된다(`runner.seek` 가 `alpha = 0`). 그 뒤 `snap().tick === T` 를 한 번 더 확인하고 300ms 기다려 찍는다. 되감기는 관찰 대상 고정을 그대로 둔다. 다만 되감은 틱에 그 사건이 아직 없거나 미신고면 고정이 풀린다(`camera.ts:44`). 이 표의 장면에는 해당하지 않는다. 0~0.5초에 몰린 연출(그림자·덩어리·충격 고리의 앞부분)은 한 틱 차이로 놓친다. 그래서 A4·A5·A9·B2 는 이 단계를 빼지 않는다.
- 현장 보기: `page.locator('.card.incident', { hasText: <글자> }).filter({ hasText: '현장 대응' }).first().click()`. 현장의 자동 확대를 끄려면 `z` 를 누르고 캔버스를 두 번 눌러(`dblclick`) 전체 보기로 둔다. 확대는 캔버스 위 `page.mouse.wheel(0, −120)`.
- 사건 카드를 코드로 찾기: `page.locator('.card.incident').filter({ has: page.locator('.code', { hasText: /^15$/ }) })`(코드 칩의 글자는 `I.code`).
- 지도에서 한 사건 보기: 아직 현장 대응이 아닐 때 그 카드를 누르면 지도 모드로 그 사건에 고정된다. 그다음 캔버스(`page.locator('canvas').first()`) 가운데에서 휠을 돌린다. 고정은 사건이 끝난 뒤에도 남으므로, 그대로 시간을 보내 끝난 뒤를 찍는다. 지도 전체는 `c`, AI 시점은 `t`.

**시각 다시 찾기** — `<scratchpad>/find.ts`:

```ts
// npx tsx find.ts collapse/std S20,S6 300 '2차 붕괴|천장 일부|현장 도착'
import { Sim } from '<작업 폴더>/src/sim/engine';
import { NORMAL } from '<작업 폴더>/src/sim/difficulty';
const [force, seeds, until, pat] = process.argv.slice(2);
for (const seed of seeds.split(',')) {
  const sim = new Sim(seed, { ...NORMAL, disaster: 'none' }, 1200, { force });      // 화면의 &disaster=none 과 같은 조건
  while (sim.t < +until && !sim.ended) sim.step();
  const I = sim.incidents.find((q) => Math.abs(q.createdAt - 15) < 0.5 && q.truth.type === force.split('/')[0]);      // 강제 사건은 15초에 생긴다
  if (!I) { console.log(seed, '없음'); continue; }
  const ev = sim.events.filter((e) => e.incidentId === I.id && new RegExp(pat).test(e.text));
  console.log(seed, sim.weather, `I${I.id} ${I.truth.variant} 심각도${I.truth.severity} ${I.truth.placeKind} 첫도착${I.firstArrivalAt.toFixed(1)}`, ev.map((e) => `틱${Math.round(e.t / 0.2)}:${e.text.slice(0, 20)}`).join(' | '));
}
```

기록의 `e.t` 는 그 틱의 `sim.t` 다(`engine.ts` 의 `step` 이 처음에 `tick++`, `t = tick·dt`). 그래서 틱 N 에 난 무너짐은 화면이 틱 N 일 때 경과 0초, N+1 일 때 0.2초다. 날씨는 `sim.weather`(`'night'` 이면 밤)로 본다. 2차 붕괴는 드물다(035a83f 에서 맑은 시드 S17~S40 가운데 300초 안에 난 것은 S20·S21·S24 셋).

지진은 `new Sim('S3', { ...NORMAL, disaster: 'quake' }, 1200)` 을 돌려 `sim.events` 에서 `/지진 발생|여진|2차 붕괴/` 를 찾는다(사건 코드는 `sim.incidents[e.incidentId].code`, 첫 도착은 `firstArrivalAt`). `npx tsx scripts/sweep.ts 1 --disaster quake --log S3` 로도 볼 수 있다(기록의 시계 − 교대 시작 시계 = 초, 틱 = 초 × 5). 위의 주소 규칙(`&disaster=none` 또는 `&disaster=quake`)과 새 컨텍스트를 지키면 기록과 화면의 시각이 같다. `snap().hash` 와 `ui-check-ref.ts` 의 해시로 확인한다.

보고에 "고치기 전 → 고친 뒤" 그림 경로를 짝지어 적는다.

## 15. 알려진 위험

1. **결과가 바뀐다** — 기록용 쓰기 자리에서 실수로 난수 호출의 순서나 조건을 바꾸는 것(특히 `tickFire` 의 `s.rng.range(9, 14)` 를 괄호 안팎으로 옮기는 것). 켜고 끄기 테스트와 기준값 비교가 잡는다. 바뀌면 그 커밋을 되돌리고 다시 쓴다(값을 맞추려고 다른 곳을 고치지 않는다).
2. **효과 종류를 바꿨다** — 2차 붕괴가 `'boom'` 대신 `'collapse'` 를 남기므로 폭발 그림·밤의 빛 구멍(어둠 블록의 효과 반복문)·`boom` 소리가 더는 나지 않는다(의도). 밤에는 그 대신 무너진 자리의 어둠을 옅게 걷는 한 줄(§4.3)이 먼지 기둥을 보이게 한다. 카메라·자동 감속·소리는 `'collapse'` 를 넣지 않으면 2차 붕괴를 놓친다 — 세 곳을 함께 고친다.
3. **효과 목록의 60개 상한** — 물줄기가 많은 현장에서 'collapse' 효과가 밀려 카메라·소리가 놓칠 수 있다. 그림은 `falls` 로 그리므로 놓치지 않는다.
4. **화면이 어지러워진다** — 붕괴 경계·위험 범위·가스 경계·글자 표지가 겹친다. AI 시점은 수치를 빼서 가볍게, 작은 창은 세부를 빼고, 스크린샷으로 판단해 투명도를 내린다. 흔들림은 0.6초·0.16칸 이하, 동작 줄이기 설정이면 없다.
5. **지도의 구멍 자리는 근사다** — 현장 평면은 지도의 건물 외곽과 무관하게 만든다(`README.md` 알려진 문제). 상대 위치(`u, v`)로 옮길 뿐이고, 넓이는 두 배쯤 과장한다. 나중에 M2 (2)(지도 외곽과 현장 평면 맞추기)를 하면 다시 본다.
6. **가스 판정은 근사다** — 가스와 불 연기가 같은 배열이라 섞인 칸을 나눌 수 없다. 칠하는 범위는 "밸브가 설명하는 몫"으로 어림하고, 폭발 위험 표지만 시뮬레이션의 판정 식 그대로다(그 식이 불 연기도 세는 것은 규칙의 성질이다 — 이 묶음은 고치지 않는다).
7. **장면의 시각이 바뀐다** — §11 의 시드·틱은 035a83f 에서 잰 것이다(1ca465d 에서 잰 것을 B3 이 합쳐진 뒤 다시 쟀다 — S6 의 첫 도착이 7초 당겨졌다). 시뮬레이션을 바꾸는 묶음(B1·H1·R1·X6·R2 등)이 먼저 합쳐지면 또 달라진다 — `find.ts` 로 다시 찾고, `snap().hash` 와 `ui-check-ref.ts` 로 같은 교대인지 확인한다.
8. **가짜 캔버스는 예외만 잡는다** — 그림이 맞는지는 스크린샷으로만 안다.
9. **AI 시점의 새는 정보** — 도착 뒤 무너진 정도(`frac`)는 진실에서 센다(겉모습은 모두가 본다고 친다). 그 밖의 수치가 AI 시점에 새지 않는지 §12-5 가 본다.
10. **기호가 헷갈린다** — 경로는 초안이다. 견본표로 고친다.
11. **화면 자동 테스트(Q1)와 겹침** — Q1 은 합쳐졌다(035a83f). 가짜 캔버스는 두지 않았고, 개발 서버 전용 읽기 고리 `window.__ar.snap()` 과 헤드리스 기준값 `scripts/ui-check-ref.ts` 를 두었다. §11 이 이 둘을 쓴다. `scripts/ui-check.cjs` 는 고치지 않는다. G5 가 가짜 캔버스를 `tests/combatfx.test.ts` 에 먼저 두었다 — 그것을 `tests/fakeCanvas.ts` 로 옮겨 쓴다(§12-4, 같은 것을 둘 만들지 않는다).
12. **바깥 벽은 무너지지 않는다** — 시뮬레이션의 무너진 구역은 층의 벽 안쪽에만 잡힌다(`builders.ts:650-652`). 현장에서는 건물 외곽선이 늘 서 있고, 이 묶음은 맞닿은 바깥 벽에 금과 가루만 그린다(§4.1 `paintRuinWalls` 3 — 과장). 지도의 `'major'` 외곽 틈(§5.3-6)도 과장이다. 건물이 통째로 무너지는 모습은 그것을 시뮬레이션에 더하는 묶음(X6)이 `markRuin`·`recordFall` 을 부르면 얻는다(§16).
13. **정보 표지가 사람 위를 지난다** — 밤에도 보이게 위험 범위·충격 고리·가스 경계를 어둠·날씨 뒤에 그리므로(§2.8) 사람·나무 수관·연기 위층 위를 지나간다. 가늘고 반투명한 선으로 두고, 어지러우면 투명도를 내린다.

## 검토 메모

독립 검토의 지적(꼭 고칠 것 9, 더할 것 11)은 모두 본문에 반영했다. 반영하는 동안 B3·P1·Q1 이 합쳐져(035a83f) 장면 시각과 시뮬레이션 쪽 줄 번호를 다시 쟀다(§1 머리, §11). 아래는 고른 방식이 검토의 제안과 다른 곳과 그 까닭이다.

- **인질 상태의 판정 순서**(§7.4): 검토는 `c.walking` 이면 `'freed'` 를 먼저 두었다. 035a83f 의 S3 `armed/hostage` 틱 700 에서 끌려가는 인질이 `walking === true` 이면서 `isHeld` 가 참이었다. 그래서 `isHeld`·구출 기회를 먼저 보고, `walking` 은 그다음에 본다. `'guarded'` 의 "가깝다"는 5칸으로 정했다.
- **AI 시점의 되살아난 불**(§7.2): 검토는 그림 쪽 캐시에 방마다 '되살아남' 믿음의 시각을 기억하자고 했다. 실제로 재 보니 그 믿음은 0.8초 만에 덮인다(틱 945 → 949). 15배속에서는 실제 시간 50ms 남짓이라, 프레임이나 카드 갱신(160ms) 때 보는 캐시는 놓친다. 그래서 같은 뜻을 뒤에 붙기만 하는 무전 기록(`sim.events`)에서 읽는다.
- **흔들림의 합**(§4.3, §16): 검토는 hazardFx 한 함수에서 두 묶음의 이동량을 더하자고 했다. 그대로 따랐다. 단위와 상한은 검토 중에 고쳐진 G5 설계서(§3.4: 칸 단위, 각자 자기 상한, 합은 자르지 않음)에 맞췄다.
- **A 장면의 시드**: 맑은 시드에서 300초 안에 2차 붕괴가 나는 경우가 드물다(S17~S40 가운데 S20·S21·S24). S21 은 2층 공사장이라 한 층만 보이므로 S20(창고)을 골랐다. S6 은 밤 장면 A8·A9 로 남겼다.
- **C3**: 검토가 고른 사건(코드 15)과 틱 3400 을 그대로 썼다. 다만 카드는 현장 대응 전(첫 도착 710.2초 전)에 눌러야 지도에 고정되므로 3100 에 누른다.
- **폭발 자리**(§7.3): 검토가 낸 두 방법 가운데 바닥 흔적 쪽을 골랐다. 소품 아래에 깔리고 G5 의 그을음과 같은 높이라 맞추기 쉽다. 그래서 `skins/crime.ts` 는 고칠 파일에서 뺐다.
- **AI 시점의 칩**(§6): 인질은 "붙잡힘만"(수 없이)을 골랐다. 폭발물의 `active: false` 는 진실의 `exploded` 로 가른다. 터진 자리는 겉모습이고 폭발음은 현장 어디서나 들린다(§2.3).
- **바깥 벽**(§4.1, §15-12): 금과 가루까지만 허용하고 과장 목록(§2.2)에 넣었다.
- **`sealPockets` 테스트**(§12-6): 메워진 칸을 빼고 세는 대신 메워진 칸의 모양(4이웃이 모두 걸을 수 없음)을 확인하고, `T.FLOOR` 가 90% 이상인지 본다. 메워질 수 있다는 사실 자체를 테스트가 지킨다.
